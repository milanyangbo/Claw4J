# Claw4J Defense Rules

## 总原则

Claw4J 的每个功能都必须配套工程防御设计。任何会调用模型、访问工具、读取知识库、跨服务通信或处理用户输入的能力，都必须明确它的预算、校验、隔离、降级、观测和回滚方式。

## 输入校验

- 所有外部输入必须校验，包括用户问题、HTTP header、请求体、RAG 检索结果、工具返回、模型输出和配置中心内容。
- Controller 只负责接收参数和返回结果，业务校验、上下文校验和防御逻辑必须放在 Service 或明确的边界组件中。
- 缺失 `requestId`、`tenantId`、`userId` 或 `idempotencyKey` 的受保护调用必须 fail closed。
- 不允许将无效上下文包装成成功降级结果，降级不能掩盖非法请求。

## 预算治理

- 所有模型调用必须配置步数、Token、超时和成本预算。
- 所有工具调用、RAG 检索和跨服务调用必须受剩余 deadline 或超时预算约束。
- 服务间调用必须配置 connect timeout、read timeout 和显式重试策略。
- 默认禁止非幂等重试；只有经过文档说明和测试证明的幂等调用才允许重试。
- 当预算耗尽时，系统必须返回稳定的业务错误或降级响应，不允许无限等待。

## 限流熔断降级

- 入口流量、租户配额、Agent 调用、工具执行和高成本模型调用都必须能纳入限流策略。
- 熔断必须基于可解释的指标，例如错误率、异常数、慢调用比例、超时或预算耗尽。
- 降级路径必须返回稳定的 Claw4J 错误码或受控响应结构，不暴露底层框架、供应商或传输细节。
- 限流、熔断和降级规则必须支持配置化，禁止把阈值硬编码在业务逻辑中。
- 动态规则更新必须有 smoke test 或自动化测试证明变更无需重启即可生效。

## 幂等与副作用

- 所有工具调用必须包含幂等键。
- 所有写操作、外部系统调用和可能产生副作用的 Agent 动作都必须有幂等防重方案。
- 幂等键必须纳入租户和用户边界，不能跨租户复用。
- 工具执行结果必须记录可追踪状态，避免超时后重复执行导致副作用放大。

## 工具执行防御

- 工具调用必须先做 Pre-filter，包括权限、租户、参数 schema、预算和工具 allowlist 校验。
- 禁止依赖 Post-filter 作为主要安全边界。
- 工具参数不能直接信任模型输出，必须按结构化 schema 校验后再执行。
- 高风险工具必须有沙箱、超时、资源限制和审计记录。
- 工具返回必须被视为不可信输入，进入模型上下文前必须做长度、格式和敏感信息处理。

## 上下文与流式治理

- 用户输入进入系统 prompt 前必须包裹为纯数据，禁止直接拼接成系统指令。
- RAG 内容、工具返回和历史消息进入模型上下文前必须经过 token 预算评估。
- 当上下文超过目标模型窗口时，必须按配置执行 summary、truncate 或 reject 策略。
- SSE 流式输出必须有事件序号、会话标识和有限缓存，避免断线恢复造成重复输出或内存膨胀。
- 模型流中断和客户端连接中断必须分开处理：模型流中断走服务端接力，客户端连接中断走重连恢复。

## 可观测性

- 跨服务调用必须透传 `X-Request-Id`、`X-Tenant-Id`、`X-User-Id` 和 `X-Idempotency-Key`。
- 日志必须包含可定位问题的上下文，但不得记录密钥、Token、完整用户敏感内容或模型内部思考。
- 限流、熔断、降级、预算耗尽、上下文裁剪和输出解析失败都必须有可观测指标或日志。
- smoke test 文档必须说明如何验证核心防御机制已生效。

## 配置与回滚

- 阈值、开关、模型路由、超时、重试和降级策略必须通过配置文件或配置中心管理。
- 本地默认值必须安全、保守、可启动。
- 动态配置错误不得导致核心服务不可启动；应保留可解释的 fallback 值或拒绝无效配置。
- 每个动态规则 smoke test 都必须提供回滚和清理步骤。

## 验收要求

- 新能力必须有 OpenSpec proposal、spec、design 和 tasks。
- 每个 task 完成后必须运行对应模块的编译和相关测试。
- 涉及运行时治理的能力必须提供 curl、smoke test 或可重复的本地验证流程。
- 不允许只用静态编译结果证明限流、熔断、降级、负载均衡或流式恢复等运行时行为。
