# Claw4J Security Rules

## 总原则

Claw4J 的安全边界必须围绕多租户、模型上下文、工具执行和跨服务通信设计。模型输出、工具返回、检索结果、配置中心内容和用户输入都必须视为不可信数据。

## 租户隔离

- 所有涉及用户数据、会话、记忆、工具结果、缓存、向量检索和审计记录的访问都必须带 `tenantId` 和 `userId`。
- Redis Key 必须包含 `tenantId:userId` 前缀，禁止使用跨租户共享 key 保存用户状态。
- RAG 检索必须使用 Pre-filter 限定租户、用户、知识库和权限范围。
- 禁止在工具执行、RAG 检索或模型路由中通过后置过滤补救跨租户访问。
- 日志、指标和错误响应不得泄露其他租户的标识、数据内容或配置细节。

## 身份与调用上下文

- 受保护入口必须校验请求 ID、租户 ID、用户 ID 和幂等键。
- 跨服务调用必须透传经过校验的上下文，不允许下游自行猜测租户或用户身份。
- 内部接口不得因为位于内网或服务间调用就跳过上下文校验。
- 下游服务发现、配置和规则读取必须限定 namespace、group 和环境，禁止跨环境读取。

## Prompt 注入防御

- 用户输入不得直接拼接进 System Prompt，必须放入明确的数据标签，例如 `<user_query>`。
- 工具返回、网页内容、RAG 文档和历史消息进入 prompt 前必须标记来源，并按不可信内容处理。
- 模型不得把检索内容或工具返回中的指令当作系统指令执行。
- 接力生成 prompt 必须区分原始问题、已发送内容、系统约束和恢复指令，避免用户内容覆盖恢复规则。
- 禁止把密钥、内部配置、系统 prompt、工具 allowlist 或安全规则注入到模型可见的用户上下文中。

## 模型输出安全

- 模型输出必须经过统一解析和清洗后再返回给用户或下游系统。
- 深度思考模型的内部思考、reasoning trace、供应商私有标记和调试信息不得直接暴露给外部调用方。
- 输出 parser 不能信任模型声称的 JSON 格式，必须做结构化解析、错误处理和 fallback。
- 当输出格式不满足业务契约时，系统必须返回稳定错误或降级响应，禁止返回半结构化脏数据。

## 工具安全

- 工具必须有明确 allowlist、参数 schema、权限边界和幂等策略。
- 工具调用参数必须来自结构化校验结果，不能直接执行模型原始文本。
- 高风险工具必须配置超时、资源限制和审计日志。
- 工具错误必须转换为稳定业务结果或异常，禁止泄露堆栈、命令、路径、密钥或外部系统敏感响应。
- 工具执行中禁止绕过预算、租户、权限、限流和熔断机制。

## 数据与密钥

- 密钥、Token、访问凭证、私有地址和账号信息不得硬编码在代码、测试或文档示例中。
- 文档中的本地示例必须使用环境变量、占位符或临时随机值。
- 日志不得记录认证头、API Key、模型供应商密钥或用户敏感数据全文。
- 配置中心内容必须按环境隔离，本地 smoke 配置必须可清理、可回滚。

## 流式接口安全

- SSE 事件必须绑定会话和请求上下文，防止跨用户恢复或串流。
- 服务端缓存的流式片段必须有大小上限、TTL 和租户隔离。
- 客户端重连时必须校验 session ownership，再根据事件序号恢复。
- 断点续写不得重复输出已发送内容，也不得把已发送内容当作新的用户指令。
- 中断恢复失败时必须明确结束事件或返回稳定错误，禁止让客户端无限等待。

## 审计与追踪

- 鉴权失败、租户校验失败、Prompt 注入拦截、工具拒绝、预算耗尽、熔断降级和输出解析失败都应可追踪。
- 审计记录应包含请求 ID、租户 ID、用户 ID、能力名称、结果类型和失败原因类别。
- 审计记录不得包含完整敏感内容、内部思考链或密钥。
