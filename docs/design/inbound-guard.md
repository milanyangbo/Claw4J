# 入站拦截：这条消息要不要送去模型

> 设计说明：为什么这么做、否决了什么。要看结论去 [README](../../README.md)，要看决策去 [ADR](../adr/)。
> 术语按 [`GLOSSARY.md`](../../GLOSSARY.md) 的「入站拦截」，下文简称「守卫」。

有些消息在到达模型之前就该被挡下——不是因为它问到了没权限的数据（那是鉴权的事），
而是因为它想干的事不属于这个助手：套取系统提示词、覆盖既有指令、诱导越权。
这类消息的共同点是**无论模型怎么答都没有正确答案**，于是最省的处置是根本不问：

```
请求 ──► 守卫(查词表) ──► 记忆 ──► 脱敏 ──► 缓存 ──► 工具循环 ──► 模型
            │
            └─ 命中：直接返回一句固定答复，后面一步都不走
```

命中时有三件事同时发生：模型一次没被调用、token 一个没花、**这一轮不写进会话历史**
（记忆在它里层，看不到它）。第三点比省钱重要——被拦下的那句话不该留在上下文里，
否则下一轮模型会带着它继续推理。

答复里不回显命中了哪个词：说出来等于把词表交给想绕过的人，他换个同义词就过去了。
也不写"我怀疑你在攻击"——大多数命中只是问法碰巧撞上，一句话把人定性成攻击者，
比拒答本身更糟。只说"换个说法"。

## 词表为什么是自己写的

Spring AI 给的只有机制（`SafeGuardAdvisor`：命中即整轮拒答），**没有词表**。
官方对它的定位原话是 "can be used as a starting point"。

公开的中文敏感词库是给**内容审核**用的，判据是"这句话能不能出现在平台上"，动辄几万条。
这里的判据窄得多："要不要连模型都不调"。差别不在词的数量，在**错了的代价**：
审核误判是少显示一条内容，这里误判是一个人的问题被整轮拒掉。所以没有抄现成的库，
只写了本仓库真会遇到的两类（套取系统提示词、诱导越权与覆盖指令），
放在 `claw4j.guard.sensitive-words` 里，按业务改。

**词表为空时整个 Advisor 不装配。** 空表时框架的判定恒为 false，行为上确实等价，
但链上会多一个永远不生效的 Advisor，从容器里看和"生效中"一模一样。
装不出来，是最明确的"没生效"。

## order 必须在会话记忆外面

`SafeGuardAdvisor` 检查的是 `prompt().getContents()` 的**全部内容**，不是"这一条用户消息"。
而记忆的 `before` 会把历史拼进 prompt。排在记忆里层的话，只要历史里有一轮出现过某个词，
之后每一轮都会被同一个词拦下——会话就此锁死，而用户看到的只是
"从某句话开始，怎么问都不理我了"。

所以守卫的 order 是 `HIGHEST_PRECEDENCE`，记忆让出这一个名额挪到 `+1`。
记忆的语义没变：它仍然比脱敏小，`after` 仍然最后收尾，写进库里的仍是打过码的文本。

代价是"历史里已经存在的词不再被拦"。这是有意的：历史只可能装着**当时被放行**的内容。
要管住历史该在写入时管，不是在读出来时管。

## 它挡不住什么

匹配是子串 + 大小写不敏感，**不理解改写**：换同义词、全角字符、词间插空格都能绕过。
官方文档自己也写明不处理 homoglyph / 全角 / 零宽字符。

所以它挡的是**随口一问**，不是有备而来的攻击。后者靠两层兜住：模型能碰到哪些表由鉴权决定
（[ADR-0007](../adr/0007-principal-and-tool-level-authorization.md)），说出去的内容由出站脱敏管。
守卫只是把最便宜的那一类挡在门外，不是安全边界本身——把它当边界，
就会在它被绕过的那天以为自己一直是安全的。

## 和出站脱敏不是一件事

| | 入站拦截 | 出站脱敏 |
| --- | --- | --- |
| 判据 | 关键词子串 | 手机号、证件号的格式 |
| 命中后 | 整轮拒答 | 打码后**照常回答** |
| 位置 | 入站，链最外层 | 出站，在记忆里层 |

两者不能互相替代，理由很具体："这单的收货手机号是多少"是**必须答得出来**的业务问题。
把手机号写进守卫的词表，等于把这个能力删掉；反过来，词表里不写手机号格式，
守卫也完全挡不住号码外泄——它不懂格式，连全角的号码都认不出。

一句话：守卫管"要不要回答这个问题"，脱敏管"答出来的东西能不能原样给人看"。

## 配置错了会怎样

- **词表没绑上**（缩进写错、键名改了）：整个 Advisor 不装配，消息直通模型。
  整机装配那条用例直接注入配置对象，绑不上就起不来——比"日志里少一行"更容易发现。
- **词表写得太宽**（例如把"忽略之前"整句之外的片段也收进来）：正常问话被拒。
  这类反馈很快会有人抱怨，比静默漏过好查。

## 顺带一个日志 Advisor

同一条链上还挂了 `SimpleLoggerAdvisor`，默认**什么都不打**：框架实现里每个方法体
都包在 `logger.isDebugEnabled()` 里，INFO 级别下连字符串拼接都不发生。

它的 order 用框架默认的 0，也就是排在工具循环**内部**、紧贴模型调用——这是官方参考文档里
示例实现的取值，好处是能看到每一轮真正发给模型的东西（含工具返回的行）。

**打开它之前先想清楚 PII**：它 dump 的是模型入口与出口的原文，而脱敏在它外层，
所以日志里是未脱敏的手机号与原始数据行。因此
`logging.level.org.springframework.ai.chat.client.advisor` 只能在本机或测试环境调到 DEBUG。

子 Agent 的链上没有它，也不该加：子链的输入是父模型生成的委派任务而不是用户原话，
而子链**不挂脱敏**（结论回父链再脱敏），把日志挂上去等于专门开一条通往明文的路。
