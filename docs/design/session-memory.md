# 会话记忆：记得住上一轮，但换了对话就重来

> 设计说明：为什么这么做、否决了什么。要看结论去 [README](../../README.md)，要看决策去 [ADR](../adr/)。

第一轮问"上周华东区成交额多少"，第二轮问"那华南呢"——第二轮不该要求把"上周""成交额"重讲一遍。
记忆挂在链的最外层（`SessionMemoryAdvisor`，order 全链最小），用
**`org.springaicommunity:spring-ai-starter-session-jdbc`**（groupId 不是 `org.springframework.ai`，
它是 spring-ai-community 的独立项目，ADR-0005 里记了这个坑）落在 Postgres，
会话表在 `claw4j_session` schema，业务表在 `business`，同库不同 schema。

**这条链上没有 Redis。** ADR-0005 否决过"Redis 兼做会话存储"：会话要事务、要按会话查事件，
这两件事 Redis 都做不好。仓库里那点占位（依赖、`spring.data.redis`、compose 的容器）
已于 2026-10-26 一并摘掉。语义缓存（M3-05）也**没有把它引回来**——那是同一份 ADR 的第二次修订，
缓存落在库里的 `claw4j_cache` schema，理由是"要和授权、会话在同一套数据里做一致性判断"。

三点值得留意：

1. **会话是"一段对话"，不是"一个人"**。会话 id 是
   `claw4j:user:<userId>@<权限指纹>:<通道>:<chatId>:<段>`，五段各管一件事：
   **权限指纹**保证"降权之后什么都想不起来"，**通道 + chatId** 保证"私聊里说的不进群聊"，
   **段**保证"这段对话有开始也有结束"（ADR-0026）。

   **段是第五段，也是唯一会变的一段**。前四段都是"这段对话的坐标"，不随时间变；
   段是"第几世"，跨了逻辑日（默认 4 点起算，按 `claw4j.agent.zone`）或空闲超过
   `claw4j.session.reset.idle-minutes`（默认 120）就换一个。**换段 = 换对话**：
   记忆、预算、召回都从零开始，旧段留在库里只读。

   没有段的话，"这段对话什么时候结束"就有四个答案：记忆认为永不结束、预算按 120 分钟自己判、
   存储按 30 天删行、定时任务借用创建者那一份。四个都说得通，合起来就是"会话"没有定义。
   更直接的一条：web 端的 `chatId` 缺省就等于 `userId`，于是用户**没有"开一段新对话"的手段**——
   它不会因空闲结束、不会因跨天结束，只会在第 30 天被后台任务删掉（删行，不是换对话）。
   段把这件事收成一个答案。

   **同一段对话同时只有一个 run**（ADR-0026 决定二）。会话记忆在 `before` 读、在 `after` 写，
   两条消息并发时，第二条拼提示词的那一刻第一条的答案还没落库——上下文里有问题、没有答案。
   这个失败长得像"模型偶尔会忘事"，不会有人想到根因是并发。所以入站消息按**对话地址**
   （`addr:<owner>|<通道>|<chatId>`——不是 `sessionId`，段会轮换，拿它当锁键跨过切换点
   就是两把不同的锁）拿一把 lane，最多等 `claw4j.agent.lane-wait`（默认 60 秒），
   等不到就回一句"现在有点忙"。**排队而不是拒绝**：用户只是打字快。

   **定时任务跑在自己的会话里**（ADR-0026 决定三）。它的会话标识是
   `cron:<taskId>:<触发时刻>`——带时刻，所以每次运行天然是一个新段，不走指针
   （指针只服务"人"这条路，那里才有"上次说到哪儿"）。`InboundMessage` 因此多了一个
   `conversationId`：`chatId` 回答"结果送到哪儿"（审批卡片、审批之后的新一轮、推送全走它），
   `conversationId` 回答"这是哪一段话"。一个字段担两件事时，改哪件都会把另一件弄坏——
   把 `chatId` 换成 `cron:<taskId>`，审批卡片就会推进一个不存在的会话，而这一轮看起来正常。

   只按人分段的话，会话键只到 `claw4j:user:<userId>@<权限指纹>`，粒度是人。同一个人在网页上
   （只有他自己）问"华东上周成交额"，答 128,400；十分钟后他在项目群里 @ 机器人问"合同 A 违约金怎么算"，
   这一轮的上下文里还留着那个数字。群里二十个人，其中三个没有华东数据的权限。
   权限指纹挡不住这一层——它保证"权限一样才共享"，而这里**听众不一样**。
   按对话分段是照 OpenClaw 的 session key（`agent:<agentId>:<channel>:<peer>`，
   `dmScope: per-channel-peer`）做的：它把"Alice 的上下文被拿去回答 Bob"叫 conversation bleed，
   还专门有一条 `openclaw security audit` 去查。

   掺权限是另一件事：一个人被降权之后，历史里还躺着他降权前查到的数字，
   下一句问同一件事，模型直接从上下文里念出来——**不查库、不鉴权、没有一处报错**，
   因为记忆读取本来就发生在工具调用之前。ADR-0007 画的边界在"会话"这一层被绕过去了。
   把权限放进会话键之后，权限一变就是另一段会话：他会"什么都想不起来"，而不是"还记得不该记的"。

   代价要记账：换通道（网页 → 飞书私聊）要重讲一遍、权限一调整历史就断、老格式的会话 id 再读不到。
   头两条是刻意选的：OpenClaw 的跨通道共享也要显式配 `identityLinks`，默认不共享；
   Claw4J 现在没有这个配置项。丢的只是记忆，不是数据。
2. **会话有自己的连接池，URL 上带 `currentSchema`**。`spring-ai-session` 的 SQL 里表名不带前缀，
   表落到哪由连接的 `search_path` 决定；而它的自动配置拿的是主 `DataSource`，表会落到 public。
   所以这里自己声明了 `SessionRepository`（官方那份带 `@ConditionalOnMissingBean`，会退让），
   指向会话 schema。会话池**不注册成 bean**——容器里有两个 `DataSource` 时，
   那些 `@ConditionalOnSingleCandidate(DataSource.class)` 的自动配置会整套安静地不装配。
3. **记忆的收尾排在脱敏之后**。链的收尾按 order 降序，order 越小越晚收尾，
   于是写进会话表的是**掩码后**的文本。反过来写，出站是干净的、会话表里躺的是明文——
   一份比出站更持久的泄露，而且没人会去看。

**TTL 是 30 天，它不是"答案的保鲜期"。** 记忆按时间淘汰，不按"这条数字还对不对"淘汰。
2026-10-27 用同一份数据连问 7 次，只有 1 次真查了库：其余几次模型把四天前的 128,400——那是"上周华东"的正确答案，今天也还是正确——又念了一遍，
而那次问的是"本周"，真值是 99,999：种子按相对日期生成，每个窗口的答案任何时候都成立，
错的不是数字，是记忆把上一个窗口的答案张冠李戴到了这一个上。不是缓存的毛病——缓存 TTL 只有 1 小时，
关掉它模型照样会从上下文里念。修法的边界也说清楚：**不靠提示词要求"带数字必须本轮查库"**，
因为"带数字"在真实对话里界定不了（序号、历史对比、文档里的百分比都算），
而且它挡不住"查了库但读错窗口"。这条按已知问题记账（`docs/agents/guardrails.md`），
排查时看 `claw4j.tool.calls{tool=querySales}`，别看回答。

**记不住不等于答不了。** 会话库挂了的时候，记忆降级成"这一轮没有历史"并打一条 WARN，
而不是让整条链 500：鉴权是安全边界，它不能因为"记不住"就连"没权限"这句话也说不出来
（要有测试钉着）。三个 Advisor 的失败姿势不一样——
鉴权失败只能拒绝、脱敏失败只能拒绝、记忆失败只能降级。

**被压掉的细节还能找回来。** 压缩是留结论、丢细节：摘要里写着
"用户问过华东区成交口径"，而"按签约主体还是按开票主体"这种具体约定往往没进摘要。
这时靠 `recall_session` 工具按关键词回查事件，**包括已归档的那些**——
`EventFilter` 的 `excludeArchived` 默认 false，压掉的事件照样查得到。

**它能查多大范围是配置项，默认 `all`。** `claw4j.tools.sessions.visibility` 照 OpenClaw 的
`tools.sessions.visibility`，四档：`self` 只有当前这一段；`tree` 再加它派生的子 Agent 会话
（子 Agent 会话今天不落会话库，所以暂等同 `self`）；`agent` 是本 agent 的全部会话
（我们只有一个 agent 命名空间，所以暂等同 `all`）；`all` 是全部会话。
默认 `all` 也是照抄——它的原文是 "Default: `all` (every session on the Gateway, including
other agents' and other users' transcripts)"。默认值不因为"我们觉得安全一点"就收窄：
默认一变，部署从"配错才出事"变成"配了才可用"。**多用户、角色不同的部署必须配 `self`**。

为什么不再用框架的 `CrossSessionRecallTools`：它按 `SessionService#findEventsByUserId`
（`WHERE user_id = ?`）查，而我们的 `user_id` 是 `userId@权限指纹`——跨用户时它一条都查不到，
`all` 会静默退化成"什么也没有"，而那与"历史里没说过"在结果与日志上完全一样。
所以跨会话那两档走自己的一条 SQL（`CrossSessionEvents`），`self` / `tree` 仍然走
`getEvents(sessionId, filter)`：范围由查询条件钉死，不做事后过滤
（事后过滤会在"没命中"与"命中但被滤掉"之间撒谎）。

五点值得留意：

1. **会话 id 由宿主写进工具上下文，模型没有参数可改。** 键是 `ChatMemory.CONVERSATION_ID`，
   由 `ChatClientAgentPort` 塞进 `toolContext`。模型手上没有"换一段会话查"的入参——
   范围是部署配的，不是模型挑的。
   工具也不许自己按 principal 推会话 id——推出来只能是一个人，而"哪一段对话"这件事
   一个人身上装不下。
2. **身份分两种核法。** `self` / `tree` 核归属前缀（`claw4j:user:<owner>:`），
   防的是宿主把 id 传错、以及将来有人把别人的会话 id 递进来；
   `agent` / `all` **不核**——那两档本来就允许跨用户，再核前缀等于把范围又收回 `self`，
   症状只是"配了 all 却查不到别人的"。身份为空时两条路都拒绝，动作照样要过授权表。
3. **结果两头封顶。** 条数 5 条、整段 2000 字。条数上限挡不住"一条就一万字"（事件存的是整条
   消息正文），字符上限挡不住"十条各两千字"——两个都要。召回是**额外**塞进提示词的上下文，
   省下来的 token 不能从这儿还回去。
4. **关键词匹配，不是语义召回。** 换个说法问同一件事它找不到（"上次那批单子"里没有"华东"，
   就查不到讲华东的那段）。语义召回要 embedding 加一张向量表，那是另一件事。
5. **动作名是 `recall_session`，不复用 `read`。** `read` 的语义是"读业务表"，拿它兜住
   "读自己的历史"会让"能不能回忆"和"能不能查销售单"变成同一件事。给 `read-only` 与 `admin`，
   不给 `guest`——他能读的那张 `region` 表与他"过去说过什么"没有关系。

**代价要记账，而且是两条。** 一条是范围的：默认 `all` 意味着一个 `read-only` 身份能召回
另一个用户的会话内容，这是它的默认值，不是 bug——安全位在配置项上；把 `visibility` 配成
`self` 之后，换到另一条通道或另一个 chat 就召不回来（"我们在飞书里说过的那个口径"）。
另一条是出处的：跨会话时每条结果都带 `sessionId`，不带的话模型会把两段对话揉成一段回答，
而那句混出来的话没有任何一处可以对照；`self` 下不带，因为那一段恒等于当前这一段。

真链路验过一次（2026-10-27，那时还是一人一段会话）：两轮对话之间把那几条事件手动置 `archived`
（等价于压缩归档），第二轮问"我上次说过的华东区成交口径是什么"，模型调了两次 `recall_session`
（第一次的关键词没命中，它自己换了一组），回答里带回了原文的"按签约主体算，不按开票主体"；
换个 `userId` 问同一句话，召回结果里没有那段话。


## 会话目标：这一段对话要一起达成什么

一段会话上最多挂**一个**目标——它是 `claw4j_session.session_entry` 上的 `goal_*` 列，
不是另一张表（票 06）。那一行装的是**会话节点**：段、两个时间、累计用量与目标。
它回答的是"这一段话在往哪儿走"，不是"这件事做到第几步"——**它不按步骤推进，也没有进度百分比**。
照 OpenClaw 的 `SessionEntry` 形状（它的 goal 就是 entry 里的一个对象）：

- **六态**：`active` / `paused` / `blocked` / `budget_limited` / `usage_limited` / `complete`。
  `usage_limited` 现在进不去，词表留着（OpenClaw 自己也标着"为将来保留"）。
- **只有 `active` 进提示词**。每回合那一行是四句话拼的：
  推进它 / 没完全达成之前保持活跃 / 同一个阻塞连续三个轮次都在才标 blocked /
  `update_goal` 之后仍要给出用户要的最终回答。少了最后一句，模型会标完 `complete` 就收工，
  用户看到的是"状态变了、但没有回答"的一轮。
- **模型只能标 `complete` 与 `blocked`**。暂停、恢复、清除、改写都是人的按钮（`/goal` 那一族），
  模型手上没有那几个参数。它能说的是"我做到了"与"我被卡住了"，不能悄悄把靶子挪走。
- **额度是目标的属性**：`create_goal` 带 `token_budget`，每轮收尾按**快照差**重算用量
  （`max(旧值, 会话累计 - goal_token_start)`，不是"把这一轮加上去"），撞线进 `budget_limited`。
  `goal_token_start_fresh=false` 表示建目标那一刻还没有可用快照：下一次真实用量到来时把它
  采纳成起点，之前的花费不算给这个目标。`/goal resume` 是唯一能开新窗口的动作，
  而且只对受限状态开。这条与"工具调用次数"是两件事：后者是一轮之内的熔断，
  到点就停、不改任何持久状态。
- **五个时刻分开存**：`goal_paused_at` / `goal_blocked_at` / `goal_completed_at` /
  `goal_usage_limited_at` / `goal_budget_limited_at`。合用一个 `updated_at` 答不了
  "首次完成时间"——重复 `complete` 要保留第一次那个值（`goal_completed_at = coalesce(旧值, now())`）。
- **`goal_id` 是所有变更的条件**：清掉再建之后，旧界面上那个按钮带着上一个 id，
  写语句 `where goal_id = ?` 匹配不到，于是它改不到新目标。
- **`/new` 换段即无目标，而且是同一条写**：那条 `insert ... on conflict do update` 在换段时
  把 17 个 `goal_*` 列一起置空、`total_tokens` 归零。不是"新段读不到旧行"——
  旧实现那样做，行会留在库里，`goal_status='active'` 的部分索引会把它们算进"有几个目标在推进"。

**为什么不挂在"一轮"上**：一轮答完就不存在了，跨轮盯着一个目标这件事在那个形状里根本表达不出来。
目标与上下文、与段是同一层的东西（一份会话状态），所以它跟会话一起走、一起换段。

**没做**：自动续跑（OpenClaw 在每轮正常收尾后会排一个隐藏的 nudge 继续推进同一个目标）。
我们这里目标只影响提示词，不会自己拉下一轮——那是一件独立的事，记在票 02 的"没做"一节。
`goal_continuation_turns` 列已经在了、恒 0；等续跑落地时它记"自动推进过几轮"
（OpenClaw 的 `continuationTurns`，人工 start/resume 不计）。
