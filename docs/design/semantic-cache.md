# 语义缓存：同一个问题第二遍不该再算一次

> 设计说明：为什么这么做、否决了什么。要看结论去 [README](../../README.md)，要看决策去 [ADR](../adr/)。

"上周华东成交额多少"这类问题每天被同一个人问好几遍，每次都要打模型、查库、再算一遍。
缓存一层做在 Advisor 链上，命中时**一次模型都不调**：

```
请求 ──► 记忆(写这条消息) ──► 脱敏 ──► 缓存(查/存) ──► 工具循环 ──► 模型
                                          │
                                          └─ 命中：直接返回"（同上次）"，工具与模型都不动
```

**命中要同时满足四条，少一条都可能把别人的答案或另一个问题的答案发出去：**

1. **同一个授权范围**。这是安全边界不是优化：`guest` 读不到 `sales_order`、`admin` 读得到，
   同一个问题在两个角色下答案本来就不同。指纹取 `tables + actions` 排序后的哈希——
   **不取 `userId`**（按人分等于同角色的人互相命中不了，缓存白做），
   **也不取角色名**（角色改一次配置，缓存全失效，而改配置看起来跟缓存无关）。
2. **相似度过阈值**（默认 0.93）。这个数是实测的，理由见下一节。
3. **时间词与数字完全一致**。这是补丁，理由也见下一节。
4. **没过期**（默认 1 小时）。

## 阈值不是拍的：一张实测表

用 `text-embedding-v3`（dimensions=1024）算余弦。两组基准分别是
「上周华东成交额多少」与「上周华东区成交额多少」（后者多一个"区"字，就是真链路里用的那句）：

| 余弦（两组） | 问句 | 意思 |
| --- | --- | --- |
| 1.0000 | 同一句话 | — |
| 0.9987 | 上周华东成交额是多少 | 只多了个"是" |
| 0.9967 | 华东上周成交额多少 | 词序颠倒 |
| **0.9950 / 0.9956** | **上上周华东成交额多少** | **换时间，意思完全不同** |
| 0.9470 / 0.9501 | 上周华东销售额多少 | 同义（额 → 销售额） |
| **0.9372 / 0.9117** | **华东上周卖了多少** | **同义改写** |
| **0.9187 / 0.9154** | **上周华东订单量多少** | **换指标** |
| 0.8968 / 0.9057 | 上周华南成交额多少 | 换区域 |

同一类"同义改写"在两组里差了 0.026，这个抖动幅度本身就是一个信号。这张表否掉三个直觉：

- **票面原定的 0.95 太高**：连 0.9470 的同义说法都会落空。
- **纯阈值救不了"换时间"**：0.995 比同义改写还高。任何单一阈值都无法同时做到
  "命中 0.9372"和"挡住 0.9956"——这不是调参能解决的，是语义相似度这件事本身的边界。
  所以命中判定里多了一道**词面守卫**：两个问题的相对时间词集合、数字集合必须完全一致
  （`上周` vs `上上周`、`3 月` vs `4 月`）。它挡的是这一类错，不是所有错，
  所以它写成一小段正则而不是一个"语义实体抽取"框架。
- **"同义改写"与"换指标"的分数是交叠的**（0.9117~0.9501 vs 0.9154）。
  任何阈值都做不到"命中所有同义改写、同时挡住所有换指标"。于是问题变成：
  往哪一边错？

**答案是往"漏"的那一边错。** 0.93 挡得住换区域（0.90）与换指标（0.9154），
代价是漏掉措辞差得多的同义改写（0.9117）。漏只是没省到钱，误是给出另一个问题的答案——
这两种错的代价不对等，所以阈值没有"中间最优"，只有一个正确方向。

**这个结论要诚实地接受**：语义缓存对"数值/时间/指标实体只差一点"的问答本质上不可靠。
它真实的收益场景是"同一个人几分钟内几乎原样再问一遍"（1.0 与 0.99 那一档可靠），
不是"随便换个说法都能命中"。真出问题时的第一反应应该是调高阈值或关掉它，
而不是再往上叠启发式规则。

## 哪些一轮不缓存

判断依据是**这一轮实际调用过的工具**，不是问题文本。规则是"所有工具的动作名都必须等于 `read`"：

| 这一轮 | 缓存？ | 为什么 |
| --- | --- | --- |
| 一次工具都没调（纯问答） | 是 | 没有外部状态参与 |
| 调了 `querySales`（`read`） | 是 | `read` 是这个系统里唯一被声明为幂等的动作 |
| 调了 `draft_script` / `run_script` | 否 | 有副作用，复用那一轮的答案等于复用一次执行结果 |
| 调了没登记权限的工具 | 否 | 没人评估过它会碰到什么，保守方向是"不缓存" |

"这一轮调过哪些工具"记在 `ToolCallLog`（ThreadLocal）里，写入点是 `MeteredToolCallback`——
那是所有工具的唯一入口，父 Agent 与子 Agent 都从那里过。放在别处必然有某条路径漏记。

**流式只读不写**：读是安全的，而且对 SSE 与飞书的收益更大（用户对首字延迟最敏感）。
写不做，因为流式下要拼出完整回答得靠累积每一块，而"每块是增量还是累计"因供应商而异——
拼错就是缓存了一条重复十遍的回答，而它下次会被原样发出去。同步路径已经能把缓存填上。

## 失败姿势：缓存不参与可用性

| 出问题的环节 | 结果 |
| --- | --- |
| 向量服务挂了 | 这一轮当作没命中（`reason=embedding-failed`），照常回答 |
| 缓存查询挂了 | 同上 |
| 缓存写入失败 | 只影响省成本，这一轮的回答照常返回 |
| 库里没有这个权限范围的候选 | 没命中；另查一次全局最相似的，用来区分 `no-candidate` 与 `different-permission` |

最后一条只是**诊断**：那个全局候选绝不参与命中判定，否则就等于绕过了授权。

## 与票面原设计的三处偏离

| 票面 | 实际 | 理由 |
| --- | --- | --- |
| 引回 Redis Stack | pgvector（`claw4j_cache.semantic`） | 缓存要和授权、会话在同一套数据里做一致性判断；pgvector 已经在库里。ADR-0005 第二次修订 |
| 阈值 0.95 | 0.93 | 0.95 太高，连 0.9470 的同义说法都会落空；而同义改写与换指标的分数本来就交叠，只能选"宁漏不误"那一侧 |
| TTL 24 小时 | 1 小时 | 问的是相对时间（上周/本周），答案随日历翻页而变；24 小时会在跨周一时给出上一周的数 |

**Redis 仍然不引**。ADR-0005 里那段"引回 Redis Stack 要换镜像、客户端要 Jedis"的说明已标作废——
不标的话，下一个人会照它去装一遍，然后发现装了个没人用的东西。
