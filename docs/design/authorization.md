# 权限：只有两处落点——清单与执行闸

> 设计说明：为什么这么做、否决了什么。要看结论去 [README](../../README.md)，要看决策去 [ADR](../adr/)。

问"上周华东区成交额多少"时，模型会要求调 `querySales`。**它要求了不等于它会发生**，
但拦住它的不是"调了之后被拒"，而是**它一开始就没在清单里**：

```
请求头 ──► 通道认人 ──► Principal(userId) ──► 工具清单 ──► 模型
                                                │
                                                └─ 不在清单里：模型看不见这个工具，
                                                   连"我要调它"这个计划都不会产生
                                                 在清单里、且要人批：执行前先问一次
```

三件事，按顺序：

1. **准入**在最外面：这个人能不能用这条通道（五份白名单，默认空 = 谁都不进）。
   它回答的不是"能做什么"，是"能不能进来"。
2. **可见性**决定模型能看见什么。看不到的工具，模型连计划都不会做——这比"调了被拒"
   彻底一层：被拒之后模型还得消化一句"你没有权限"，而它会开始找别的路。
   收窄只发生在清单上（画像 / allow / deny / 按发送者 / 子 Agent），**加不回来**。
3. **执行闸**决定"看见了、能不能真的做"：要人批的工具先问一次（审批），
   exec 类另按 `security × ask` 当场判一条命令。

身份只剩一个 `userId`。**它不携带任何权限**——`Principal` 回答"这次调用是谁发起的"，
不回答"他能做什么"。角色、可读表、可执行动作那一套（ADR-0007 的结论）在 ADR-0030 里
整块删掉了：那套东西的第一性问题是把业务系统的授权语义搬进了 agent，而 agent 这边
真正管得住的是"模型看得见什么"。

代价写在 ADR-0030 的缺口表里，最要紧的两条：

- **清单算漏就是越权**，没有第二道兜底。改清单的 PR 要当权限变更审。
- **业务数据范围没有判定**：知识库检索与销售数据范围都只看"有没有身份"。
  这是第二步的事，别把现在的宽松当成设计。

## 脱敏是另一件事：查到了能不能原样说出去

权限管"能不能拿到"，脱敏管"拿到了能不能原样说出去"。这一层没有随权限模型一起变，
它挂在出站 Advisor 上，认手机号与身份证号，手机号留头三尾四、身份证留头六尾四——
全打码的话"尾号 5678 那位"这种话就说不出口了。

三点值得留意：

1. **order 在工具循环外面**（小于 `ToolSearchToolCallingAdvisor.DEFAULT_ORDER`），整通对话只在出站前做一次。
   放进去会把**工具结果**也一起打码，而模型要靠原始值判断"这个号码是哪一单的"。
2. **流式不能逐块各自脱敏**：分块边界会正好落在一个手机号中间（8 字一块时是必然的），
   两块都匹配不上，原始号码整个漏出去，而且漏不漏取决于模型那批吐了多少字。
   做法是扣住"还可能是号码开头"的尾巴，等下一块来了再一起判，收尾时把剩下的全部吐出。
3. **日志里也是脱敏后的**。只在响应里脱敏、日志里仍是明文，等于没脱；
   `ChatClientAgentPort` 敢在 DEBUG 打出站全文，正是因为脱敏已经做完了——
   哪天有人在链路之外打日志，那条断言会立刻出现原始值。
