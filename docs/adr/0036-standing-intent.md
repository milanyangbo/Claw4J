# 事件条件意图：遇到才做，不排时钟

---
status: accepted
date: 2026-11-22
---

要对齐 OpenClaw 的 standing intents：用户留一句嘱咐（"以后有人问客户数，先确认是签约数还是活跃数"），
系统记住，等条件出现时提醒一次。它与定时任务是两档东西——定时任务"到点做"，它"遇到才做"。

## Context

现有三档里缺这一档：

| 想要 | 现在有什么 |
| --- | --- |
| 每天九点提醒我 | `ScheduleScanner` + `schedule_task`（到点） |
| 回答简短点 | 人设（常驻、每轮注入、不过期） |
| **老王来电话时提醒我那笔钱** | **没有** |

第三种靠人设就得每轮念一遍，靠记忆只能记成"老王很重要"，靠定时任务根本设不出来。

## Decision

**一、表逐字对齐它的 `standing_intents`，只加一列 `owner`。**

它一列一列都在表达"这条意图什么时候该触发、还能触发几次"：`trigger_keywords` / `channel_scope` /
`sender_scope` / `creator_sender` / `status`（六态）/ `expires_at` / `max_fires` / `fire_count` /
`cooldown_seconds` / `last_fired_at` / `source_session_id`。照抄，不自创。

两处偏离：

1. **加 `owner`**：它每个 agent 一个 SQLite 库，owner 由库隐含；我们一个库多租户，只能显式写。
2. **`trigger_embedding` 建列不写**：当前只做关键词匹配。写入恒为 null，将来要开只改写入与匹配
   两条路径，不动表。

**二、作用域按 owner + 通道 + 发送者，不含"段"。**

它的 `source_session_id` 只是出处，scope 是 channel/sender——意图不随会话重置消失。我们的段
每日/空闲轮换（ADR-0026），按段存等于"每天凌晨四点把意图全清掉"，与"90 天有效"矛盾。

代价写清楚：`/new` 之后旧意图仍会触发。这与"换段 = 新对话"有张力，是有意取舍。

**三、匹配是纯规则，零模型调用。**

整词匹配；含 CJK 的词按字面子串（FTS 与我们的分词都把不带空格的中文整句当一个词）；
每轮最多 256 个候选，防止"吵的触发词拖慢回复"。命中后 `fire_count++`、记 `last_fired_at`，
冷却过后回到 `armed`；预算耗尽转 `done`；过期转 `expired`。

**四、命中注入一段有界隐藏块，失败不阻塞回复。**

与它一致：块是有界的少量文字，不是系统提示的一节。数据库不可用时不注入、不报错——
记忆子系统降级只掉召回质量，不吃掉一整轮。

**五、取消只能显式。**

不从不含命中的普通对话里推断"他不想被提醒了"。这既是它的裁决，也是我们唯一能解释的行为。

**六、子代理不触发。**

它的匹配只发生在"可交互的回复"上；子代理不是回复，所以不匹配。我们的子代理不走
`PromptComposer`，天然不触发——这一条要写成用例，别靠"碰巧不走那条路"。

## Consequences

- 意图跨段存活：`/new` 之后仍会提醒，用户会觉得"我明明换了话题"。要撤销得显式 `intent cancel`。
- 只有关键词，没有"意思相近也算"：说了"客户数量"而触发词写"客户数"能中（子串），
  说"多少家客户"就不中。这是当前取舍，不是缺陷漏写。
- 多一张表 + 两个索引，跑在 `claw4j_session` 里，跟着 `SessionCleanup` 那条任务一起过期。

## 与既有 ADR 的关系

- **ADR-0026（段的边界）不冲突**：段仍管"对话内容"，意图是 owner 级的前瞻记忆，作用域显式不含段。
- **ADR-0024（不往上下文钉进度）不涉及**：意图注入的是"这一次命中"，不是常驻状态。
- **ADR-0021（明确不做）不涉及**：这不是 heartbeat，没有自唤醒，只在有入站消息时匹配。
