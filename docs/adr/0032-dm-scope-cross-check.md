# 0032 `dm-scope=main` 与多人可及不能同时成立：启动期交叉校验

- Status: accepted
- Date: 2026-11-20
- 决策来源：用户 2026-11-20。"只是移动了一下配置文件地址，并没有改代码逻辑呀，感觉应该优化代码逻辑吧"
  —— 原提议是"启动时扫旧配置键并告警"，被否掉：那是键形状的胶水，下次加键还得再写一遍。
- 相关票：`.scratch/session-scope-guard/issues/01-dm-scope-guard.md`

## 背景

ADR-0029 定了会话键的两个边界：`dm-scope`（私聊怎么分段，默认 `main`）与 `group-scope`
（群聊，默认 `per-group`）。`main` 意味着**一个人所有私聊共用一段上下文**——单用户部署是便利，
多人可及的部署里等于串话：网页里问到的数字，飞书私聊里的模型也看得见。

这条风险原来只写在两处：`SessionScopeProperties` 的类注释、`application.yml` 的注释。代码里没有任何
一处会**拒绝**它。更糟的是那个类的注释写着「所以生效值在启动日志里打一行」——
**这一行从来没写过**（`dmScope()` 在整仓只出现在注释里）。所以"配了 `main` 的多人部署"
在日志上没有任何痕迹。

配置键归并（ADR-0031）之后，这个问题多了一条进入路径：升级时没改 yml 的部署，旧键静默失效、
`dm-scope` 落默认值 `main`。但根本原因不是键搬家，是**代码把"没配"与"认不出"都当成 `main`，
且从不检查它与准入名单是否自洽**。

## 裁决

**一、认不出的值启动失败。** `dm-scope` 只接受四个枚举值，其余（拼错）抛异常并列出可选值。
与 `session.maintenance.mode` 同一口径：这一档两侧的后果不对称，错的方向必须选得出来。
"没配"仍然是 `main`（对齐 ADR-0029 与上游默认值），但下面第二条会让它可见。

**二、多人可及 + `main` = 拒绝启动。** 装配层取**所有已启用通道准入名单的并集**：

```text
并集为空                → 放行（谁都不能进）
并集 = {一个人}          → 放行（多通道也只有一个身份）
并集含 "*"              → 拒绝（"不设准入" = 人数未知）
并集去重后 > 1 个        → 拒绝
dm-scope ≠ main         → 放行
```

判据是**并集**而不是逐通道：http 给 alice、飞书给 bob，每条各自只有一个人，但两个人共用一段
主会话照样串话。

**三、生效值进启动日志。** 把类注释承诺过的那一行补上：私聊与群聊各打一个生效值。

## 为什么不在 agent 里做

`claw4j-agent` 不认识 channel（ArchUnit 的「agent 不认识 channel」）。校验需要同时拿到
`SessionScopeProperties` 与五个通道的配置，只有 `claw4j-app`（拼装面）两边都依赖。
落地成 `InitializingBean`：抛异常即启动失败，早于任何请求。

## 代价

- **本机演示会被拦。** 把某条通道写成 `users: ["*"]`（配置注释里介绍过这种写法）而 `dm-scope`
  还是默认的 `main`，现在起不来。这不是误伤——`*` 意味着陌生人能进，那就不该共用一段主会话；
  两行改法：收窄 `users`，或把 `dm-scope` 改成 `per-channel-peer`。
- **`users: []`（默认）不受影响**：一个人都进不来。
- **只拦 `dm-scope`，不拦 `group-scope`**：`group-scope` 错的方向是安全的（认不出落 `per-group`，
  分得开），"群并进主会话"必须显式写 `main`，不存在"默认就危险"这回事。
- **`*` 被当成"很多人"**：代码无法知道通配符背后是多少人，取严的一侧。

## 退场条件

- 如果哪天把 `dm-scope` 的默认值改成 `per-channel-peer`（多人安全侧），这条硬失败降级为 WARN。
- 如果通道准入模型换成"按角色/组"（而不是每人一条名单），并集算法作废，改为读那个模型的人数上界。
- 如果出现"一次进程服务多个 agent 且人的集合不同"的形态，"谁跟谁共用主会话"要按 agent 分别判，
  这条单点校验不够用。
