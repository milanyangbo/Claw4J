# 测试不再用假模型：所有需要模型的测试连真实 DeepSeek

---
status: accepted
date: 2026-10-23
---

单元测试与集成测试**一律不再对 `ChatModel` 打桩**。需要模型的测试连真实 DeepSeek；
`MockChatModel`（生产兜底）与 `ScriptedChatModel`（测试编排）两个假模型类一并删除。
没有 API key 时测试**失败**，不跳过；key 从环境里取（本机 `set -a; . ./.env; set +a`）。
CI 暂未接入（README「质量门禁」记了它的状态），将来接上时由 `secrets.DEEPSEEK_API_KEY` 提供。

本 ADR **取代** ADR-0006 的"所有单元测试与 CI 一律 mock 模型调用"与
ADR-0008 测试策略里的"单元测试全部 mock 模型调用"。

## 为什么反转

ADR-0006 当初否决"真实调用进 CI"的理由成立且仍然成立：基线会从"改坏了会红"
变成"供应商抖一下也会红"。这次反转**不是**推翻那条理由，而是承认另一条更重的事实：

**假模型拦不住只在真链路上出现的缺陷，而这类缺陷我们已经踩过三次。**
M1-07 用真模型跑一遍，连抓两个 bug（跨厂商降级丢工具、模型内部重试把降级拖成分钟级）；
再往前，ADR-0006 记过一次"通义不调工具、直接反问口径"。这三个有一个共同点：
**假模型既不会真的失败，也不会真的需要工具**——所以任何一张假模型的测试都拦不住它们。

代价的另一半更隐蔽：假模型把断言的落点从"模型做对了什么"挪到了"脚本念了什么"。
`SalesQueryEndToEndTest` 断言第二轮提示词里带着 `128400.00`，而那个数**是脚本里的常量**，
不是模型查出来的——它证明的是"链路能把一串字符传下去"，不是"模型会按工具描述去调
`querySales`、会把数据库报错读懂再重写一版 SQL"。模型侧那半件事从来没被验过。

## Considered Options

**维持全 mock（ADR-0006 现状）**
否决。理由即上节。补一条：面试场景里"你怎么测 LLM 应用"这个问题，
"我们全 mock"是最容易被追问到墙角的答案——mock 只能证明管道通，证明不了会干活。

**录制真实交互做回放（cassette / VCR 模式）**
否决（本次）。真跑一次录进仓库、之后回放，确实同时拿到真实性与确定性，
但它引入一个新问题：**cassette 会随 prompt、工具描述、Advisor 链的变化静默过期**，
过期之后它退化成一个更难察觉的假模型——内容看着还是真模型说的，但已经不是当前
这条链会产生的东西了。要压住这点就得再建一套"过期检测与重录"机制，
那是一张独立的票而不是顺手能带的事。

记下回退条件：**若真实模型的 flaky 率或成本失控（见下），第一顺位就是改成录制回放**，
而不是退回 mock。

**真模型只跑 IT，`-Preal-model` 隔离，不进 CI（现有做法）**
否决。日常回归里仍然一条真链路都没有，`RealModelIT` 只有想起来才跑一次，
等于把"只在真链路上才暴露的缺陷"留给下一次联调去发现。

**全面连真模型（采纳）**
代价已知且可控（见下），换来的是日常回归里每一条都在真链路上跑。

## Consequences

### 代价（逐条记账，不粉饰）

- **每次 CI 烧 token 且变慢**：约 20 条测试、每条 1–6 次模型往返，一次 CI 的量级是
  几十次调用、几分钟。DeepSeek 的单价下每次 CI 是几分钱，慢是主要代价。
- **flaky 从零变成非零**：真实模型不保证每次都调工具、也不保证措辞。
  处置是三条一起上：温度设 `0.0`（把随机性压到最低，这是最便宜的一招）、
  断言一律方向性、关键断言给**有限重试**（最多 2 次，第 1 次不调工具就再要一次）。
- **约 14 条"精确编排"测试失去端到端形态**：预算、鉴权计数、脱敏这三条
  依赖"脚本指挥模型连调 7 次 / 精确调用 1 次 / 精确输出一句话"，真模型做不到。
  它们改成**不经过模型的组件级测试**：真实 `ToolCallingManager` + 真实预算配置 +
  真实 Advisor，工具调用指令由测试直接构造（`AssistantMessage` 带 `toolCalls`）
  而不再由模型生成。丢掉的是"模型会自己发起这些调用"这一层，
  留下的是"组件在这条链路上真的这么工作"——后者仍然是真组件，不是假模型。
- **没有 key 就跑不了**：本地与 CI 都必须有 key。

### 落地规则

- **没有 key 是 failure，不是 skip**。跳过与被排除在外的测试会被
  `scripts/assert-no-skipped-tests.sh` 放过——那正是 M1 那个 P0 的形状
  （26 条数据库测试从未执行却被当成绿）。所以无 key 时让测试**红**并写明原因，
  而不是让它安静地"没跑"。
- **断言只写方向性**：拿到数 / 拿不到数 / 文本里不含明文手机号 / 块数大于 1。
  钉整句只会让它在措辞变化时假红，而这里要抓的是"查不到数""说没权限"这类方向性错误。
- **`MockChatModel` 一并删除**，连带 ADR-0006 里"没有可用 API key 时应用必须能启动
  并以 mock 模型跑通全链路"这条一并作废。新的取向是**没 key 就起不来**，
  与 ADR-0006 已经定下的"主模型没配 key 时启动失败"一致——
  留着 mock 兜底，就会出现"本地演示跑的是 mock 却以为是真模型"这种更贵的困惑。
- **模型名与端点仍然全部走配置**（ADR-0006 这条不变），
  `CLAW4J_MODEL_PRIMARY` 一改就能用另一家跑同一批断言。

### 这一趟真模型当场抓到的缺陷（记账）

改真模型的过程中，测试立刻抓到一个假模型时代不可能发现的缺陷，它证明上面那笔代价花得值：

**用户消息里的手机号以明文进了会话表。** 出站脱敏发生在 Advisor 链的 `after`，
而会话记忆是在 `before` 里最早那一步就把用户消息写进库的——它改得到模型的回答，
改不到已经落库的那条用户消息。于是"出站是掩码、会话表里躺着明文"，
而后者是**比出站更持久的一份泄露**，并且没人会去看。
假模型时代没有任何用例往用户消息里放号码，所以这条边界一直是黑的。

修法是**入站就脱敏**（`ChatClientAgentPort` 交给链之前先过一遍 `PiiRedactor`）。
代价要记账：模型从此看不到用户写的原始号码。当前没有"按手机号查订单"这类工具，
掩码不影响任何能力；哪天有了，该给那个工具开白名单，而不是把入站脱敏撤掉。

### 三条 HTTP 用例曾经互相污染

`AuthorizationOverHttpTest` 的三条用例共用一个 Spring 容器、同一个 `X-Claw4j-User`，
于是也共用同一个会话。假模型不看历史，这件事一直没暴露；换真模型后，
"有权限"那条读到了上一条"没权限"的对话，跟着答成没权限。
修法是每条用例换一个用户——**一次性证明不该有跨次依赖**，这条原则本身与模型无关。

### 永真断言会原样吃掉真模型带来的真实性

换真模型时最容易写出的让步是"模型不会复述原话了，那就只断言回答非空"。
这条让步的危险在于它比模型退得更多：断言一放宽，"这条链路其实一直没查到数"就被藏住了，
于是换真模型换来的那点真实性一分都没落到判据上。

活例子：`HttpChannelEndToEndTest` 收尾时三条断言被写成了"非空"，补做变异检验
（把断言改回"回答里有没有库里那个数"）时立刻红 3 条——这个测试一直在用
**没有权限的默认角色**（只发 user 头，落到 `defaultRole = read-only`）问成交额，
而假模型时代它是回声，从没真查过库。

所以本 ADR 里"断言只写方向性"指的是**不钉死措辞**（数字可以写成 128,400 或 128400），
不是**不钉结果**（不能只断言非空）。判据要落在"拿到数 / 明确拿不到数"上。

例外要说清：只验**包装行为**的用例（会话标识透传、结尾块标记、流式确实分了块）
判据落在那些包装属性上，模型输出只需"非空"——它验的本来就不是模型说了什么。
上面那条规则针对的是端到端业务链路的用例。

### 什么时候回退

连续一周内出现下列任一情形，就按上节的回退条件改成录制回放，并回来修订本 ADR：

- 同一条测试在无代码改动的情况下红了两次以上（flaky 已发生，不只是理论风险）；
- 单次 CI 的模型耗时超过 15 分钟，或月 token 支出超过一顿饭钱；
- 供应商限流导致 CI 大面积变红——这时真实信号已经被噪声盖住，
  继续跑真模型就退回了 ADR-0006 当初否决的那个状态。
