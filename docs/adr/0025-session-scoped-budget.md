# 预算挂会话，会话按对话分段

---

status: accepted
date: 2026-11-05

---

A04 的判据是"一次 run 跨 3 轮共调 7 次工具，第 7 次被拒"。这个 ADR 记录的是：
**它从来没有成立过**，以及改挂会话之后，为什么"会话什么时候结束"的答案是空闲超时，
而不是"任务做完了"。

## Context

`ChatClientAgentPort` 每轮收尾都调 `runs.finish(runId, RunStatus.DONE, answer)`，
下一轮开的是新 run（ADR-0024 实测：连问两句之后，该 owner 下未收尾的 run 是 0 条）。

于是 A04 写的"跨轮不重置"，在实现里等于每轮从 0 开始：

```text
第 1 轮  run A  6/6  停
第 2 轮  run B  6/6  停      ← 预算重新给的
第 3 轮  run C  6/6  停
```

三轮各调 6 次、一共 18 次，每一次都落在"新 run 的 0/6"之内。而三处文档
（`V8__budget_dimensions.sql` 的列注释、`RunBudget` 类注释、`application.yml`）
都写着"按 run 累计、跨轮不重置（三轮各调两次会被第 7 次挡住）"。
**文档承诺的防线，代码里没有。**

同一个时期还发现第二个问题：会话键是 `userId@权限指纹`，不含 chatId。
同一个人在网页私聊里查到的数字，会出现在他十分钟后 @ 机器人的项目群里——
权限指纹挡不住这一层，它保证"权限一样才共享"，而这里**听众不一样**。

两件事的根是同一个：`run` 想代表"一件事"，实际只代表"一句话"；
而 `session` 想代表"一段对话"，实际代表"一个人"。

## Decision

**一、run 不改，仍是一轮一件。** 执行单元短命是行业惯例：OpenAI Assistants 的 run
到 `completed` 就是终态，Claude Code 的一次 query 也是。要让 run 跨轮活着，
就得先回答"什么时候算完"，而那个问题没有好答案（见下）。所以不把 run 拉长，
把该挂在"一段对话"上的东西挪到会话上。

**二、预算挂会话**：新增 `claw4j_run.agent_session_budget`，三项（工具调用 / token / 耗时）
按 `session_id` 累计，**空闲超过 `claw4j.run.budget.idle-minutes`（默认 120）即整行清零**。
计数只增不减，不做"对窗口内的 run 行求和"——那样连续对话会回血：
每轮都写新的 `updated_at`，两小时前那几轮滑出窗口，累计值从 5 掉回 3。

**三、会话键加对话维度**：`sessionId = claw4j:user:<owner>:<通道>:<chatId>`。
`owner`（run 归属、审计、定时任务、跨会话召回）保持不变，两把键管两件事。

**四、"什么时候算完"：不判定任务完成，只判空闲。** 这是照行业做的，不是省事：

- OpenClaw 的会话生命周期只有三种结束方式——`idleMinutes` 空闲重置（文档示例 120）、
  每日定时重置、手动 `/new` 或 `/reset`。没有任何"任务完成"判定。
- Claude Code 的 TodoWrite 也是会话级的，退出终端就没了；要跨会话得换落盘的 Tasks API。
- 判定"用户这件事做完了"没有可靠信号：模型猜会提前收尾，等用户说会永远等不到。

## Alternatives

| 方案 | 为什么否决 |
| --- | --- |
| 预算继续挂 run | 就是现在这个：每轮 6 次，18 次全放行，且文档在说谎 |
| 对窗口内的 run 行求和 | 会回血（见上）。额度只会变少是预算最要紧的性质 |
| 把计数塞进 `ai_session` 表 | 那是 Spring AI 的表，不该加业务列；而且它按 owner 存，本身没有对话维度 |
| 新增一张"任务表"承载预算 | 会话已经是"一段对话"的现成载体，再立一张表等于两套生命周期要同步 |
| 让 run 跨轮活着 | 要先定"什么时候算完"；定了也仍然要回答"谁来收尾"。收益是 A08 那类需求，代价是一次语义重写 |
| 只改注释说实话，代码不动 | 额度仍然能被"多问一句"绕过——那不是取舍，是把已知漏洞写进文档 |

## Consequences

- **换通道 = 换对话，记忆断。** 网页切到飞书私聊，讲过的口径要重讲一遍。
  OpenClaw 的默认行为也是这样：跨通道共享要显式配置 `identityLinks`，默认不共享。
  Claw4J 现在没有这个配置项，这条路上的行为就是"断"。
- **老数据不参与会话累计**：`session_id` 为空（加列之前的 run）时退回按 run 自己那一行算，
  也就是改之前的行为。少算一段历史，不拿猜出来的归属去拦人。
- **定时任务共享一段会话**：它的 chatId 固定，两次运行落在同一段会话里，预算也合成；
  跨过 `idle-minutes` 就清零，所以它不会把第二天的运行卡住。
  哪天要"每次运行单独计"，得先给 run 一个**来源**字段（web / 定时 / 审批）——
  不能拿 `notify_policy` 去猜，那是"做完要不要通知人"，不是"这件事从哪来"。
- **跨会话召回还没有跟着隔离**：`RecallSessionTool` 仍按 `owner` 召回这个人的**所有**会话，
  包括群聊与私聊。也就是说历史分段了，但模型主动调 `recall_session` 仍可能把私聊内容
  取到群里。这一条是本 ADR 的**未决项**，不是已完成的部分。
- 会话表里老格式的 id（`claw4j:user:<owner>`，不带通道与 chatId）再读不到——
  与权限指纹改口径时一样：只丢记忆，不泄数据。

## 待办

- 召回按"调用方当前所在会话"过滤，或者给 `recall_session` 加作用域参数（未开票）。
- 跨通道同一段对话（OpenClaw 的 `identityLinks`）——需要先有"这两个 chatId 是同一个人同一段话"
  的事实来源，不能猜（未开票）。
