# 通道选型：飞书长连接为真实 IM 通道，HTTP+SSE 为无账号演示通道

---
status: accepted
date: 2026-10-22
---

ADR-0008 定的通道顺序里没有真实 IM。真实 IM 通道的价值不在于"多接一个平台"，而在于它会逼出 HTTP 通道逼不出来的工程约束（事件推送的超时、重推、多实例投递语义），这些约束才是能讲的东西。选择标准是三条：**个人能否开通**、**本地能否免公网调试**、**有无官方 Java SDK**。

## 事实核查结论（2026-10）

| 平台 | 个人能否开通机器人 | 免公网调试 | 官方 Java SDK |
|---|---|---|---|
| **飞书** | ✅ 个人账号可直接创建企业自建应用，无需企业认证 | ✅ 长连接（WebSocket）模式，SDK 主动外连，无需公网 IP/域名/内网穿透 | ✅ `com.larksuite.oapi:oapi-sdk`，Central 上最新 2.8.7 |
| **企业微信** | ❌ 个人可注册"个人组建团队"，但**腾讯官方明确：个人注册无法登录网页管理后台**，而机器人必须通过在管理后台创建自建应用拿 AgentId/Secret | 部分（有长连接，但前提是能进后台） | ❌ 无官方 SDK，只有社区包（`weixin-java-cp`） |
| **钉钉** | ✅ 个人可建团队 | ✅ Stream 模式同样免公网 | ⚠️ 官方 SDK 未在 Maven Central 命中，需按官方文档确认坐标 |
| **Telegram** | ✅ BotFather 几分钟拿 token | ✅ 长轮询/getUpdates | ✅ `telegrambots` 6.9.7.1 |
| **微信个人号** | ❌ 无官方机器人 API，第三方走协议逆向 | — | ❌ 封号风险，不做 |

**企业微信这条路对没有公司的人走不通**，不是配置问题而是账号体系问题：个人团队拿不到管理后台，就没有自建应用，也就没有收发消息的凭据。它唯一能用的是"群机器人 webhook"，但那个只能往群里推消息，**收不到用户消息**，做不成双向对话。若后续拿到企业管理员权限，本条 ADR 的顺序需要重排。

## Considered Options

**Telegram 作为主通道**
否决。它最简单，但国内访问需要代理，面试现场演示有翻车风险；且它在国内企业场景里不是主流，讲不出业务价值。保留价值：作为"第二个 Channel 实现"证明 SPI 抽象有效，成本仅半天。

**企业微信作为主通道**
否决，理由见上。

**HTTP+SSE 作为唯一通道**
部分采纳，但降级为"演示通道"而非唯一。它不需要任何外部账号，是面试现场唯一能保证演示的通道，必须保留；但它逼不出事件推送的真实约束。

**飞书长连接 + HTTP+SSE 双通道（采纳）**
飞书满足全部三条标准，且它的两条硬约束反而成了设计素材（见下）。

## Consequences

- **交付顺序更新为**：HTTP+SSE（M1）→ 飞书长连接（M2）→ A2A（M3）→ Teammors WebSocket（最后，可不做）。Telegram 作为可选的第二 Channel 实现，用于证明 SPI 可替换。
- **3 秒超时重推是硬约束**：飞书长连接要求收到事件后 3 秒内处理完成且不抛异常，否则触发重推。而 Agent 跑一次 Text-to-SQL 可能十几秒。因此 `ChatChannel` 的入站路径必须做成**收到事件立刻 ACK → 交给异步编排 → 结果通过主动发消息接口回推**，而不是在事件线程里同步等 Agent。这条约束同时逼出**事件去重**（重推会导致同一条消息被处理两次），是真实的工程问题，正好落在 M2。
- **集群投递语义**：长连接模式的推送是集群模式、不支持广播，同一应用多个客户端时只有随机一个收到。本地演示保持单实例；多实例场景要说明这条限制，不能假装它能负载均衡。
- **模块调整**：`claw4j-channel` 拆为 `claw4j-channel-api`（放 `ChatChannel` SPI，不依赖任何平台 SDK）+ `claw4j-channel-http` + `claw4j-channel-feishu`。重依赖（`oapi-sdk`）只留在飞书实现里，`claw4j-app` 按需引入，不想接 IM 的人不会被拖累。ADR-0004 的五模块由此变为七模块。
- **凭据处理**：App ID / App Secret 走环境变量与 Spring 配置，不进 `SKILL.md`、不进仓库（延续 ADR-0002 的收口原则）。
- 1.x 的 Teammors 私有加密协议仍排最后：它的 ECDH/AES 与自建心跳讲不出通用价值，代码留在 `legacy/` 作对照。
