# 明确不做清单（以及与 OpenClaw 的偏离说明）

---
status: accepted
date: 2026-10-29
---

把"不做什么"固化成可复查的条目，**每条都写清"为什么不做"与"什么条件下应该重开"**。
这份文档存在的唯一理由：这六类需求每一条都有"看起来很诱人"的时刻，不提前写下来，
就一定会在最容易被说服的场合被塞进路线图。这不是"以后再说"，是**刻意不做**。

## Context

对齐 OpenClaw 时最大的风险不是漏了某一项，而是**把它的形态当成目标**。

| | OpenClaw | Claw4J |
| --- | --- | --- |
| 定位 | 单用户常驻个人助手 | 企业里那一层：多用户身份、权限前移到模型之前、可嵌入到网关后面 |
| 形态 | Gateway 是控制面，通道 / 浏览器 / 手机节点都是它的外设 | 无状态 HTTP 服务，通道可换 |
| 状态 | 本地文件 + SQLite | Postgres + Flyway，多实例与可审计优先 |

所以**同一个功能落在两个系统里，判定可以相反**：OpenClaw 的 `computer use` 是核心执行力，
我们做它就是错——一个多租户服务里让 agent 去操作某台终端的桌面，权限模型的粒度再细也没有挂点。

反过来，两条看起来相似的曲线也不能互相印证：**企业侧的多租户隔离与"用完即走"是两条不同的曲线，
embedding 走云端推理还是本地推理，跟"帮同事收一份投标材料"也不是同一个取舍**。

## Considered Options

**不做类型的笔记别落盘，写在对话里就够了**
否决。对话会丢，而且提出这个建议时看不到当年的理由，只会再问一遍。ADR 是给"那时不在现场的人"看的。

**只在 roadmap 里写"暂缓"，不写理由**
否决。两条：① 暂缓的条目会过期——等多久？没人知道。② 它替代不了"什么条件下可以重开"，
而没有重开条件的东西很快会变成永久禁令或被随手推翻，两种结局都不好。

**一条 ADR，每条带「为什么」+「重开条件」（采纳）**
每条最长不过五行，但每一条都可以被单独复查、单独重开、单独推翻。

## Decision

| 明确不做 | 它的形态 | 为什么不做（一句话，不涉及第三方产品） | 什么条件下重开 |
| --- | --- | --- | --- |
| **浏览器自动化** | Playwright + 托管浏览器，OpenClaw 最核心的执行力之一 | 多租户下"操作谁的浏览器"没有答案；会话、凭据、Cookie 的归属说不清，而权限模型要在模型之前裁决 | 出现明确的**企业内**场景（如代替操作员办理某个后台流程），且该场景已有独立执行边界时，做成独立 MCP server 宿主 Sandboxed sidecar；不长进核心 |
| **语音 / Canvas 实时画面** | wake word、连续语音、实时画布 | 依赖终端侧硬件与长连接流式协议；属于个人终端，不属于服务 | 有终端产品需要我们做后端时，由那个产品实现，我们只提供会话接口 |
| **设备节点**（macOS / iOS / Android 节点、Windows Hub） | Gateway 配对后远程执行 | 设备属于人，不属于服务 | 不设想。企业侧若有 MDM 需求，那是另一类产品 |
| **配对与 challenge**（未知发送者配对码） | pairing 挑战陌生发送者 | 身份由网关侧注入是**明确边界**（ADR-0007）；自己做一套等于绕过企业 IAM | 部署形态变成"直接暴露到公网且无网关前置"时**必须**重开——但那时应该先补网关 |
| **`heartbeat` 常驻自唤醒** | 每小时让便宜模型自己检查一遍 | 企业版第一版它会变成烧钱机器：没有预算与审计之前，自唤醒 = 不可控的成本 + 不可解释的行为 | A04（run 级预算）与 P07（审计）落地**之后**重估。届时它是 P05 `schedule_task` 的一个上层用法，不是新能力 |
| **插件市场 / ClawHub 分发** | 注册表 + 一百多个官方插件 | 我们的插件是 Boot 自动配置，没有分发渠道 | 生态出现之前不做。先有使用方，再谈分发；**P16 只做版本契约（plugin 声明依赖的 core 版本区间）**，不做市场 |

### 讨论过并否决的三条（写在这里，区别开"没想过"与"想过不要"）

1. **显式 ReAct 的 thought / observation 文本协议**。框架的工具循环本身就是这个，
   再在提示词外面包一层 XML 标签只会更脆——模型不按格式输出就崩，而"不按格式"是常态不是异常。
2. **自动重试到成功**。无人值守时（定时、审批通过后续跑）它是预算杀手，而且会把一次确定的失败
   变成一串看不出头的重复调用。见 ADR-0017 对 blocked 行的处理：转成待办，不自动重来。
3. **自研向量检索**。pgvector 已经在 ADR-0005 里定了，别的向量库不会带来它没给的能力。

### 与 OpenClaw 的偏离：三追平、两领先、两不追（外加一不补）

把决议归档而不是停留在口头讨论：

| 结论 | 内容 | 落在哪些票 |
| --- | --- | --- |
| **追平 1**：任务与投递 | run / step + 通知策略（`done_only / silent / state_changes`，照 OpenClaw `tasks` 系统的少数好设计），定时任务默认 `silent` | A01 A02 A05 |
| **追平 2**：执行隔离 | sandbox 后端（network=none、只读根 FS、限额），从"有约束"变成"有隔离" | P17 |
| **追平 3**：运维自检 | `doctor` | P18 |
| **领先 1**：治理粒度 | 权限前移到模型之前、越权不花 token 不进历史（已在） | P01 P09 |
| **领先 2**：工具可见性 | 渐进式披露 + 预算，行为不随工具数量变化（已在，比全量注入省 token） | A07 |
| **不追 1**：执行外设 | 浏览器 / 语音 / Canvas / 设备节点（本表上半部分） | — |
| **不追 2**：常驻自唤醒 | `heartbeat`（待 A04 + P07 落地后重估） | — |
| **不补**：插件市场 | ClawHub 分发，**P16 只做契约** | P16 |

## Consequences

1. **这几条是对外的默认口径**。被问到"支不支持浏览器自动化"时，标准答案是
   "作为 MCP server 接入、核心不做"——这句话现在有了出处，不需要每次重新论证。
2. **"以后再说"的条目会过期，这是特性**。表里每条都写了重开条件，其中 `heartbeat` 的条件
   （A04 + P07 落地）在 M8 内就可能满足。届时它是被引用，而不是被遗忘——这正是写下来的目的。
3. **代价是落后的地方不会自动补上**。按上面那张表，七条企业属性里"已在"的只有治理粒度与
   工具可见性两条；"执行隔离"与"凭据有主"要分别等到 P17 / P08 才解决。在那之前，这两件事
   只能靠**部署层**（容器、secret 注入）兜，不能靠应用层的 `SandboxPolicy` 兜——
   **这句要写进运维文档**，别让使用者误以为应用层已经给了隔离。
4. **每一条都可以被单独推翻**。这是把为什么写下来的反过来好处：将来有人真的要做一个设备节点，
   他可以直接在这张表上改一行，而不用先说服所有人。
