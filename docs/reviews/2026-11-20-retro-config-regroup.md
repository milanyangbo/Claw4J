### A · 流程上自作主张（1 处）

`AGENTS.md` 写得很直白：**ADR → 票 → 代码，顺序不能换，不许改完代码回头补 ADR**。
这一轮是用户当场裁决的形状（"都放到 `advisor.` 下面"、"改成一张表"），我在票里写了分类理由，
那恰好就是 ADR 该写的内容——**决策做对了，位置放错了**。事后补的 0031 是记录，不是裁决。

要认的差别：用户当场说"这么做"不等于"跳过 ADR"；裁决已经发生，落成文件是同一个动作的一步，
应该发生在写第一行代码之前。

### B · 判据先于核实（1 处）

"列表比 map 更有扩展性"——这话我照抄了用户的前提，没在同一个呼吸里说出代价：
以名字为键的 map 天然不能写重，改成列表之后 `name` 变成普通字段，写重写空只能靠启动期校验拦。
代价后来补进了票和 ADR，但**说出来是零成本的**，补进去要改三个文件。

同源的还有一处没进表：我一开始的判断是"配置键改名对部署无害"——实际旧键静默失效
（Spring 绑定忽略未知键，不报错不警告）。这个判断是写 ADR 的「代价」时才真去核的。
"无害"这种词，要么当场给依据，要么别用。

### C · 承诺比代码走得远（3 处，本轮主症）

第 5 条是上一轮复盘 C 堆的原样重演：**票 06 的 TDD 表六条全仓不存在**，这一轮是**三张票根本没有表**。
上一轮为此加的闸（`check-ticket-cases.sh`）只查"打了 ✅ 的用例名在不在仓库里"，
查不到"这张票里有没有那张表"——闸修的是半个问题，于是同一个坑换了个形态再来一次。

第 8 条更隐蔽：报错文案本身是"承诺"。表被删空时报"没有 name=deepseek 这一条"，
读者会去查名字，而真正的原因是整段配置没了。**报错指向错的地方，比不报错更贵**。

### D · 批量替换与整块搬运没打样本（4 处）

第 1 条是这一轮唯一造成外部影响的：指标名是对外契约，改了之后面板、告警、历史数据静默对不上，
而它不报错、不红、用例也照过（测试里的断言被我一起改了，所以是**绿着错的**）。
这是"测试跟着实现一起改"的经典形态：断言和常量是同一批替换的，闸看不见。

第 2 条与上一轮第 10 条同源（137 处 `**x**` → `<b>x</b>` 打坏四处单行 Javadoc）：
上一轮的教训写成了"跨文件替换先打样本"，这一轮的手写 javadoc 又犯，说明**规则记在复盘里不等于
写的时候会想起来**，得靠"写完立刻 grep 一次 `**`"这种机械动作。

第 3、4 条同一类：整块搬 YAML、整块改注解，都是"改了一处、旁边那处跟着坏"。
注释不参与解析，缩进错了不报错、只误导下一个读的人。

## 三、这一轮验证了哪些结构真的在拦人（3 条）

1. **两轴评审的分工边界**：指标改名只有 Spec 轴看得见（它问"做了票里没要求的事吗"），
   Standards 轴完全看不到——它只看规范和坏味道，而"多做了一件事"不是坏味道。
   反过来，javadoc 加粗与缺 ADR 只有 Standards 轴看得见。上一轮的结论是"两轴不能合并排名"，
   这一轮补上后半句：**它们不是同一件事的两种说法，是两类缺陷的两个入口**。
2. **`check-ticket-cases.sh`**：写完三张票的表后跑，153 条引用全部对上。它逼我把用例名写成真名，
   也让"⏳ 行必须搬进缺口"这条规则有了落点。但它的盲区这一轮暴露得很清楚：**没有表 = 它不检查**。

   补一个数：`.scratch` 下 126 张 `resolved` 的票里，**101 张没有「TDD 用例清单」**（07 之前那一批
   是"验收"小节，不是本票要求的三列表）。要求全仓合规就是 101 张红，红完没人补。

   用户 2026-11-20 的裁决把这道坎绕过去了：**历史不追，新票必须有**。落地方式是给闸加一步，
   只认 git 里"还没进 HEAD"的票（`??` / `A`），要求两样东西：裁决在哪（`docs/adr/00xx` /
   `ADR-00xx` / `无需 ADR：<理由>`）与「TDD 用例清单」（resolved 再要一行 `复核：`）。
   加完照这仓库的规矩**先红一次**：临时票写了三种形态——都缺、缺复核行、三样齐备——分别红、红、绿，
   验完把临时票删掉。代价是**它在提交后就不管了**（判据是"还没进 HEAD"，所以提交前跑才有意义），
   这条盲区写在脚本头部。
3. **`claw4j-agent` 的 14 文件上限**：providers 的用例没有单开文件，并进 `ModelAndToolSelectionTest`
   （20 → 21 个方法）。它按设计工作。代价是四个缺口现在没有地方落——上限挡住的不只是"摊大饼"，
   也挡住了"补一条小用例"。

## 五、下一轮的门槛

- **替换前先给字符串归类**：配置键（跟着改）、指标名（不动）、表名（只在 schema 一处）。
  判据一句话：**这个常量是给部署的人看的，还是给面板/告警看的**。同一批替换里两类混着出现时，
  先 grep 常量名（`ARCHIVED`、`FAILURES` 是指标还是键），不要按前缀批量改。
- **改公开契约先写 ADR，票在同一提交里带 TDD 表**。这条已经不靠自觉：`check-ticket-cases.sh`
  加了第 4 步，**还没提交的新票**必须交代裁决在哪（`docs/adr/00xx` / `ADR-00xx` / `无需 ADR：<理由>`）
  并带「TDD 用例清单」，resolved 还要一行 `复核：`。历史 101 张没表的票按裁决不追。
  盲区记在脚本头部：**判据是"还没进 HEAD"，所以提交后它就不管了**——它管"我这张新票写没写"，
  不管"历史干不干净"。
- **整块搬 YAML / 改注解，单独看一遍"缩进之外的注释"**：注释不参与解析，错了不报错。
- **一句话的代价先说出来再照做**：用户给的形状不一定最优（列表 vs map 就是一例），
  指出代价是零成本的；照做之后再补，要改三个文件。
- **单模块跑测试带 `-am`**：不带就吃本地仓库里过期的依赖，`package Approvals does not exist`
  这类错与代码无关，白赔一轮。
