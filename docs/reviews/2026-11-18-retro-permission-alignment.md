### A · 替用户做架构决定（3 处，最贵）

三次都不是"实现写错"，是**在没人授权的位置上做了一个决定**：选一条执行路径（自研容器）、
把"一张票卡住"读成"整条线卡住"（整体回滚）、加一个没人要的功能（自检命令）。

第 2 条最刺眼：P17b/c blocked 是事实，我却顺手把 P17a 也回滚了，理由写成"等上游"。
用户原话是"**我没说容器化回滚啊**"。三张票的范围本来写在同一份 spec 里，
我却按目录回滚、不按件回滚——**回滚粒度和开票粒度必须是同一个**，否则一次卡的是一张，回滚的是一片。

第 1、3 条同一个判据：动手前问"这是不是已经有人做了 / 有没有人要我这么做"。

### B · 判据先于核实（1 处，上一轮踩过）

上一轮复盘 B 堆写的是"判据里出现'偏差 / 不一致'之前，先给 `文件:行`"。这一轮换了个场景又踩：
我拿"这样也说得通"当依据，断言 OpenClaw 的脚本要 argv，于是给脚本层留了一条 argv 通道。
用户问"这是你自己思考的，还是跟 OpenClaw 的设计对齐了"——一查，它只有字符串 `exec`。

代价不只是那条通道白写：**ADR-0002 的裁决跟着它一起错**，直到整包删除才纠正。
现在的硬规则：说"它这么做的"必须给配置项名或 `文件:行`；给不出就写成"我推的，等人判"。

### C · 承诺比代码走得远（5 处，这一轮的主症）

五处来源不同，形状完全一样：**票面 / 注释 / 配置说明在描述一个不存在的形状**。
它们全都不报错、不红、不影响运行，只会在下一个人照着做的时候骗他一次。

最典型的是第 5 条：票 06 `Status: resolved`，同一份文件里却写着"整张表未复核（票还没开始）"。
两个状态从开票并存到收票，没有任何东西会去核对它们。第 9 条更隐蔽——删掉 `Server.tools` 之后
类注释还留着"权限默认按 server 声明，可以按工具覆盖"，读者会以为加一段配置就能收紧。

**根因不是懒，是"改代码"和"改承诺"从来不是同一个动作**：`AGENTS.md` 写了 resolved 的门槛是
"表里没有 ❌"，但没人（也没有闸）会去查表里的用例名在仓库里存不存在。门禁查的是
`ToolPermission` 这类**删除词**，查不到"用例名"。

### D · 机械替换没打样本（1 处）

137 处 `**x**` → `<b>x</b>` 是脚本做的，四处单行 Javadoc 被打坏：`/** 每条都问。**它盖过…**`
被匹配成 `<b> 每条都问。</b>`——`/**` 的两个 `*` 与加粗开头的 `**` 相邻。
跨文件替换的正确姿势是先在一个文件上跑、读 diff、再铺开；这次是直接铺开、事后发现。

## 三、这一轮验证了哪些结构真的在拦人（3 条）

1. **删除词闸**（`verify.sh` 第 1 步，十个词）：它拦的不是漏删，是"删完还在注释/字符串里提"。
   二审又靠它抓到 `McpServerProperties` 那一处——**这一类闸比它原本的设计目标更有用**。
2. **测试文件数 / 方法数上限**：`ExecToolTest` 顶到 26 是它逼出来的"该拆了"信号；
   `McpToolTest` 曾经因为它被迫单开 `McpToolFilterTest`，上限抬到 26 之后又并回去。
   它既拦摊大饼，也会逼出错误的拆法——2026-11-18 抬过一次，代价是这两个数从此是"到顶"。
3. **两轴评审**：Spec 轴十条里五条是"文档承诺 ≠ 代码"，Standards 轴一条都看不见；
   反过来 Javadoc / GLOSSARY 那类问题 Spec 轴也不看。单跑一条轴，另一类会整批漏掉——
   这次两轴各报各的、不合并排名，才让"六条同源"这件事显出来。
