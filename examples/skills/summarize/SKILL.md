# 抽取式摘要

## 什么时候用

用户给了一份文本（文件路径或 `http(s)` 链接），要"几条要点""摘要""这段讲了什么"。
**不改写原文**是这一版的取舍：脚本拿不到凭据，调不了模型，所以它只能挑句子。
需要改写或提炼口径时，先摘要、再由你自己组织语言——但要把原文一起给出，别让用户以为那是原文。

## 怎么跑

脚本在技能目录的 `scripts/` 下，目录路径是工具返回的第一行（`Base directory for this skill:`）。
用 `Bash` 照抄这一条（`{baseDir}` 会被替换成那个目录）：

```
bash {baseDir}/scripts/run.sh sample.md
```

参数只有一个：要摘要的源。三种写法都行——

- 技能目录内的相对路径，例如 `sample.md`（按技能目录解析，不按当前工作目录）；
- 绝对路径；
- `http://` 或 `https://` 链接（会抓下来、去标签，再断句）。

## 期望的输出

第一行是计数，之后每句一行、以 `  - ` 开头，默认 5 句，例如：

```
摘要（5 句，摘自 5 句原文）：
  - 华东区自签收之日起 7 天内可无理由退货，商品需保持完好、配件齐全、不影响二次销售。
  - 华南区为 5 天，需提供原包装；
```

退出码 0 且 stdout 非空才算成功。**退出码非 0 时把 stderr 原样告诉用户**：
那通常是"文件不存在""链接抓不下来"这类环境问题，不是摘要算法的问题。

## 不要做的事

- 不要用你的话重写摘要、再声称是原文——用户要"逐字"时尤其不能。
- 不要自己编一个路径：拿不到 `Base directory` 就先用 `Skill` 工具把这份正文取回来。
- 不要在一条命令里塞多个文件（`a.md b.md`）：只会摘要第一个，其余被忽略。
