# 值班现场采集

## 这一步解决什么

"挂了没有"这种问题最怕凭印象答。这个脚本把**能现查的**一次查完，输出一份固定格式的简报：
时间、负载、三个端口的健康码、MCP 端口通不通。它不分析原因，原因由你看完简报再判断。

## 怎么跑

```
bash {baseDir}/scripts/collect.sh
```

不带参数时看默认那几个端口：

| 端口 | 是什么 |
| --- | --- |
| 8080 | 应用本体。actuator 不在这个端口，所以这里只能看出"端口在听"（`http=404`） |
| 9090 | 管理口（健康检查与指标都在这儿，`health=UP` 才是真的活着） |
| 8082 | 仓库自带的 Java MCP server（`examples/mcp`，要单独起） |

要换端口就写在后面：`bash {baseDir}/scripts/collect.sh 8080 8082`。

## 期望的输出

```
值班简报 2026-11-22 21:04:11 (+0800)
  主机：Darwin arm64，负载 2.31 2.10 1.98
  进程内没有权限看别的进程（沙箱），端口一律只测连通性
  127.0.0.1:8080  health=UP
  127.0.0.1:9090  health=UP
  127.0.0.1:8082  http=000（连不上）
  结论：上述 unreachable 的端口在这台机器上没有服务在听
```

退出码永远是 0（**"连不上"是结论的一部分，不是脚本失败**）。所以判据是简报里的
`health=` 与 `http=` 两列，不是退出码。

## 怎么读

- `health=UP`：那个端口的 `/actuator/health` 自己说还活着。
- `http=000`：curl 连不上（没有服务在听，或者被拒）。**它就是"没起来"**，不要念成"超时"。
- 负载三个数分别是 1 / 5 / 15 分钟均值；单看一个数说明不了问题。

## 不要做的事

- 不要用它重启服务：这一层只读，重启越界，要人来。
- 不要把 `http=000` 解释成"网络问题"——先看那个端口本来该不该有服务。
