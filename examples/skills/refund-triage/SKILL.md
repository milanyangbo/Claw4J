# 退货判定

## 这一步解决什么

政策里全是"几天内""哪一档""谁承担运费"，模型口算两件事最容易错：**天数边界**和**金额**。
这个脚本把这两件事做成确定性的：你只要把已核实的事实传进去，它给判定与依据。

**它不判断事实**。区域、签收后第几天、金额、是不是质量问题，都得你先从订单与对话里拿到——
拿不到就先问，不要替用户填一个。

## 怎么跑

脚本在技能目录的 `scripts/` 下，目录路径是技能工具返回的第一行（`Base directory for this skill:`）：

```
bash {baseDir}/scripts/refund_quote.sh --region east --days 8 --amount 74400
```

四个参数：

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| `--region` | `east` / `south` | **按收货地**，不按客户注册地（政策「跨区订单按哪一档算」） |
| `--days` | 整数 | 自**签收日**起的天数，不按付款日 |
| `--amount` | 元，可带小数 | 订单金额；只算货款，不含运费 |
| `--quality` | 开关 | 声明是质量问题时才加。不加表示"客户没说质量问题" |

## 期望的输出

```
退款判定（售后政策 2026 版）
  区域：east（无理由 7 天 / 质量问题 15 天）
  签收后：8 天
  结论：无理由窗口（7 天）已过；属于质量问题可走 15 天窗口，需区域售后主管审批
  可退货款：74400.00
  运费：质量问题我方承担；无理由退货由客户承担
  到账：验收通过后 3 个工作日原路退回，银行卡再 1-3 个工作日
  依据：after-sales.md 华东区 / 退款到账 / 退货、换货、保修三件事别混
```

退出码 0 且 stdout 非空才算成功。**退出码非 0 时把 stderr 原样告诉用户**（通常是参数写错）。

## 不要把脚本的结论改写成别的结论

脚本说"不可退"，回复里就不能出现"应该可以退"。要推翻它，只能改参数重跑——
比如用户补了"其实是质量问题"，那就加 `--quality` 再跑一次，而不是自己改口。

## 不要做的事

- 不要用它算成交额、订单数：它只认`金额 / 天数 / 区域`这三样。
- 不要拿 `--days 0` 代表"不知道签收日"。不知道就先问，0 天会被判成"刚签收"，那是另一个结论。
