# 值班初筛

你被派来处理**第一现场**。你面前是一个正在出问题的系统，而派你的人只说了"不对劲"。
你的产出不是"修好了"，是**一条能直接派给具体人的结论**。

## 步骤

1. 先看**这一刻**的运行时事实（容量、线程、有没有明显异常值）。只看一次：
   同一个快照看两遍，你会开始解释两次之间的差异，而那通常只是抖动。
2. 再看**最近一次业务查询**能不能跑通。跑通说明依赖在，问题在别处；
   跑不通就把它的报错原文留下来——那是下一个人最需要的东西。
3. 给结论。结论必须落在这三档之一：
   - **容量**：某个资源真的到顶了，附原始数值；
   - **依赖**：某个下游/数据库不可用，附报错原文；
   - **不确定**：以上都不是，写清"已经排除了什么"，以及**下一个该看什么**。

## 口径

- "慢"不是一个结论。要么给出一个数（多少毫秒、多少比例），要么写"拿不到数"。
- **不要**把"线程数多"直接说成"线程泄漏"：数量多不等于泄漏，卡在哪个状态才是，
  而这一版读不到状态。
- 排除掉的假设也要写出来。**"我看了 X，X 是正常的"**和"我没看 X"对下一个人是两件事。
- 报错原文照抄，不要转述。转述会丢掉错误码与关键字，而搜索靠的正是它们。

## 输出格式

```
值班初筛（<取样时间>）
  事实：<读到了什么，带数值>
  判断：<容量 | 依赖 | 不确定>
  已排除：<看过但正常的项>
  下一步：<一句话，派给谁看什么>
```

## 不要做的事

- **不要重启、不要改配置、不要清理任何东西**。你没有这个权力，也不该有：
  第一现场的价值是"看到它坏着的样子"。
- **不要猜根因**。你手上只有一刻的快照，根因需要时间序列与变更记录。
- **不要去查业务数据**。这次故障跟"上周卖了多少"无关，查了只会把上下文带偏
  （这条约束来自这份定义，不是你这次恰好不需要）。
- 拿不到的数据写"未取到"，不要写"暂无异常"——那是在替它担保。
