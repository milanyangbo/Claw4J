# 口径

这份文件是这个部署的统一口径，所有助手共用。它定的是**怎么描述一次统计**，不是具体指标：
指标名、表名、字段名跟着部署走，属于工具描述里的 schema，不在这里重复——在两处各写一遍，
改一处必漏一处，而漏掉的那处会让两个助手对同一个数给出两种说法。

## 一次口径至少要说清四件事

1. **取哪份数据**：表、接口、还是某个文件；
2. **统计什么**：求和、计数、去重计数、还是比率；
3. **排除了什么**：作废、测试数据、内部账号、重复行；
4. **覆盖哪一段**：起止时间，含不含两端。

四条里缺任何一条，报出来的数都不能直接拿去做决定。

## 时间

区间两端**默认都含**：说"从 A 到 B"就按 A、B 都算进去。要半开区间（含头不含尾）必须明写，
因为两种写法在边界那天差一整天。

相对时间（今天 / 昨天 / 本周 / 上月）按**会话里给的当前时间**算，不要用训练数据里的日期。
时区跟着会话时区；跨时区的数据要说明按哪个时区切的天。

## 金额与单位

金额取**明细行之和**，不取预先算好的汇总字段——两者都存在时，汇总字段的口径往往和明细对不上，
而取错了不会报错，只会少算或多算。

单位与币种写在数字后面。没写就是没确认，别让读者自己去猜是元还是万元。

## 维度编码

状态、区域、类别一律用**代码**，不用展示名。写展示名通常不报错、只返回 0 行，
这是自纠错最难发现的一类错误——模型会以为"这条数据不存在"，而其实是"写法不对"。

代码的取值以工具描述里的 schema 为准。

## 空结果

查不到分两种，回答时要说清是哪一种：

- **没有这个口径**：系统里就没有这个指标或这份数据，属于能力问题；
- **这个条件没命中**：条件本身成立，只是那段时间没有记录，属于数据问题，答"这段是 0"。

把后一种说成前一种，会让用户以为系统做不到；反过来，会让用户以为业务真的掉到零。

## 口径冲突与变更

人设正文、本文件、工具描述里的 schema 三处冲突时，**停下来说明冲突**，不要挑一个顺手的往下算。
口径有变更时写清日期与原因，只改一处来源——抄进正文的那种写法迟早会漏。
