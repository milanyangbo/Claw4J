# Model Streaming Chain Smoke Tests

This guide verifies the integrated browser -> `claw4j-api-gateway` -> `claw4j-orchestrator` model streaming path. Use it as the primary runtime smoke test for model output, Gateway Sentinel ingress protection, Spring AI DeepSeek primary calls, DashScope/Qwen fallback calls, Resilience4j failover, SSE resume headers, and cleanup.

## Prerequisites

- Local Nacos and Sentinel Dashboard are running from [Local Deployment](DEPLOYMENT.md).
- `claw4j-api-gateway` is reachable at `http://127.0.0.1:8080`.
- `claw4j-orchestrator` is registered in Nacos and reachable through Gateway Feign + LoadBalancer.
- DeepSeek and DashScope/Qwen credentials are available through official Spring AI configuration.

Get local provider keys before starting Orchestrator:

- DeepSeek: sign in to `https://platform.deepseek.com/`, open `API Keys`, create a key, and export it as `CLAW4J_DEEPSEEK_API_KEY`.
- DashScope/Qwen: sign in to Alibaba Cloud Model Studio at `https://bailian.console.aliyun.com/`, open the `API-KEY` page, create a key, and export it as `CLAW4J_DASHSCOPE_API_KEY`.
- Make sure both accounts have usable quota or billing enabled. Missing, disabled, or exhausted keys should fail the smoke test.

```bash
export CLAW4J_DEEPSEEK_API_KEY="replace-with-local-secret"
export CLAW4J_DASHSCOPE_API_KEY="replace-with-local-secret"
```

Do not put API keys in committed files. `application.yml` only keeps API keys and deployment-sensitive addresses as environment variables; local defaults such as model names, timeouts, Nacos group, and streaming budgets are written directly for readability. Override them with command-line Spring properties or Nacos Config only when an environment actually needs different values.

The runtime reads provider credentials from official Spring AI properties: `spring.ai.deepseek.*` and `spring.ai.dashscope.*`. Claw4J-owned governance remains under `claw4j.model.streaming.*`; model failure behavior uses official Resilience4j instance keys such as `resilience4j.circuitbreaker.instances.deepseek-primary-model.*` and `resilience4j.timelimiter.instances.deepseek-primary-model.*`.

This smoke test is not considered passed unless a request to the real Gateway URL streams real provider output. Contract tests can use fakes; this smoke test cannot.

## Start Services

Build the required modules:

```bash
mvn -q package -DskipTests -pl claw4j-api-gateway,claw4j-orchestrator -am
```

Start Orchestrator with provider credentials:

```bash
CLAW4J_DEEPSEEK_API_KEY="${CLAW4J_DEEPSEEK_API_KEY}" \
CLAW4J_DASHSCOPE_API_KEY="${CLAW4J_DASHSCOPE_API_KEY}" \
java -Duser.home="$PWD/target/runtime-home/orchestrator" \
  -jar claw4j-orchestrator/target/claw4j-orchestrator-0.0.1-SNAPSHOT.jar
```

Optional model overrides should use official Spring AI property names rather than Claw4J-specific aliases:

```bash
CLAW4J_DEEPSEEK_API_KEY="${CLAW4J_DEEPSEEK_API_KEY}" \
CLAW4J_DASHSCOPE_API_KEY="${CLAW4J_DASHSCOPE_API_KEY}" \
java -Duser.home="$PWD/target/runtime-home/orchestrator" \
  -jar claw4j-orchestrator/target/claw4j-orchestrator-0.0.1-SNAPSHOT.jar \
  --spring.ai.deepseek.chat.options.model=deepseek-reasoner \
  --spring.ai.dashscope.chat.options.model=qwen-plus
```

Start Gateway with Sentinel Dashboard logging:

```bash
java -Duser.home="$PWD/target/runtime-home/gateway" \
  -Dcsp.sentinel.log.dir="$PWD/target/sentinel-logs/gateway" \
  -jar claw4j-api-gateway/target/claw4j-api-gateway-0.0.1-SNAPSHOT.jar
```

## Browser Path

Open this Gateway URL in a browser:

```text
http://127.0.0.1:8080/ai/chat?query=hello
```

Expected result:

- The response is `text/event-stream`.
- Events come from the Gateway URL, not a direct Orchestrator URL.
- Browser-friendly context is generated by Gateway, so no custom headers are required.
- At least one `token` event contains real model text from DeepSeek.
- Event names can include `token`, `fallback-start`, `adaptation`, `failure`, and `complete`.

## Curl Path

Use the same browser-friendly entry from curl:

```bash
curl -N -sS 'http://127.0.0.1:8080/ai/chat?query=hello'
```

Use the formal Header-driven API when testing context propagation:

```bash
curl -N -sS 'http://127.0.0.1:8080/api/model/stream' \
  -H 'Content-Type: application/json' \
  -H 'X-Request-Id: smoke-stream-1' \
  -H 'X-Tenant-Id: smoke-tenant-a' \
  -H 'X-User-Id: smoke-user-a' \
  -H 'X-Idempotency-Key: smoke-stream-1' \
  -H 'X-Session-Id: smoke-session-a' \
  -d '{"query":"Explain what Claw4J does in one short paragraph."}'
```

Reconnect from a retained event position:

```bash
curl -N -sS 'http://127.0.0.1:8080/api/model/stream' \
  -H 'Content-Type: application/json' \
  -H 'X-Request-Id: smoke-stream-reconnect-1' \
  -H 'X-Tenant-Id: smoke-tenant-a' \
  -H 'X-User-Id: smoke-user-a' \
  -H 'X-Idempotency-Key: smoke-stream-reconnect-1' \
  -H 'X-Session-Id: smoke-session-a' \
  -H 'Last-Event-ID: 1' \
  -d '{"query":"Continue from the previous retained stream position."}'
```

Expected SSE shape:

```text
id: 1
event: token
data: {"eventName":"token",...}

event: complete
data: {"eventName":"complete",...}
```

## Gateway Sentinel Check

Gateway keeps only the official Sentinel starter and Dashboard transport configuration by default. Send Gateway model-stream traffic, then verify the protected resource appears in Sentinel Dashboard:

```bash
for i in 1 2 3; do
  curl -N -sS 'http://127.0.0.1:8080/api/model/stream' \
    -H 'Content-Type: application/json' \
    -H "X-Request-Id: smoke-rate-${i}" \
    -H 'X-Tenant-Id: smoke-tenant-a' \
    -H 'X-User-Id: smoke-user-a' \
    -H "X-Idempotency-Key: smoke-rate-${i}" \
    -H 'X-Session-Id: smoke-rate-session' \
    -d '{"query":"rate limit smoke"}'
done
```

Expected result:

- The requests still go through the real Gateway -> Orchestrator streaming chain.
- Sentinel Dashboard shows the Gateway application and protected resource `claw4j-gateway-ingress` after traffic reaches the endpoint.
- If you add a temporary flow rule in Sentinel Dashboard for `claw4j-gateway-ingress`, over-limit requests return the stable rate-limit outcome `CLAW4J-SENTINEL-429`, and Orchestrator is not invoked for blocked requests.

## Fallback Check

For a controlled local fallback check, reduce the primary timeout and restart Orchestrator:

```bash
CLAW4J_DEEPSEEK_API_KEY="${CLAW4J_DEEPSEEK_API_KEY}" \
CLAW4J_DASHSCOPE_API_KEY="${CLAW4J_DASHSCOPE_API_KEY}" \
java -Duser.home="$PWD/target/runtime-home/orchestrator" \
  -jar claw4j-orchestrator/target/claw4j-orchestrator-0.0.1-SNAPSHOT.jar \
  --resilience4j.timelimiter.instances.deepseek-primary-model.timeout-duration=1ms
```

Then call Gateway again:

```bash
curl -N -sS 'http://127.0.0.1:8080/ai/chat?query=Please%20answer%20briefly'
```

Expected result: the same Gateway-facing stream includes a `fallback-start` event with a primary timeout or circuit-open status, followed by Qwen fallback token events from the real DashScope provider.

For circuit checks, tune these official Resilience4j instance keys through command-line properties or Nacos Config and repeat the Gateway call pattern:

```yaml
resilience4j:
  circuitbreaker:
    instances:
      deepseek-primary-model:
        failure-rate-threshold: 50
        sliding-window-size: 4
        minimum-number-of-calls: 2
  timelimiter:
    instances:
      deepseek-primary-model:
        timeout-duration: 30s
```

## Pass Criteria

- `curl -N -sS 'http://127.0.0.1:8080/ai/chat?query=hello'` returns SSE from Gateway and includes real DeepSeek token output.
- The Header-driven Gateway API returns SSE from the same chain and rejects missing context before reaching Orchestrator.
- Gateway Sentinel Dashboard shows the protected `claw4j-gateway-ingress` resource after real Gateway traffic; optional Dashboard rules can verify `CLAW4J-SENTINEL-429`.
- The forced primary-timeout check emits `fallback-start` and then real Qwen token output through the same Gateway URL.
- No smoke step calls direct Orchestrator proof endpoints, standalone Sentinel proof endpoints, dynamic-config demo endpoints, deterministic provider mode, or simulated request fields.

## Cleanup

Stop services with `Ctrl+C`, then stop local containers from [Local Deployment](DEPLOYMENT.md).
