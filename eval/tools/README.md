# 工具检索评测（票 09）

回答一个问题：**同一句人话，索引的前 5 里有没有那个工具。**
不回答"模型拿到候选后选不选对"——那是 BFCL 那一层，要真模型与多轮，另一张票。

## 跑

```bash
# 起容器 + 真 embedding，一次约 40 秒（19 个工具、20 条题、5 档配置）
./mvnw -o -Peval -pl claw4j-eval -am test -Dtest=ToolRetrievalSnapshotTest

# 只验题面与算术（不调模型）：它在 clean verify 里，跟着门禁跑
./mvnw -o -pl claw4j-eval test -Dtest=ToolGoldTest
```

表打在 surefire 输出里：`claw4j-eval/target/surefire-reports/*-output.txt`。
`-Peval` 是必须的：`eval` 组默认被排除（它要容器与外部世界）。

## 列

| 列 | 意思 |
| --- | --- |
| `R@k` | 前 k 名里有 gold 工具的比例。**一句题只要有 gold 里任一工具在就算命中** |
| `MRR` | 第一个 gold 工具名次的倒数均值；没命中记 0 |
| 分类 | `base` 基座 / `business` 中文问中文 / `zh-en` 中文问英文描述 / `no-search` 不该给候选 |

`no-search` 那两道的判据是**零候选**：给了候选就算没中（"你好"收到五个工具就是噪声）。

## 2026-11-26 的基线（19 个工具、20 条题）

```
配置          分类        题数  R@1    R@3    R@5    MRR
regex         全部         20  0.150  0.400  0.500  0.289
lucene        全部         20  0.200  0.300  0.450  0.283
hybrid-1.0    全部         20  0.150  0.400  0.500  0.289
hybrid-0.5    全部         20  0.200  0.450  0.550  0.350
hybrid-0.0    全部         20  0.350  0.450  0.600  0.427
```

三条读法：

1. **`hybrid-1.0` 与 `regex` 逐字相同**——权重 1 真的等于纯关键字，那张"对照"是真对照
   （不是实现漏了参数）。
2. **纯向量（0.0）明显最好**：R@1 是 regex 的两倍多，`zh-en` 那档 R@1 0.60 / MRR 0.64
   （regex 是 0.20 / 0.29）。中文问英文描述这件事，词面匹配确实救不回来。
3. **默认 0.5 被关键字那一路拖回中间**：0.200 / 0.450 / 0.550。这不是"融合错了"，
   是关键字那一路在这个题库上贡献的多是噪声——降权或换描述，都得先有这张表。

**样本小**（20 条、19 个工具、评估上下文的人设筛掉了 MCP 与部分工具），所以这不是"结论"，
是**基线**：往后每改一次检索（描述本地化、索引参数、权重），跑同一份题对比。
