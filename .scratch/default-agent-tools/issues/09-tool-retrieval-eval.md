# 票 09：工具检索的评测集——Recall@k 与一份能对照的基线

**Status:** open

## 由来

票 07 收票时只能判"通了"：三路索引都在跑、数据落对表、指标有值。**判不了"好多少"**——
真机那一次问「examples 目录下有哪些 .md 文件」，`Glob` 在向量那一路排第 7，
但"第 7 是这次运气不好还是典型情况"没有任何数据回答。

用户 2026-11-26 点名：用 `tool-retrieval-benchmark`。

## 裁决

无需 ADR：这是评测设施，不改任何线上行为。

两处借它：

- **题面形状**：`tool-retrieval-benchmark`（mangopy，ACL 2025，Apache-2.0）是专为"工具检索"出的
  数据集——每题给出用户问法 + 正确工具，干扰项是**同域相近工具**（不是随便凑的噪声）。我们的题
  照这个形状出，不自创。
- **产物形状**：`rag-retrieval-eval`（本仓 16 张票那套）已经定下了"配置网格 + 逐题失败分析"的输出，
  工具这边照抄，不另造一份报告格式。

**不引它的代码**：它是数据集与实验脚本，不是能挂进来的库；我们的管线（YAML 金标 + Recall@k）
已经在 `claw4j-eval` 里跑了一年。缺的是题，不是指标实现。

## 只评一层：索引

分清楚两件事，本票只做第一件：

| | 问什么 | 怎么测 | 本票 |
| --- | --- | --- | --- |
| **检索层** | 问一句，候选里有没有对的工具 | Recall@k / MRR，确定性，不调模型 | ✅ |
| 选择层 | 模型拿到候选后选不选对、参数对不对 | BFCL 那套（AST 比对 + irrelevance detection） | ❌ 见缺口 |

不做选择层的理由：检索层现在是主要失效点（票 05/07 的证据），而选择层要真模型 + 多轮 + 参数
比对，是另一个量级的设施。**先修"翻不到"，再谈"选了没用上"。**

## 金标

`claw4j-eval/src/test/resources/tool-gold.yaml`，形状照 `RetrievalGold` 那套（严格键校验：
认不得的键当场报错，不让打错一个字母变成"这条题没生效"）：

```yaml
- id: glob-find-md
  question: examples 目录下有哪些 .md 文件？     # 用户真的会这么说，不点工具名
  gold_tools: [Glob]
- id: web-fetch-explain
  question: 这个地址写了什么 https://example.com
  gold_tools: [WebFetch]
```

至少 20 条，四类各占一档（**分类不是为了好看，是为了失败时知道该改哪边**）：

| 类 | 例子 | 失败说明什么 |
| --- | --- | --- |
| 基座（现在会进 pinned） | 「examples 下有哪些 .md」→ `Glob` | 会常驻，检索里掉分不影响线上，但它是"索引能不能工作"的底线 |
| 业务 | 「上周华东成交额」→ `querySales` | 中文问中文描述，这一档掉分说明索引本身坏了 |
| 中文问英文描述 | 「这个地址写了什么」→ `WebFetch` | 票 04 的同义词桥与票 07 的向量各自值多少分 |
| 不该检索 | 「你好」「谢谢」→ 空 | 检索器不该给出任何候选——给出就是噪声 |

## 指标与判据

- `Recall@1 / @3 / @5` + `MRR`，按上面四类分开报，再报总。
- 一句题只要 gold 里**任一**工具出现在前 k 就算命中；多 gold 的题（"看网页并总结"可能）
  记 partial 在报告里，不进主指标。
- **不设通过阈值**。第一版的任务是建立基线，设阈值等于把当前噪声固化成标准；
  阈值等有两轮数据、知道方差之后再议。
- 跑法：`claw4j-eval` 里一条用例，对同一份题跑五种配置——`regex`、`lucene`、
  `hybrid{0.0, 0.5, 1.0}`——输出一张对照表 + 每类失败题清单。

## TDD 用例清单

`claw4j-eval` 现在 3 个文件 / 最大 11 个方法，空间够，不碰别处。

| 判什么行为 | 用例 | 先红的样子 |
| --- | --- | --- |
| 金标能加载且键写错当场报 | `claw4j-eval` 里 `ToolGoldTest#rejectsUnknownKeys` | 打错的键被静默忽略时，题数对不上，断言红 |
| Recall@k 的算术对 | `ToolGoldTest#recallCountsHitWithinK` | 把"命中"算成"第 1 名"时，@3 与 @1 同值，断言红 |
| 五种配置真的给出不同分数 | `ToolGoldTest#configurationsDifferOnTheSameSet` | 配置没透传（每次都是 regex）时，五行数字完全一样，断言红 |

第三条是这票的自检：**一张所有配置都同分的对照表，就是"配置没生效"的样子**，与
"三种索引一样好"分不开。

## 缺口（本票不做）

- **选择层**：模型拿到候选后选不选对（BFCL 那套）。要真模型、要参数级比对，另一张票。
- **adoption**：检索回来的工具到底有没有被调用（票 08 缺口同一条）。
- **中文化的收益要靠它量**：票 11 改的是描述，前后对比就落在这张表上——所以 11 排在 09 之后。
- **题从哪来**：第一版用真实失败问法（票 05 的 6 条 + 票 07 那条）+ 各工具文档里的一句话；
  不追求覆盖面，追求"每条都能指到一个曾经出事的场景"。
