# 34 通用工具按用户原话点亮，B2-4 拆成链路与行为两半

**Status:** in_progress（2026-11-27 22:35 开票）

**Depends on:** 29（准入闸）、33（控制类回常驻 / ADR-0043）

## 为什么

票 33 收口时留了两条红：B2-4（网页抓取）与 B7 不点名那一半。今天补了三个探针，把"哪一步断的"钉死了。

**探针一（用户 `wf1`，点名工具）**：`请用 WebFetch 抓一下 https://example.com…`

```
检索次数 0，工具调用 0
模型回答：「我这边没有 WebFetch 这个工具，抓不了网页。」
```

**探针二（用户 `wf2`，只要求"先看看有没有"）**：同一句业务，多一句"先看看你手上有没有能打开网页的工具"

```
工具检索 hybrid：query=打开网页 抓取 URL 内容 fetch web page 关键字=[WebFetch, Read, …]
WebFetch 调用 1 次 → 抓回 example.com 真正文（"This domain is for use in documentation examples…"）
```

**探针三（票 33 的 `q34`）**：`AskUserQuestionTool` 常驻之后，点名它就能用（问题登记 → answer 204 → 回「预发」）。

三条合起来说明：

1. **链路没问题**。装配、闸、检索、执行、内容注入全通，`WebFetch` 抓回来的是真内容。
2. **断在"模型不主动去搜"**。而且不是"搜错了"，是**一次都不搜**——连用户点名它，它都断言"没有这个工具"。
3. 模型只在这两种情形下动手：**工具看得见**（`AskUserQuestionTool` / `TodoWrite` 常驻后都能用），
   或者**它确信自己缺这个能力**（A1 查成交额会去搜 `querySales`）。它一旦有"我上不了网"的先验，
   这条先验就压过"目录里还有别的工具"那句话。

所以票 32 那条思路（把"先去找一遍"写进提示词）注定无效——模型根本没有"去搜"这个动作，
提示词叫它去搜也没用。票 33 的 BFCL 数据也印证：那句话没换来行为，还赔了 7.5 点 `irrelevance`。

## 判断：改代码（按用户原话点亮），不改提示词、不常驻

`WebFetch` 常驻能解决 B2-4，但票 28 量到它是"对任何话题都能凑合"的第二名（240 题里 6 条误调），
而且它**出网**——常驻等于把一条出网通道默认摆到眼前。不值得为一个用例付这个价。

真正缺的是一条**不依赖模型自觉**的通路：用户在话里提到了这类事，就把对应的通用工具直接放进这一轮清单。
配置里本来就有这个信息——`rules` 的 `pattern → tools` 就是"用户这么说，就该给这个工具"，现在它只在
**检索**里生效（而且判据是模型改写的检索词）；把它接成 `prepare()` 的第四个补位来源即可：

```
selected = toolSearchTool
         + pinned            （配置点名的常驻）
         + injected          （上游 advisor 注入的，票 32）
         + matched           （用户原话命中 rules 里 gate: true 的 pattern）← 新增
         + referenced        （历史里检索到过的）
```

判据用**用户原话**，不是模型的检索词：用户说"打开这个网页"，`WebFetch` 就在清单里，
不需要模型先想到"我该去搜一个抓网页的工具"。

B7 不点名那一半不在此列：`AskUserQuestionTool` 现在常驻（看得见），它不调是它认为
"写两个选项在正文里也一样"——那是模型选择，属 ADR-0042 那条会话策略，不在本票改。

## 做什么

1. `DisclosureToolCallingAdvisor`：构造时把 `properties.rules()` 里 `gate: true` 的编译成闸
   （正则错在构造时抛，与 `GatedToolIndex` 同一个态度）；`prepare()` 里取**最后一条用户消息**的正文
   匹配，命中就把该规则的工具并进清单。只匹配 `gate: true` 的：没标 gate 的规则本来就由
   `RuleToolIndex` 在检索里置顶，往清单里塞会变成"绕过检索"。
2. `README-capability-tests.md` B2-4：拆成两半，与 B7 同一个写法——
   **链路半**用"先看看你手上有没有能打开网页的工具"（不是点名工具，是点名"去找"这个动作），
   判据是日志里有一次 `工具检索 hybrid` 且 `WebFetch +1`；
   **行为半**仍用原来的"不点名"题面，但记为观察：模型不主动搜是模型的事，红的时候先看链路半。
3. 实测：B2-4 两半、B7 两半、BFCL 两档（看 `irrelevance` 有没有因为多了个补位来源而掉）。

## 验收

- 单测：用户原话提到网页 → `WebFetch` 进清单；没提 → 不进（`InjectedToolsAndSearchTest` 加一条，
  它现在 4 条，未到 26）。
- 实测 B2-4 不点名：清单里有 `WebFetch`（日志/审计可查），模型要么用了、要么明确说不用——
  不再是"我没有这个工具"这种断言。
- BFCL `--with-prompt` 的 `irrelevance` 不低于回退后的 84.17%（BFCL 题面里没有网址/网页这类词，
  按道理不受影响；掉了说明匹配写宽了）。
