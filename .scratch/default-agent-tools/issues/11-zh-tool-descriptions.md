# 票 11：工具描述本地化——运行时自动译成中文，开关可配

**Status:** resolved

> 依赖票 09：改完之后"好了多少"只有那张对照表能回答。09 没落地时本票只能判"通了"。
>
> **2026-11-26 修正**：作用域从"模型 + 索引"收窄到"只喂向量索引"（关键字那一路被它拖低）。
> 收窄后复测，向量侧没有可测变化，**默认关、机制保留**。见文末第二版实跑。

## 由来

票 05 的根因第 2 条：检索是词面匹配，而框架自带的工具描述**只有英文**。票 04 给网页那一族搭了
同义词桥（`页/链接/网址/浏览 → fetch,url`），桥是逐个搭的、描述一改就静默失效。

票 10 把基座工具常驻之后，`Glob`/`Read` 这类不再靠检索——但**长尾还在**：MCP、技能、子 Agent、
业务工具的描述大多是英文，中文问法照样撞不上。用户 2026-11-26 的裁决是：不要人写映射表，
`zh-description` 配"要不要转"，**代码里运行时自动转**，并可指定哪些工具转。

## 裁决

`docs/adr/0021-explicitly-not-doing.md`（「**领先 2**：工具可见性」）再修订一条：
**喂给向量索引的工具描述可运行时本地化**，开关与作用范围可配；本地化只改入库文本，
不改工具名、不改权限、不改计量口径、**不改模型看到的清单**（2026-11-26 收窄，见文末修正）。

## 配置

```yaml
claw4j:
  advisor:
    tool-search:
      zh-description:
        # 要不要把英文的工具描述译成中文喂给向量索引。默认关：每次部署会花掉若干次 utility 调用，
        # 而默认 index=regex 根本用不上它。
        enabled: false
        # 只译这些工具（名字来自 @Tool(name=…)）。空 = 自动判定：描述里汉字少于 6 个才译。
        # 名字写错不报错也不翻——与 pinned 不同，它没有"必须有"的语义。
        tools: []
```

**为什么要自动判定**：绝大多数工具的描述是英文，逐个人工登记就是又一张会漂的映射表。判据简单到
不需要配置——`description` 里的 CJK 字符少于 6 个，就当成"没有中文"。已经中文化的描述（CJK ≥ 6）
不再翻，免得把"中文 + 英文"再译一遍。

**`zh-description-tools` 的作用是收窄，不是开关**：非空时只在名单里挑"确实没有中文"的那些。
它存在的理由是钱——工具集大了以后，一次部署全量译一遍是几十次调用。

## 译成什么样

```
<中文一句>
<原文>
```

保留原文：向量检索要的是语义，但描述里有参数名、路径语义这类译不准的东西，删掉原文等于把
不确定性交给一次模型调用。

**没有 token 代价**（修正后）：这一份只进向量库，不进模型的清单，所以不占每轮上下文。
代价变成 `indexTools` 时的那几次 utility 调用（只在工具集变化时发生）。

翻的规矩写死在提示词里（不开放配置）：一句简体中文、保留工具名/参数名/代码标识符原样、
不加解释、不换行、只输出译文。

## 落在哪

`ToolSearch#index` 建索引时，**只包在向量那一路外面**（`TranslatedVectorIndex`）：

```java
case HYBRID -> HybridToolIndex.of(categories, new ChineseToolIndex(),
        new TranslatedVectorIndex(new VectorToolIndex(store), translator), weight);
```

为什么不是包在 `collectToolCallbacks` 出口（最初的设计）：那样模型与索引拿同一份中文，2026-11-26
的对照里关键字那一路从 0.15 掉到 0.10——描述变长、中文二元组碰撞变多。既然收益与代价分在两条路上，
就让两条路读不同的文本。位置选在向量索引外面一层：`index=vector` 与 `hybrid` 两档自动都覆盖，
`HybridToolIndex` 不用知道这件事。

翻译器本身：`ToolDescriptionTranslator`，拿 `ChatModel`（`roles.utility`，票 F7 那条链）与一个
进程内缓存 `ConcurrentHashMap<toolName, Entry(sha256(原文), 中文)>`——原文变了就重译。

**不落表**：重启之后重译一遍（几十次小调用、每次几十 token）。V9 留作缺口——等它成为成本问题，
或工具有几百个时再说。少一次 schema 变更，这一版就能早一天有数。

**失败口径**：译不出来就用原文 + 一个工具一条 WARN，不抛、不启动失败。与 `claw4j.rag.enabled`
那条相反，理由要写在代码注释里：中文化是增强，缺了只是命中率低一点；而启动失败会把整个服务挡在门外。

## 首轮延迟

译是懒的（第一次拿到这份清单时），30 个工具串行 ≈ 几秒，所以**并发译**：一个工具一次调用、
互不依赖，失败各自退原文。译完进缓存，后续轮次零调用。预热（启动后后台译）不做，见缺口。

## 实跑：同一份题、开与关各一遍（2026-11-26，19 工具 / 20 题）

### 第一版（两翼都读中文）——已作废

下面的数字是"模型与索引都看中文"那一版。**"向量受益"这一条没有复现**，留在票面是为了说明
为什么改设计，不要引用。

```
配置         分类       R@1 关 → 开      R@5 关 → 开      MRR 关 → 开
regex        全部      0.150 → 0.100    0.500 → 0.600    0.289 → 0.255
hybrid-0.5   全部      0.200 → 0.200    0.550 → 0.650    0.350 → 0.389
hybrid-0.0   全部      0.350 → 0.450    0.600 → 0.600    0.427 → 0.504

hybrid-0.0   zh-en     0.600 → 0.800    0.800 → 0.800    0.640 → 0.800
hybrid-0.5   zh-en     0.200 → 0.400    0.600 → 0.800    0.290 → 0.600
```

**向量那一路明显受益**（`zh-en` 档 R@1 0.60 → 0.80、MRR 0.64 → 0.80）：中文描述与中文问法在
同一个语义空间里，这正是中文化想买的东西。

**关键字那一路反而略降**（regex 全部 R@1 0.15 → 0.10，business 檔 R@1 0.11 → 0.00）：描述变长了，
二元组可碰撞的字也变多，"提到某个词的无关工具"更容易挤进前排。这一条与直觉相反，得记下来——
**中文化的收益要配向量那一路，配纯关键字是负的**。

样本只有 20 条、19 个工具，方向可信、数值不可引；重跑命令在 `eval/tools/README.md`。

### 第二版（只喂向量）——现状

```
配置         全部 R@1 关 → 开    全部 MRR 关 → 开    zh-en R@1 关 → 开
regex        0.150 → 0.150      0.289 → 0.289      0.200 → 0.200
hybrid-0.5   0.200 → 0.200      0.350 → 0.342      0.200 → 0.200
hybrid-0.0   0.350 → 0.350      0.433 → 0.431      0.600 → 0.600
```

**关键字那一路不再降**（0.15 保住）——收窄的目的达到。但**向量那一路也没有变化**：
五道 `zh-en` 题逐格相同。向量模型本身跨语言，中文 query 对英文描述早就能命中，中文化在
这一档上的边际收益是零。第一版那两个数从哪来，这次复现不出来，**不编原因**。

结论：机制保留、默认关。它现在既没有收益也没有害处；要判值不值，先把 `zh-en` 那一档加厚。

## 落地时与票面不同的两处（据实改）

1. **配置是嵌套的两项**，不是平铺的三个：`zh-description.enabled` + `zh-description.tools`。
   `ToolSearchProperties` 已经 8 个分量，再平铺两条就是 10 个。
2. **`zh-description-tools` 的语义是"允许翻的范围"**：非空时只在这个范围里挑"描述没中文"的那些；
   已有中文的一律不动（名单里有它也不翻——把中文再译一遍只会更长）。

## 缺口（本票不做）

- **子链不翻**：`SubagentAutoConfiguration` 收集工具时传的是 `NONE`。它拿到的是父清单里那批业务
  工具（描述本来就是中文），先不付这份钱。真出现"子 Agent 找不到工具"再开。
- **落表缓存**（V9）：重启重译。等工具上百个、或 utility 调用成为可感成本时再开。
- **批量翻译**：一次请求译多个工具能降调用次数，但要处理模型输出格式的失败路径。先一次一个，
  简单、可测、失败隔离。
- **译得准不准**：一次样本看不出来。上面那张表只回答"命中率变没变"，回答不了"意思对不对"——
  后者要么人工抽检，要么等题面里带参数约束的题。
- **反向**（中文描述译成英文）：同样的机制，等真有中文描述的工具再说，现在没有。
