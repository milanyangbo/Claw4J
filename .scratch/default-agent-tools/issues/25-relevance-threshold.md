# 票 25：给检索一个像样的相关性下限——没有够格的候选就返回空

**Status:** open（待批：会动检索，可能掉召回）
**裁决来源：** 用户 2026-11-26「核心点不应该是大模型乱调用了工具吗（假设是严肃问题，也不能乱调用工具啊）」
「toolSearch 总归无法达到绝对精准，就跟 rag 一样」。
**no ADR needed**（沿用 ADR-0021 的"先检索后调用"，只把两翼的门槛从"没有"变成"可配的有"）。

## 问题：模型永远有 5 个候选可凑

"模型乱调工具"在我们这一侧只有一个成因：**它手上总有东西**。检索层现在两翼的门槛形同虚设：

| 翼 | 门槛 | 出处 | 后果 |
| --- | --- | --- | --- |
| 向量 | `0.2`（`private static final double DEFAULT_SIMILARITY_THRESHOLD`） | 框架写死，**外部改不了** | 稠密向量的余弦相似度普遍偏高（无关文本常在 0.3 以上）。**这是这类模型的常识，本项目没量过**——所以本节第 1 步就是去量 |
| Lucene | `0.25` | `Lucene.DEFAULT_MIN_SCORE`，可配 | 中文短 query 词面撞不上时返回空，这一翼其实正常 |

合起来：关键字翼空了，向量翼照样给 5 条 → 融合后永远 5 个候选 → 模型要"硬凑"时，永远凑得出来。
这就是 BFCL 那 55 条错误（给 `math.sum` 去解二次方程）在真实链路上的对应物，只不过线上是
"从 5 个不相干的工具里挑一个最像的"，而不是"用唯一的工具硬做"。

这与票 22 不冲突，两个判据不同：

- 票 22 删掉的是**"这句话有没有意义"**——意图判定，`ToolIndex` 不该回答。
- 本票说的是**"这批候选够不够格"**——检索质量，正是 `ToolIndex` 该回答的，和 RAG 侧
  `R@5` 配相似度阈值是同一件事。

## 先量再改：阈值抬多少，召回掉多少

现在没有"分数分布"这一层数据，直接拍一个 0.5 就是在赌。做法（用现有 `eval/tools/retrieval`，
不新建评测）：

1. 临时把每轮的 `(qid, tool, score)` 打出来，跑一遍 `gold.yaml` 那 50 题 → 拿到"该命中的工具"
   的分数分布。
2. 扫描若干个阈值（0.2 / 0.3 / 0.35 / 0.4 / 0.45 / 0.5），每档算 `R@5` 与"平均候选数"。
3. 选**保住 `R@5 ≥ 0.80`（现行绝对门）的最高一档**。这条判据是单向安全的：抬高门槛只可能让
   候选变少，不可能让模型更容易凑。

已知代价，先说在前面：

- **召回一定会掉一些**。掉多少不知道，所以先量。若 0.4 就把 `R@5` 从 0.880 打到 0.76，那这条路
  在现有阈值机制下走不通，得回头改融合策略（按分数而不是纯 RRF），那是另一张票。
- **"不该命中的分数分布"拿不到**：票 22 把 `no-search` 那 10 题删了，gold 里没有反例。
  所以本票只能做"保召回"这一侧，**证明不了"阈值能挡住乱调"**——那一侧只能在模型侧量（BFCL）。
  这一点必须写在报告里，不能拿"候选数变少"冒充"乱调变少"。

## 怎么落地（如果要改）

框架的 `VectorToolIndex` 把阈值写死了，只能自己接一层：

- 新增 `ThresholdedVectorIndex implements ToolIndex`：自己 `vectorStore.similaritySearch(SearchRequest)`
  并带上配置的阈值，其余委托给框架那份（或直接照它 20 行实现写一遍）。
- 配置：`claw4j.advisor.tool-search.vector.similarity-threshold`，缺省 `0.2`（与框架一致，
  换实现不换行为）。
- 空候选必须能一路走到模型：`DisclosureToolCallingAdvisor` 拿到空 `ToolSearchResponse` 时的行为
  要有一条用例守着（票 22 之后没人测过这条路）。

| 判什么行为 | 用例 | 先红的样子 |
| --- | --- | --- |
| 阈值以下的候选不出现 | `ThresholdedVectorIndexTest`（新） | 现在框架那版 0.2 恒过，断言 0.5 门槛下空结果必红 |
| 空候选不炸、原样交给模型 | `ModelAndToolSelectionTest` 新增一条：索引返回空时这一轮没有工具可用 | 搜了一遍没有对应用例（该文件里三处 `isEmpty()` 都是别的意思），空列表走到 advisor 现在只是我读代码推的 |
| 缺省行为不变（0.2 = 框架那版） | 装配断言：不配该项时与改造前逐条等价 | 改实现时最容易顺手把缺省改高，那等于偷偷改了所有部署 |

## 缺口

- **这条不改 BFCL 的 irrelevance 分数**：BFCL 是裸模型、单工具，不经过我们的检索。要让那个数
  ≥90，只有换模型/换调用形态（票 23 已量：FC 76.25% vs prompt 88.75%）。
- **阈值是全局的**：不同 embedding 模型的相似度分布不同，写死一个数换模型就得重扫。
  要不要按模型名给缺省，等有了第二份数据再说。
- **RRF 融合没有分数量纲**：两翼各自的门槛是唯一的分数控制点；若要把"融合后整体太弱就返回空"
  也做掉，得改融合算法，不在本票。
