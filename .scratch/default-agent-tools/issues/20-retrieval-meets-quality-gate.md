## 四处改动，每一处都能单独指到失效点

1. **评测里打开中文化**（`zh-description.enabled`）。
   关着时向量读英文描述，中文问法只能靠 embedding 硬扛。打开后 `hybrid-0.0` 的 `R@5` 0.640 → 0.720。
   这本来就是票 11 的架构决定（译文只喂向量那一路），只是默认一直关着，评测也就没吃到。

2. **译文带上中文口语说法**（`ToolDescriptionTranslator.ask` 的提示词）。
   从「只直译」改成「译完再补 5–8 个用户口语说法，含委婉、不点名、只描述处境的讲法」。
   0.720 → **0.800**。这一步是关键：`KillShell` 的描述是「终止运行中的命令」，
   而用户说的是「跑太久了，不用等了，结束它」——直译文本里一个重合词都没有。
   `R@3` 也从 0.680 涨到 0.740。

3. **寒暄过滤**（`ChineseToolIndex.chitchatOnly`）。
   整句只由寒暄词拼成时返回 `NEVER_MATCH`。零候选率 0.500 → **1.000**。
   **只增不减**：命中才过滤，没命中走原路，所以不会让任何正常 query 变差。
   没用「短句 + 无动词就判闲聊」那种更通用的规则——实测它会误杀
   「那个进程打印了什么」「还有什么事挂着没人管」，而那两句正是检索该处理的。

4. **`intent` 描述去掉「每天九点提醒我」那个例子**。
   它原本为了指引模型去用 `schedule_task`，副作用是把这个说法拉进了自己的向量附近，
   于是「一到早上九点就叫我一声」被 `intent` 抢走。改成「按时间、按日程的定时任务不归这里」。

## 顺带修的两个静默失效

- **`PROMPT_VERSION` 进 hash**：译文表按 `(tool_name, source_hash)` 判新鲜，只对描述取 hash 的话，
  改了提示词仍会读到旧译文。评测每次都是新库所以看不出来，生产里就是「改了没生效」。现在改提示词要 +1。
- **生产默认 `index: regex` → `hybrid-0.0`**：`application.yml` 的注释原本写着「换默认值要单独量一次」，
  这次就是那次量（0.360 vs 0.800）。代价与回退方法都写在注释里：要 pgvector 与 embedding key，
  建不出向量库时启动失败（不降级）；要回退就改回 `regex` 并把 `zh-description` 关掉。

## 未做到的：选择层 `irrelevance`

BFCL 的 `irrelevance` 还是 77.08%（线是 90%）。**这一层我没有动**，理由是：

- 它判的是**模型的决策**（该不该调工具），不是我们的索引或代码。题库、prompt、判据都是 BFCL 的。
- 想靠给 BFCL 的请求加一句「不相关就别调」来拉高分数，**是操纵评测条件**：官方榜不是这个条件，
  分数会变得不可比。等价于把尺子改短，票 19 刚否掉过这种做法。
- 能真提的是换更强的模型，或改我们自己的 system prompt——两者都得单独量，不是这张票顺手能定的。

这一档仍是缺口，记在票 17 与本票的「未做到」里。
