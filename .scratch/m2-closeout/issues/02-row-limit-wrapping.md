# 02: 行上限包装不把合法 SQL 变成语法错误

**What to build:** 模型写的 SQL 以行注释结尾（`-- 只看华东`）时，行上限那道包装不能把
`) as claw4j_limited limit N` 拼进注释里。修法是**包成子查询之前先保证原句末尾有换行**——
不改语义、不剥注释、也不需要认识方言。

现在这种语句会在数据库里报语法错误，而模型拿到的是一条**与被问的问题无关**的报错，
自纠错于是朝错误方向猜。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**Demo:** 问一句会让模型写出带行注释的 SQL 的问题，能拿到数；把补换行那行删掉，同一条测试变红。

- [ ] 以行注释结尾的合法查询，经包装后在真库执行成功并返回行（断言落在执行结果，不是字符串形状）
- [ ] 原句末尾已有分号、已有换行、以块注释结尾三种写法都不受影响
- [ ] 包装形态仍是"子查询 + 外层 limit"：内部自带的 `order by` / `limit` 不被改坏
- [ ] 只读约束在包装之后仍然有效：写语句不会因为包装这一步通过校验
- [ ] 多取一行（区分"刚好 N 行"与"被截断"）的语义保持
- [ ] 变异：删掉补换行那一行 → 第 1 条变红

**落点:** `SalesSqlGuard.withRowLimit`；测试加进 `SalesQueryTest`，不新增文件。

**注意:** 执行的是原句（ADR-0005 已定）。剥注释会悄悄改掉模型写的文本条件，所以不剥。

**不要做:** 猜注释边界；按方言分别处理；把校验用的"去噪"结果拿去执行。
