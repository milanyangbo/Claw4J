# 10: 种子数据会随迁移日期漂，判据数字不稳定

**What to build:** 让"上周 / 本周 / 三周前"那组期望数字在任何时候都成立——要么一条命令能重灌种子，
要么让判据自己算。现在是"库放一周，数字就换一组"。

**Blocked by:** 无。

**Type:** bug（测试资产）

**Status:** ready-for-agent

**Demo:** 一周后重跑 `docs/capability-tests.md` §1 那三条时间窗，仍然是对的数字；或者文档里那三条
改成"先跑 `<命令>` 重灌种子，再对照"。

## 现场

`V2__business_seed.sql` 的日期是**相对迁移那一刻的本周一**算的：

```sql
(date_trunc('week', current_date) + (seed.day_offset * interval '1 day'))::date
```

Flyway 只跑一次，于是这行只在迁移当天成立。这份库是 2026-11-09 那周迁移的，到 11-16 再测：

| 问句 | 文档期望 | 实测 |
| --- | --- | --- |
| 上周各区成交额 | 128400 / 31500 / 26000 | 华东 **99999**、其余两区 **0** |
| 本周华东 | 99999 | 落到"上周"窗口里去了 |

我差点把"模型算错了"写进报告——查库才看出是数据漂了：
`select region_code, order_date, status, sum(amount) …` 显示所有行都锚在 11-09 那一周。

## 为什么这是测试资产的问题，不是产品问题

模型算得没错（它按当前日期切窗口，切得对）。错的是"期望值写死成 SQL 结果"，而 SQL 结果依赖
插入时刻。同一条判据在下一次迁移周之前都"看起来正常"，之后全红——**而这与代码改坏无法区分**。

## 两个方向

| 方向 | 做法 | 代价 |
| --- | --- | --- |
| A（小） | 加 `scripts/reset-demo-data.sh`：清 `business.*` 四张表 → 重跑 `V2__business_seed.sql`；`docs/capability-tests.md` §0 与 §1 开头各加一句"先跑它" | 依赖 `docker exec psql`，得处理容器名 |
| B（正） | 判据不写死数字，改成"用 SQL 现算一遍期望值再比对"（`eval.sh` 那类），或把种子改成固定绝对日期 + 查询也锚固定周 | 要改一批判据的写法；绝对日期又会在别的方面过期 |

我倾向 **A** 先做（10 行脚本 + 两句话），B 留给"判据要进自动化"那天。

## 验收判据

- 清库 → 跑脚本 → `select … group by` 得到的数字与文档期望逐字相同；
- 脚本重复执行幂等（第二次跑不报错、数字不变）；
- 文档 §0 写明"每天第一次跑验收前先执行它"。
