# 11: 验收文档里三处判据自己跟自己打架

**What to build:** 把 `docs/capability-tests.md` 里三处"照着做就判不出来"的地方改对。
只改文字，不动代码。

**Blocked by:** 票 10（§1 的时间窗数字要先能重灌种子才稳定）。

**Type:** docs

**Status:** ready-for-agent

**Demo:** 照 §19 做一次摘要，拿到的是能逐字对上原文的句子；照 §4 做时不因为"没配人设"而误判成失败。

## 三处

### 1. §19 摘要：要求互斥

现在写：

> `t '用 summarize 摘要一下 sample.md，三句以内'` → 通过标准：**原文句子（不是改写）**

但脚本默认输出 5 句，"三句以内"必然要模型压句——实测它把 5 句压成 3 句，第 3 句是合并改写
（"华南区为 5 天且需提供原包装，其余条件与华东一致"），于是"逐字"这条判据**永远不可能满足**。

改成：`t '用 summarize 处理 sample.md，把工具返回的原文原样贴给我，不要总结'` → 判据保持逐字。
实测这样问，输出与 `sample.md` 逐字相同（`华南区为 5 天，需提供原包装；`）。

### 2. §4 Skill：少写了一个前提

判据是"按 weekly-sales 的口径出数，三区都对"，但**口径不在 Skill 里**，在 persona 的
`glossary`（`examples/agents/glossary/metrics.md`）。没配 `claw4j.agent.directory` 时，
模型会按 SKILL.md 那句"没看到这段口径就先问一句"来问口径——**这是对的行为**，
但按现在的文档会被判成"没出数"。

补一句：跑 §4 之前要 `--claw4j.agent.directory=examples/agents --claw4j.agent.default=sales`
（或 ops），否则测的是"缺口径时该问"的那条路。

### 3. §1 的三条时间窗：依赖种子新鲜度

128400 / 99999 / 77777 只在**刚灌过种子**的库上成立（票 10 有实测：库放一周就变成 99999 / 0）。
补一句"先重灌种子"，或在票 10 的脚本落地后指向它。

## 验收判据

文字类，按改后的写法各跑一次业务流即可：§19 逐字对上、§4 出三区数字、§1 三条数字对。
