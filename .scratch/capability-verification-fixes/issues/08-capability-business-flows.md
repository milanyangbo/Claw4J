# 08: 六项能力的**业务流程**端到端验证（不是异常路径）

**What to build:** 对 MCP / Tool / 脚本包 / Skill / 子 Agent / RAG 各跑一条**真实业务流**，
判据是"业务结果对不对"——具体数字、口径、出处、边界，而不是"工具被调用过"或"异常被兜住了"。

**Blocked by:** 无。

**Type:** verification（只产报告，不改代码；发现缺陷另开票）

**Status:** resolved

**Demo:** 下表每一行的"业务判据"都被实测打勾，报告落在
`docs/reviews/2026-11-16-capability-business-flows.md`。

## 判据（数字全部来自 `docs/capability-tests.md` 与种子 `V2__business_seed.sql`）

| 能力 | 业务流（一句话） | 业务判据（必须逐字对上） | 只看工具被调用是不够的，因为 |
| --- | --- | --- | --- |
| Tool | 上周各区成交额 | 华东 **128400** / 华北 **31500** / 华南 **26000**，合计 **185900**；`SO-LAST-03` 是 `CANCELLED` 不进 | 计数只证明 SQL 发出去过，不证明时间窗与状态过滤写对 |
| Tool | 换两个时间窗 | 本周华东 **99999**、三周前华东 **77777** | 三个窗的数字故意错开，只对上一条说明不了时间窗 |
| MCP | 同一子进程报两次读数 | 两次 **pid 相同**、**时间戳变大** | "答了时间"可以是模型编的；pid 相同才证明是同一个外部进程的真读数 |
| MCP | 原样回显 | 回答里出现我指定的那句话 | 证明跨进程往返没丢字、没改写 |
| 脚本包 | 摘要包内文件 | 摘出来的句子能在 `sample.md` 里**逐字找到** | 改写过的摘要说明模型没在用脚本输出 |
| Skill | 按 skill 口径出数 | 三区数字同上；并复述出 `sum(order_item.amount)` 与 `status <> 'CANCELLED'` | 只加载不办事 = 正文没起作用 |
| 子 Agent | 容量研判 | 堆 已用/上限 + 百分比；**不给具体扩容数值** | 数字要有出处，建议要克制 |
| 子 Agent | 跨层周报 | 三区 + 合计 **185900**，且父这轮 `querySales` 计数不涨 | 父自己查的 ≠ 子 Agent 查的 |
| RAG | 退货政策问答 | 华东 **7 天** / 华南 **5 天**，带出处且首条是 `after-sales` | 数字对但没出处 = 可能来自常识 |
| RAG | 问知识库里没有的东西 | 明确说查不到，**不编** | 检索增强最容易在这里"自信地胡说" |

## 执行条件（三条，否则测的是缓存不是能力）

1. `--claw4j.cache.enabled=false`：语义缓存会复用旧回答（票 02 的教训）。
2. 每条业务流换一个 `X-Claw4j-User`：对话记忆会让模型"记得"上次失败而拒绝重试。
3. 判据只认回答里的数字与出处，不认模型的自我描述。

## 实测结果（报告：`docs/reviews/2026-11-16-capability-business-flows.md`）

9 条业务流：**8 通、1 不通**。

| 通 | Tool 三条时间窗（128400/31500/26000/185900、99999、77777）、MCP 两次读数 pid 相同时间戳递增、
MCP 原样回显、脚本包逐字抽取、Skill 按口径出数 185900、capacity-triage 真实堆与线程、
RAG 华东 7 天/华南 5 天带出处、RAG 对没有的编号明确说查不到 |
| --- | --- |
| **不通** | `weekly-digest` 跨层周报：单工具 `MAX_CALLS_PER_TOOL=3` 打住 |

另外挖出两个更基础的问题（各自开票）：

- **票 09**：默认预算与本仓示范流程规模不匹配——单工具 3 次、整轮 6 次；Skill 那条流在 6 次下被拦，
  调到 20 才通。
- **票 10**：种子日期随迁移时刻漂移，不重灌就会把"产品 bug"测出来（T1 差点被误判）。
