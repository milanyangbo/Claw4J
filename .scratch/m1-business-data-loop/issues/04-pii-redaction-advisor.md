# 04: PII 脱敏 Advisor

**What to build:** 出站之前对回答做 PII 脱敏的 Advisor，同样双接口实现。它和鉴权是两件事：鉴权管"能不能查"，脱敏管"查到了能不能原样说出去"。

**Blocked by:** 01

**Status:** resolved

**Demo:** 脚本化响应里放一个手机号——同步与 SSE 两条路径拿到的输出都是掩码后的，且原始值不出现在日志里。

- [x] Advisor 同时实现 `CallAdvisor` 与 `StreamAdvisor`，并覆写 `getName()`
- [x] 脚本化响应里带手机号与身份证号，输出里是掩码形式
- [x] 同步与流式两条路径各一条断言（SSE 逐块输出时，掩码不能因为分块边界被切成两半而失效）
- [x] **原始值不落日志**：断言日志输出里不含原始值。只在响应里脱敏、日志里仍是明文，等于没脱
- [x] 脱敏发生在出站之前，不是 controller 里事后替换

**注意**：分块边界会把一个手机号切成两块（`138****` + `1234`），逐块脱敏会漏。要么在完整文本上脱敏后再分块，要么确认分块发生在脱敏之后——这个顺序要写进测试，不能靠运气。

**不要做**：行级 / 列级脱敏（ADR-0007 明确不做，表级白名单已足够讲清设计）。也不要在这张票里做"Agent 先问一句再答"的澄清逻辑。

## Answer

提交 `6545bde`。111 个测试全绿。

### 一、摆位与鉴权相反：脱敏在工具循环**外面**

`PiiRedactionAdvisor.ORDER = DEFAULT_CHAT_MEMORY_PRECEDENCE_ORDER - 100`，
小于 `ToolCallingAdvisor.DEFAULT_ORDER`，于是排在循环外面、整通对话只跑一次。

放进去也不是不行，但那会把**工具结果**一起打码——而模型要靠原始值判断"这个号码是哪一单的"。
脱敏是给人看的最后一道工序，不是给模型看的。这一点与 03 号票正好相反，
两张票的 order 一个大于一个小于 `DEFAULT_ORDER`，不是随手写的，各自都有理由。

### 二、流式：扣住"还可能是号码开头"的尾巴

分块边界会正好落在一个手机号中间（假模型按 8 字切，11 位号码必然被切开）。
逐块各自脱敏的话两块都匹配不上，原始号码整个漏出去——
而且**漏不漏取决于模型那批吐了多少字**，这种偶发漏是最难查的。

做法：`PiiRedactor.safePrefix(pending)` 砍掉末尾连续的数字/X 段（PII 模式只由这些字符组成），
只把前面的部分脱敏后吐出，剩下的原样攒着；收尾时把剩下的全部脱敏吐出。
一旦出现别的字符（哪怕是句号），就说明这个号码已经收尾了，前面那些可以定了。

配套一条性质测试：**任意位置切一刀**，两块走完这个流程之后的结果必须与"一次性脱敏整段"完全相同。
切分位置不该影响脱敏结果——这条比挑几个切点断言强得多。

### 三、正则两侧必须定界

手机号 `1[3-9]\d{9}` 不加 `(?<!\d)` / `(?!\d)` 的话，
一串 18 位数字会被当手机号切一段出来打码，打出来的东西谁都不认识。
金额、订单号这类"不是号码的数字"也必须原样放过——打错地方比不打更糟，因为它看着像真数据。
这两条各有一条断言。

### 四、日志断言踩到的坑：抓 System.out 抓不到

先用了 Spring Boot 的 `OutputCaptureExtension` + `CapturedOutput`，**实测抓到的是空串**。
原因：日志系统若在替换 stdout 之前就已经初始化（同 JVM 里别的测试先碰过日志就会这样），
它的 appender 持有的是原来的流，捕获不到。这种断言红了根本分不清"真漏了"还是"没抓到"。

改成往 logger 上挂 Logback 的 `ListAppender`，并**显式把 level 设成 DEBUG**
（不依赖外部日志配置），结束时 detach 并还原 level。

断言分两半才有意义：`不含原始值` 单独看是恒真的（什么都不打日志它也成立），
所以同时断言 `含掩码后的值`——证明这条日志真的打了，且打的是脱敏之后的内容。

顺带一个设计结论：`ChatClientAgentPort` 敢在 DEBUG 打出站**全文**，
正因为链上已经脱过了。哪天有人在链路之外打日志，这条断言会立刻出现原始值。

### 五、变异检验

| 变异 | 结果 |
| --- | --- |
| `safePrefix` 不再扣尾巴（逐块各自脱敏） | 14 红 4（含流式那条与性质测试） |
| 正则去掉定界 | 金额/订单号那条立刻红 |
| 摘掉 `piiRedactionAdvisor` bean | 同步与流式两条红 |
| 去掉出站 DEBUG 日志 | 日志那条红 |

### 留给后面

- 现在只认手机号与身份证号。银行卡、邮箱、地址都不做——加之前先确认业务上真需要，
  每加一类就多一处"打错了看着像真数据"的风险。
- 05 号票真实数据里若有客户手机号，脱敏规则要跟数据字典对齐（例如号码是不是都存在 `customer` 表）。
- 脱敏只做出站。工具结果与模型中间轮次**仍是原值**，这是刻意的；
  将来若要求"连工具结果也不许出网"，那是另一处设计，不在本票范围。
