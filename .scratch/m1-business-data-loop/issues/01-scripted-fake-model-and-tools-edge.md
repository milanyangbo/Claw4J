# 01: 脚本化假模型与 `agent → tools` 依赖边

**What to build:** `claw4j-tools` 里第一次出现 Java 代码（一个桩工具），`claw4j-agent` 第一次依赖它并完成装配——这是 M0 留下的缺口。同时把假模型从"回声"升级成"按脚本吐响应"，于是"模型先要调工具、再据此作答"这两步在 CI 里第一次变得可测。没有这两样，M1 后面每一张票都只能在真模型上手工验。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**Demo:** 一条走 `AgentPort` 接缝的端到端测试——假模型先吐一次工具调用请求、再吐最终回答，桩工具真的被调用，最终回答里带着工具返回的值。

- [ ] `claw4j-tools` 有一个 `@Tool`（桩即可，返回固定串），该模块只依赖 `claw4j-domain`
- [ ] `claw4j-agent` 的 POM 依赖 `claw4j-tools`，工具注册进 `ChatClient`（补上 M0 缺的那条边）
- [ ] ArchUnit 规则：`tools` 不得依赖 `agent` 或 `channel`（反向依赖即失败）
- [ ] 脚本化假模型：按预设顺序吐响应（第一次带工具调用请求，第二次是最终回答），脚本耗尽时给出明确失败而不是静默返回空
- [ ] 端到端测试（AgentPort 接缝）：最终回答里含桩工具的返回值。**开工前这条必然是红的**——现在没有任何工具会被调用
- [ ] 同步与流式两条路径各一条断言
- [ ] 不烧 token、不依赖网络（ADR-0006）

**注意**：这里的桩工具是 deliberately 临时的，05 号票会用真实的 Text-to-SQL 工具替换它。所以端到端断言要断言"回答里含工具返回值"，不要断言具体的业务数值——那个数属于 05。

**顺带要做**：`MockChatModel` 升级后，M0 那些依赖"回声"语义的既有测试可能要跟着改断言。改的时候顺手确认一下流式路径仍按块吐（每 8 字符一块是 M0 为测出"流式被降级成一次性响应"而设的），别把这条保护弄丢。
