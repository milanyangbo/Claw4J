> 这里是 ADR-0019 的 M8（agent 线 A06–A10）。两个 M8 是同一个批次的两条线，

## 一句话

装配已经证明过了（646 条用例、跳过 0）。这条线要回答的是另一个问题：**答得好不好**。

## 五张票

- `A06-eval-set.md`：评测集。50~100 条带判分口径的用例，真模型跑，产出可比较的报告。
- `A07-chinese-tool-index.md`：工具检索对中文整句有解（现在 `RegexToolIndex` 按空白切词，
  "回忆以前说过的话"命中 0 个工具）。
- `A08-long-run-context.md`：压缩可以丢细节，不能丢"还剩几步没做"和"上一次为什么失败"。
  **已关闭**（2026-11-05）：run 的寿命是一轮，答完即 `done`，普通多轮里没有"没做完的事"可钉；
  详见 [ADR-0024](../../docs/adr/0024-no-task-progress-prefix.md)。
- `A09-diagnosable-failure.md`：工具失败要把结构化原因回灌模型一次，只允许一次重试。
- `A10-subagent-budget.md`：子 run 挂 `parent_run_id`，消耗计入父 run 的预算。

后面还有 ADR-0019 的 M9 两张（A11 同 run 内并行工具、A12 多 run 调度与配额），
它们不属于这条线，等这五张收口再开目录。

## 为什么 A06 必须先做

ADR-0019 的原话：**"A06 是 M8 唯一的硬闸门。它之前的所有『改好了』都是自述"**。
A07–A10 的判据全是效果类的（命中率、还记不记得、能不能自救），
没有评测集就只能靠人问一遍然后说"好像好了"。

这不是推测。2026-11-04 的两次 code review 抓到三处"注释说得比代码强"
（非静态 `@Bean` 会失效、全角数字会报错、WARN 验不了），**三处都是人肉变异测试发现的**。
那种审查方式一次只能覆盖一个提交，而评测集覆盖的是"这句话改完之后效果动了没有"——
后者正是 A07–A10 需要的。

## 与平台线的边界

平台线管"能不能用得住"（凭据、通道、可观测、版本契约），这条线管"答得对不对"。
两者在代码上的交汇点只有一个：**`run` 与 `step`**。评测读的是它们（`Run#result`、
`RunStore#stepsOf`），A10 写的是它们（`parent_run_id`）。所以这条线不新增表结构，
只在 A10 加一列。

## 判据（与 ADR-0019 一致，不另立）

- 每条"改好了"都要有一个**能跑出来的数**，不是一段描述。
- 评测与回归分开跑、分开看（A06 的第五节），但评测集本身进回归。
- 没有 key 是失败，不是跳过（ADR-0011）。
