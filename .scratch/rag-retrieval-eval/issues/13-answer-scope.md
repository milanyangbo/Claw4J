# 票 13：回答范围约束（运行时）+ 回答相关性指标（只补，不跑）

状态：进行中（2026-11-21）

## 一、起因

票 10 把 `rag-crossdoc-tier-limit` 的题面从"只问账期"改成"账期 + 额度"，
`Recall@10` 0.912 → 0.919。那 +0.007 是**去掉假扣分**，不是能力提升。

问题在于：这类"reference 比问题宽"的错位**会反复出现，且没法靠题集彻底规避**——
真实用户的问题本身就含糊，而 gold 是从一段自由写出来的答案反解的，答案顺手多答一句，
gold 就多一段。所以题集侧只能做"标注"，治理点应该前移到**运行时**。

运行时的问题长这样：检索回来的块是 350 字，答案常常只有一句。块"相关"，模型就有权
把整块搬进回答——用户问"退货几天"，回答里连运费谁承担、生鲜例外都带上了。
约束要加在"把资料组装成提示词"这一步，也就是 `RagAutoConfiguration#PROMPT_TEMPLATE`。

## 二、行业怎么写（四处对照）

骨架一致，都是四条：grounding / refusal / citation / conciseness。

| 来源 | 对"回答范围"的约束 |
| --- | --- |
| LangChain `rlm/rag-prompt` | `Use three sentences maximum and keep the answer concise.` |
| LangChain 中文文档 | 同上一版（三句上限） |
| knovo《How to build a RAG system》2026 | `Return format: 1) Answer (2-5 sentences) 2) Citations` |
| tutorialq RAG 指南 | `Be concise and direct`，外加 grounding / refusal / citation |
| **本仓 legacy `RAGService`** | **没有范围约束**，第 5 条反而写"如果有多条相关信息，请进行整合" |

两条结论：

1. 行业里约束"范围"主要靠**长度约束**（三句 / 2–5 句），很少逐条列举"别搬别的条款"。
   长度是一个便宜且有效的代理指标。
2. 我们 legacy 那版方向是**反的**：它明确要求"整合"，等于鼓励把多段都写进回答。
   所以这不是抄一句就完事，措辞得重写。

## 三、方案：不抄"三句上限"，换成三条

**不抄三句上限**：本库有合法的枚举型答案（分级账期、退货条件、例外清单），
写死句数会把它们截断。行业给的是"最多几句"，我们要的是"不多写没被问的东西"。

`PROMPT_TEMPLATE` 的"用法"从三条变六条，新增的是 2/3/4：

```
1. 资料确实回答了问题，就据此回答，并在句末用资料开头的编号标出处（例如「见 [2]」）。
2. 只答被问到的部分：同一份资料里还写着别的条款、别的数字、别的例外，不要一并搬出来。
3. 一个问题要几处资料合起来才答得全，就合起来答——合并是允许的，超范围不是。
4. 篇幅按问题定：问一件事就一两句；要列条件时才用短列表，不为了显得完整而扩写。
5. 资料与问题无关，就忽略它，按你平时的方式回答，不要提"资料里没有"。
6. 不要在资料之外编造规定、数字或流程。
```

第 3 条不能省：只写"只答所问、不要扩展"，多跳题（价格 + 延保 = 总价）会被理解成
"只能引用一段"，本该答对的题退化成"资料不足"。

**可配置**（与 `rewrite.prompt` 同一个形状）：

| 键 | 默认 | 含义 |
| --- | --- | --- |
| `claw4j.rag.answer.enabled` | `true` | 关掉回到旧三条（含"整合"那版），用于 A/B 对照 |
| `claw4j.rag.answer.instructions` | 空 | 空 = 内置上面六条；非空整段替换。**不能含 `{` `}`**，那是模板占位符 |

## 四、为什么必须同时补 answer_relevancy

现有三项都**量不到**这条改动：

- `faithfulness` 判的是"回答里每句主张有没有上下文支持"。无关的两句是从上下文里搬的，
  仍在上下文里 → 照样满分。
- `context_precision` / `context_recall` 判的是**上下文**，不看回答。

所以只改模板不动指标，报表一分不动——和改写那 0.007 同一个陷阱：改了，但证明不了。

ragas 0.4.4 有 `ResponseRelevancy`（把回答反推成"它其实在回答什么问题"，再和原问题算
embedding 相似度；走 embedding，不走 judge，成本可忽略）。默认需要给 `embeddings`，
用 DashScope 的 OpenAI 兼容 `/embeddings`（`text-embedding-v4`）构造 `OpenAIEmbeddings`。

**本轮只接代码，不开跑**：`--answer-relevancy` 默认关，关着时报告行与基线一个字都不变；
开着时它自己会因为"基线里没有此项"落到「存疑」，不会污染现有判定。

## 五、不做

- 不改检索链路、不动 gold、不重钉 L1 基线
- 不把"三句上限"写进默认措辞（理由见第三节）
- 不跑 L2（用户明确：先不跑）
- 不做题集对齐的自动校验（那是另一件事，见讨论记录）
