# 票 16：BM25 vs substring 的 L1 对照（换不换默认由它回答）

状态：**已完成（2026-11-21）**，TDD 表无 ❌。上游票 15。裁决在 ADR-0033，本票只补一次对照，不新增裁决。

## 一、目标

同一批 68 题、同一份语料，分别用 `substring` 与 `bm25` 导出候选池，比 L1。

回答**一个**问题：要不要把 `claw4j.rag.keyword.engine` 的默认值换成 `bm25`。

本票不预设结论。分数不动也是结论——那说明这个语料的瓶颈不在"认不认得出词"，
换引擎的理由就只剩维护成本，得由人来拍。

## 二、范围

| # | 改什么 | 要点 |
| --- | --- | --- |
| 1 | `RetrievalExportTest` 支持三个系统属性 | 数据库镜像、引擎、输出路径。三者默认值与现在**逐字一致**，不传参时行为零变化 |
| 2 | 跑两次导出 | substring 用 `pgvector:pg16`；bm25 用 `paradedb/paradedb:pg16` |
| 3 | 跑两次 L1 | `--skip-judge`，只算检索，零模型成本 |
| 4 | 结果写进本票第五节 | 两组 @3/@5/@8/@10、两次的池宽、缺的题清单 |

为什么改导出侧而不是另写一个脚本：导出走的是线上那条链（召回 → 融合 → 重排 → 截断），
另写一份一定会漏掉某一步，而漏掉的那一步不会报错，只会让分数凭空低一截（票 03 踩过：
自己拼的那版漏了重排，Recall@5 低 0.07，报告上看不出来）。

## 三、不做的

- 不改默认值（改默认是结论出来之后的事，且要单独过 L2 重钉）
- 不跑 L2、不重钉 `baseline.json`、不动门槛
- 不改检索链路任何参数（top-k / 每路条数 / 重排候选 / 融合权重）
- 不改语料与题集
- 不为 BM25 加 jieba 词典

## 四、TDD 用例清单

这一票的"实现"只有一处（三个系统属性），其余是跑与记录。

| 判什么行为 | 用例名 | 先红的样子 |
| --- | --- | --- |
| 不传参时导出仍是 substring + pgvector，行为零变化 | `RetrievalExportTest#everyCaseExportsRetrievedIds` ✅ | 把引擎默认值改成 bm25，这条会因为容器里没有 `pg_search` 启动失败 |
| 引擎参数能切到 bm25 且真的走了 BM25 | 两次导出的库内索引不同（`pg_indexes` 里有 `ix_rag_vector_store_content_bm25`） ✅ | 属性没接上时索引不存在，引擎仍是 substring |
| 两次导出写不同文件，不互相覆盖 | 两次的 `run.jsonl` 文件名不同 ✅ | 输出路径写死时第二次覆盖第一次，两组分数变成同一组 |

第二条的证据不是直接查 `pg_indexes`（容器在测试结束后销毁），而是更强的间接证据：`engine=bm25`
时启动任务必须建 bm25 索引，建不出来就启动失败；那一次导出成功，且两组分数不同——引擎确实换了。

复核：2026-11-21 两次 `-Peval test -Dtest=RetrievalExportTest` 全绿（3 tests × 2），
两次 `run_ragas.py --skip-judge` 各 68 条，`run-substring.jsonl` 与 `run-bm25.jsonl` 都是 68 行。

### 结论：不换默认

1. 分数不升反降，且没有救回任何一条原缺题。那 7 条是「字面对不上」或「要推理」，不是「认不出词」，
   换引擎不解决。
2. 型号类查询上 `bm25` 更差：`substring` 的 `short-model-pattern` 给 `A2` 权重 3，把价格表拎进池；
   `bm25` 按总分排序，价格表只命中少数词，被「延保」块挤出 25 名。
3. 换默认的代价是镜像 + 许可证 + 融合权重重标 + 基线重钉，收益为负。

已同步 ADR-0033 的「验证」一节：判据第一道没过，重开条件收敛成「语料上万段」或「出现分词决定成败
的真实例子」。本票不改默认值、不跑 L2、不重钉基线。
