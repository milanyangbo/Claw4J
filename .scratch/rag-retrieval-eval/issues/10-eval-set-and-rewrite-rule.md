# 票 10：评测题面对齐 + 改写跳过规则收窄 + 多跳归档

状态：进行中（2026-11-20）

## 一、背景

票 04–09 落地后，L1 到了 Recall@10 = 0.912（改写开 0.934），基线已钉。剩下 7 条没召全，
逐条看完以后，没有一条是"检索链路还能改好的"，而是三种性质：

| 题 | 现象 | 性质 |
| --- | --- | --- |
| `rag-crossdoc-tier-limit` | 账期段第 5 位进了，额度段第 15 位没进 | **题面问的和答案要求的不一致** |
| `rag-noanswer-iso`、`rag-noanswer-2027-roadmap` | 零字面重叠、且含数字 → 被改写规则挡住 | **规则副作用** |
| `rag-multihop-tradein-a1`、`rag-discount-rebate`、`rag-multihop-price-protect` | 价格表块第 14 位 / 不在池 | **多跳中间证据**，见第四节 |

所以这张票只做三件收尾的事，都不碰检索链路本身。

## 二、题面对齐：`rag-crossdoc-tier-limit`

现状：

```
问题：A 级客户的账期是多少？
答案：月结 60 个自然日；额度按上一年度月均采购额的 2 倍核定。B 级 30 天，C 级款到发货。
gold：customer-tiers.md（账期，位次 5） + credit-limit.md（额度，位次 15）
```

问题只问账期，答案却答了"账期 + 额度"，第二段 gold 是为了对齐答案才加的。这是**先写答案、
后拆 span** 留下的错位，不是检索的错。

修法**不是删掉第二段**：这题 id 里的 `crossdoc` 就是它的设计意图（跨两份文档），删掉就退化成
单文档题，还白丢一条跨文档覆盖，同时 cases 数从 68 变 67、基线要重钉。

改的是问题：**「A 级客户的账期和授信额度分别是多少？」**——答案不动、gold_spans 不动、
cases 数不变，只让卷子问的和答的对齐。

改完必须重跑 L1 确认两段都进 top-10：进了，说明原来扣的分是题面的错；没进，才轮到查检索。

## 三、改写跳过规则：从"含数字"收窄到"含数值"

现状（`RetrievalQueryRewriter#SKIP`）：

```java
"[0-9０-９]|百分之|万分之|[零一二三四五六七八九十百千万亿]+\\s*(元|块|天|日|个工作日|%|％|份|件|台)"
```

`[0-9]` 这一条把**任何含数字的问题**都挡在门外，于是 9 条本该被改写的题拿不到改写：

```
SKU-2024-M6 的尺寸和每卷张数是多少？      A2 桌面机多少钱？
M7 标签纸每卷多少张？                    P1 停机故障多久要恢复？
你们有 ISO 9001 认证吗？                 A1 要停产了吗？
P1 故障必须马上派人到现场吗？
```

跳过的**真正理由**不是"问题里有数字"，而是 **HyDE 类改写会把精确值近似化**（把「万分之五」
改成「千分之几」）。那只对**数值型**成立：金额、比例、时限、数量。对**标识型**（型号、标准号、
SKU）不成立——标识是实体名，模型会照抄。

所以改成两道闸：

1. **跳过**：只拦"数值 + 计量单位"（元/块/天/日/个工作日/月/年/％/份/件/台/倍/折/次/小时/
   分钟/秒/万/千）与比例词（百分之/万分之/千分之）。
2. **校验**：改写结果必须包含原问题里所有的 ASCII 标识 token（`[A-Za-z0-9]+([._-][A-Za-z0-9]+)*`，
   长度 ≥2），丢任何一个就回落原问题。

第二道是这次的关键：**保护从"猜哪些该跳过"变成"检查改写结果"**。前者靠正则猜，漏一个就放一个
精确值过去；后者是确定性的，模型抽风也伤不到。

代价：多一次 token 比对（微秒级）。收益：`ISO 9001` 与 `SKU-2024` 在字面形态上无法区分，
但校验能分开——前者要求保留 `ISO` 与 `9001`，后者要求保留 `SKU-2024`。

## 四、多跳题：归档，不投工程

三条多跳题的性质不同：

| 题 | 缺的段 | 位次 | 性质 |
| --- | --- | --- | --- |
| `multihop-tradein-a1` | `price-list-2026.md#1` | 14 | 进池了，排序没排上去 |
| `discount-rebate` | `price-list-2026.md#1` | 不在池 | 召回侧 |
| `multihop-price-protect` | `price-protection.md#1` | 不在池 | 召回侧 |

不做查询分解的理由：

1. 收益 3/68 = 4.4%，全修好 0.934 → 0.978，而门是 0.90，已过。
2. 成本是全链路改动：每条提问多 2–4 次模型调用 + 一套子问题合并逻辑。
3. 其中 2 条是召回侧就没捞到，而 `price-list-2026.md#1` 是 markdown 表格——**表格行在向量里
   天然弱**，拆子问题仍要查那张表，救不了。

**如果**以后要把 Recall 提到 0.95+，动手顺序是：① 表格块转文本嵌入（索引时把表行转成
「A1：单价 3999 元」的键值句，返回时仍给原表格；代价是块文本变了、`CHUNKING_VERSION` +1、
全量重建一次）；② 才是查询分解。

本次只把它写进 `docs/design/knowledge-retrieval.md` 的"已知局限"，注明性质，不写成待办。

- 不把 `rewrite.enabled` 改成 true（默认值仍关；开不开是上线决策，要先有"改写异常率"的观测）

## 七、实测（2026-11-20 晚，只跑 L1，两轮各约 7 分钟）

| 配置 | 旧题面 | 新题面 |
| --- | --- | --- |
| 改写关（默认） | 0.912 | **0.919** |
| 改写开 | 0.934 | 0.926 |

### 题面对齐：+0.007，且是唯一改动

`rag-crossdoc-tier-limit` 改问「账期和授信额度分别是多少」之后，两段落到 **第 8 位与第 9 位**，
都在 top-10 内。0.912 → 0.919 正好等于 +0.5/68（这题有 2 段 gold，原来只命中 1 段）——
数字对得上，说明涨的这一点**全部**来自这题，不是别处波动。

这不是"调参调出来的提升"，是把一个假扣分去掉：原来那 0.5 段是因为问题没问，不是检索没找到。

### 规则收窄：指标上 −0.008，落在噪声里

改写开的两轮：旧规则 0.934 → 新规则 0.926。同题面下比较，规则收窄是 **−0.008**。

拆开看这 0.008 是什么：

- **修好 2 条**：`colloquial-late`、`multihop-price-protect`（都不是新放开的题，是改写本身的效果）
- **翻红 2 条**：`neg-consumable-return`（不在池）、`warehouse-return48`（第 12 位，边界）
- 新放开的 7 条标识型题里，`sku-spec` / `price-a2` / `price-m7` / `sla-p1` / `p1-dispatch` /
  `a1-stop` 在**改写关**时本来就召全了（型号锚点 + bigram 够用），所以改写对它们是中性

也就是说：**规则收窄没有带来正面收益，反而多了两条改写的不确定性**。原因不复杂——放开的那些题
本来就不需要改写。

**那为什么还留着？** 因为它修的是一个逻辑错，不是指标：
「含数字就跳过」把型号当成数值拦掉了，而型号和数值是两类东西。留着的价值在于——一旦哪天要开
改写（比如线上口语问句占比高），不会因为题里带 `A2` 就无脑跳过；而 `keepsIdentifiers` 那层
校验是纯防御，不依赖开不开。

**代价要如实写在文档里**：规则收窄在 68 条上没有可证明的收益。

### 更重要的结论：改写的影响小于测量噪声

同为"改写开"，旧规则 0.934、新规则 0.926，差 0.008；而同为"改写开"的两次跑之间就差了 0.008。
68 条里一条 = 0.015（单段题），所以 **±2 条的抖动是这套评测的固有噪声**，而改写带来的净变化
正好在这个量级。

这直接回答了"改写要不要默认开"：**不开**。理由不再是"延迟换 2 条值不值"的权衡，而是
**当前样本证明不了它有效**。要证明，得把评测集扩到 200 条以上，让 1 条题不再等于 1.5 个百分点。
