# 06: Skill Generator 五步链路

**What to build:** 让 Agent 能**自己产出一个新 Script Package**，但全程关在笼子里：生成 → 静态检查 → 隔离沙箱自测 → 审计留痕 → 人审通过才注册。未人审的脚本拿不到被调用的资格。这是 ADR-0002 修订后定下的链路，也是本项目"开放扩展"这个定位唯一能自证的部分。

**Blocked by:** 03, 04

**Status:** closed

**Demo:** 让模型为一个没写过的能力生成一个脚本包，五步每一步都有可见产物：静态检查挡下一个危险用例、沙箱自测跑出脚本的原始输出（失败时也是原话）、审计里有这条记录、人审之前它不在可调用的工具清单里。

- [x] 五步链路串起来，每一步的产物可见
- [x] **静态检查是纯函数、用表驱动用例钉死**：危险清单逐条一个用例，命中必须拒、正常脚本必须放行，两条都要有。它是未审核代码进门前的唯一一道机器关，也是最便宜的一环
- [x] 自测发生在**隔离沙箱**内（与 03 那个执行位置分清，ADR-0003）：网络受限、有资源上限、不继承应用容器的环境变量
- [x] 审计留痕：生成、自测、执行都能回放"谁在什么时候跑了什么、结果如何"
- [x] 人审通过才注册为 Script Package；未人审的脚本不在工具清单里（用 01 那条清单断言验）
- [x] 自测失败时把脚本的原话（stderr）给到模型，不要包装 —— 与自纠错同理，包装过的话没有可改的信息
- [x] 变异检验：去掉静态检查 / 跳过人审直接注册 → 各自对应的测试红

**注意:** 沙箱跑不起来就等于这条链路没有测试，而没有测试的"沙箱"不能写进 README 当承诺。若这一处的物理形态与 03 不同，在票的 Answer 里说明理由，并写进 ADR-0002 的修订记录。

**不要做:** 自动生成 Java `@Tool`；自动人审（这一步必须是人）。

---

## Answer

落在 `claw4j-tools` 的 `io.github.claw4j.tools.generator`。模型手上多一个工具
`propose_script`（动作 `draft_script`），五步走完停在"待人工审核"。

### 五步的顺序就是安全边界的顺序

| 步 | 落在哪 | 为什么在这个位置 |
| --- | --- | --- |
| 1 生成 | `SkillGenerator.writeCandidate` → 暂存区 | —— |
| 2 静态检查 | `ScriptStaticCheck`（纯函数） | 在落盘**之前**：危险代码不该先被写下来再被删掉 |
| 3 沙箱自测 | `GeneratorSandbox` | 跑的是未审核代码，不能让它改自己待审的那份内容 |
| 4 审计 | `GenerationAudit`（只追加） | 三步各记一条，最后补的那条写不出"被挡下的是谁提交的" |
| 5 人审 | `ReviewGate` 只读签字 | 唯一没有代码替人做的那一步 |

**静态检查是纯函数**（不读文件、不看时间、不取随机数），于是"它挡住了什么"被一张表钉死：
危险清单 16 条逐条一个用例，正常脚本另有一组 6 个用例——只测"危险被挡下"的话，
一条全拒的实现也会绿，而那种实现的后果是这条链路从此产不出任何脚本。
它**认写法不认意图**（装包、提权、连网、读凭据、删东西、动态执行），
挡的是明着写的那部分；1.x 那次 `pip install --break-system-packages` 就是明着写的。

### 沙箱的物理形态：临时目录副本，不是容器（与 03 不同）

判据沿用 03 那条——**CI 上没有 Docker 守护进程**，依赖容器的沙箱在 CI 上是一串红灯。
第 ② 类跑的是"模型刚写出来的东西"，所以比第 ① 类多一层：**候选目录复制成临时目录再跑，跑完即删**。

这一层不是形式主义。候选目录里放着"等着被人审的"脚本与审批目标，
让自测跑在那儿等于允许未审核代码改自己将要被审的内容——
甚至给自己写一个审批标记（沙箱锁得住入口、参数、工作目录，
锁不住脚本体内去写一个绝对路径，这是 03 就写明挡不住的那一样）。
所以审批目录默认放在暂存区**旁边**（`reviews/`），不在里面，也不在沙箱里。

它给的三样：工作目录隔离、环境只有 `PATH`、5 秒上限（比 ① 的 15/30 更紧）。

**票面上"网络受限、有资源上限"这两项，本形态给不了**，理由写进 ADR-0002 修订记录与 ADR-0013：
纯 Java 起的子进程没有可移植的网络/资源限制手段，`unshare` / `sandbox-exec`
都是要再起一条命令，而那正是 ADR-0002 禁止的那件事。
规格里如实写成 `NOT_ISOLATED` 并附原因（有一条断言盯着它不许撒谎），
真正的网络隔离由部署层的容器网络策略给；**联网的脚本在静态检查那一关就被挡了**
（`NETWORK_CLIENT` / `PY_NETWORK`）。README 与 GLOSSARY 不把这两项写成承诺。

### 人审比对的是"审的哪一版"，不是"有没有签"

审批标记要写 `status=approved` / `by` / `at` / `sha256`，四项缺一不算通过，
`status` 严格相等（写成 `approve` 或 `Approved` 不算——"看着像通过"不算通过）。
摘要对不上（签字之后脚本被改过）时那次签字自动作废：
否则"审过一次"会变成一张长期通行证，人看到的是"我审过"、系统跑的却是另一份内容。

**未人审不在工具清单**落在 `ScriptPackageRegistry` 上：工具清单由 provider 现取，
于是"待审"在模型那边就是"根本没有这个工具"——不是靠"模型不去调它"维持的，它看不见。
（`ScriptPackageToolProvider` 因此从"构造时快照"改成"现取"，权限表同样现取：
否则新包会出现在清单里却在鉴权那一步被拒。）

### 偏差

1. **执行留痕挂在 `ExecutionListeners` 容器上**，不是注入一个 listener：脚本层先装配、
   生成器后装配，按类型注入的那一刻还没有审计，"没接上"的表现是静默的——从此没有任何执行记录。
   容器先落地、后来者往里加，顺序就不再是问题。
2. **没有脚本层就没有生成器**（`@ConditionalOnBean(ScriptPackageRegistry.class)`）：
   人审之后的注册目标就是脚本层的清单，没有它，"人签了字"会变成一个没有任何效果、
   却看起来成功的动作。
3. **`draft_script` 只给了 admin**：提交一份草稿不等于能跑脚本
   （`run_script` 是另一个动作），合成一个就等于让"能提议的人"顺手拿到执行权。
4. **审计用制表符分隔的文本而不是 JSON**：六个字段、只追加、tools 层不为一个日志文件引解析依赖。
5. **身份那把 key 搬到了 domain**（`ContextKeys.PRINCIPAL`）：工具回调里读身份
   （委派与执行都在工具内部），而 tools 不认识 agent（ADR-0010），
   各写一份常量会漂移，漂移的表现是"一律按没身份拒绝"。

### 变异检验

| 变异 | 结果 |
| --- | --- |
| 去掉静态检查（直接落盘） | `静态检查没过不落盘` 红 |
| 跳过人审直接注册 | `未人审不在清单里`、`人审通过才注册`、`五步走完前四步`、装配那条共 5 条红 |
| 不比对脚本摘要 | `签字版本对不上就不注册` 红 |
| 自测跑在候选目录（不复制） | `沙箱目录不是候选目录` 等 6 条红 |
| 审计不记 SELF_TESTED | `五步走完前四步` 红 |
| 失败时把 stderr 包装成"请修改后重试" | `失败时给脚本原话` 红 |
| 没有身份也照常提交 | `没有身份的提交被拒` 红 |
| 删掉规则表里 NETWORK_CLIENT 那一条 | `危险写法一律被拒`、`拒绝理由带行号与原因` 红 |
