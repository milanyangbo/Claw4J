# 06: Skill Generator 五步链路

**What to build:** 让 Agent 能**自己产出一个新 Script Package**，但全程关在笼子里：生成 → 静态检查 → 隔离沙箱自测 → 审计留痕 → 人审通过才注册。未人审的脚本拿不到被调用的资格。这是 ADR-0002 修订后定下的链路，也是本项目"开放扩展"这个定位唯一能自证的部分。

**Blocked by:** 03, 04

**Status:** ready-for-agent

**Demo:** 让模型为一个没写过的能力生成一个脚本包，五步每一步都有可见产物：静态检查挡下一个危险用例、沙箱自测跑出脚本的原始输出（失败时也是原话）、审计里有这条记录、人审之前它不在可调用的工具清单里。

- [ ] 五步链路串起来，每一步的产物可见
- [ ] **静态检查是纯函数、用表驱动用例钉死**：危险清单逐条一个用例，命中必须拒、正常脚本必须放行，两条都要有。它是未审核代码进门前的唯一一道机器关，也是最便宜的一环
- [ ] 自测发生在**隔离沙箱**内（与 03 那个执行位置分清，ADR-0003）：网络受限、有资源上限、不继承应用容器的环境变量
- [ ] 审计留痕：生成、自测、执行都能回放"谁在什么时候跑了什么、结果如何"
- [ ] 人审通过才注册为 Script Package；未人审的脚本不在工具清单里（用 01 那条清单断言验）
- [ ] 自测失败时把脚本的原话（stderr）给到模型，不要包装 —— 与自纠错同理，包装过的话没有可改的信息
- [ ] 变异检验：去掉静态检查 / 跳过人审直接注册 → 各自对应的测试红

**注意:** 沙箱跑不起来就等于这条链路没有测试，而没有测试的"沙箱"不能写进 README 当承诺。若这一处的物理形态与 03 不同，在票的 Answer 里说明理由，并写进 ADR-0002 的修订记录。

**不要做:** 自动生成 Java `@Tool`；自动人审（这一步必须是人）。
