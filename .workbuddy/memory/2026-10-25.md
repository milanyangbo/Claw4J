## 目录重构 + 单测收敛（一次性收口）

### 1. 模块与包的对应关系（`claw4j-tools` → `claw4j-capability`）

起因是一条"看着别扭"：`tools/sales` 包与 `SalesTools` 分居两处，而 `tools` 下又平铺着
mcp / script / skill / generator。定下来的规则是 **`capability` 顶层只放"装配与契约"，
每一条具体能力自己一个 `builtin/<name>` 子包，类跟着包走**：

- `tools` → `capability`；`sales` / `system` 收进 `capability/builtin/`；`SalesTools` 跟着进 `builtin/sales/`。
- `domain.principal.ContextKeys` → `domain.ContextKeys`（它是会话键，不是身份的一部分）。
- `channel.http.PrincipalRejectedException` / `TooBusyException` → `channel.spi`（通道契约的失败类型，不是 HTTP 的）。
- `agent.ModelConfiguration` / `RoutingModelConfiguration` → `agent.model`（它们是"模型这一块"的装配）。

教训：批量按前缀替换包名时，`tools.SalesTools` 会被替换成**目录名**而不是新包名，
改完必须编译一次；`TooBusyException` 挪包后忘了改 `public`，报的是"not public in ...spi"。

### 3. 这次真正定下来的硬规则：合并只看"运行前提"，不看主题

一个测试类的运行前提是**整类生效**的（`@Testcontainers` / 要真模型的装配 / `@Tag` 组）。
所以：

- 纯组件级 + 纯组件级 → 可以合（ToolLoop 那组、Authorization 那组）
- 都要 Docker / 都要真模型 → 可以合
- **一个纯 + 一个要真模型 → 不许合**：`SessionMemoryDegradationTest`（1 条，要真模型装配）
  因此**没有**并进 `SessionMemoryTest`（9 条纯规则）——并了之后没 key 的人会一次性失去 9 条纯规则
- **一个纯 + 一个要 Docker → 不许合**：`SalesSqlExecutionTest` 没有并进 `SalesQueryTest`，
  `SchemaMigrationOnStartupTest` 没有并进 `ToolsAutoConfigurationTest`，同理
- 默认组 + `@Tag("real-cli")` → 不许合：`RealCliMcpEndToEndTest` 因此独立

这条写进了 `docs/agents/testing.md` 第五节（含对照表），并改掉原来"验收层一个能力一份"的说法
——现在是"按同一组判据分组"，因为两种工具来源过的是同一张检查清单。

剩下 14 / 12 份的构成是：能力各一份（9 / 9）+ 闸门（arch、迁移、real-cli）+ 前提不同而无法合并的。
再压就要么删真规则、要么让纯规则跟着 Docker/真模型一起红，两者都不做。
