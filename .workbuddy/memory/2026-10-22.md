### 代码库事实（子代理勘察，40 类 / 6793 行 / 零测试）
- Spring AI 只用 1.0.0-M6，且极浅：仅 `ChatClient.prompt().call().content()` + `SimpleVectorStore` + 一个 `SimpleLoggerAdvisor`；**无 ChatMemory、无 Advisor 链、无 Tool Calling**
- "工具调用"是字符串协议：LLM 输出 `CALL_SKILL: xxx`，Java 侧 `indexOf` 解析（TeammorsMessageAdapter:78）
- 死通道：Telegram 注册代码被注释（AgentManager:56），**0 个 @Controller**（有 undertow + 8900 端口空转）
- 安全 P0：`ShellUtils` 把用户自然语言当 argv 喂 `python3`（GenericSkill:180-211），`sh -c` 注入面，硬编码 root SSH 且关主机校验；`SkillGeneratorSkill` 让 AI 写 Python 落盘执行并允许 `pip install --break-system-packages`
- 明文凭证：`application.yml:40` Teammors token；`skills/unread-mail/scripts/test_imap_debug.py` 邮箱密码
- 构建三处冲突：属性 21 / compiler plugin 17 / `<executable>` 指向不存在的 `/usr/local/opt/openjdk@17/bin/javac`；`mvn compile` 本机必失败，target 里是 IDE(zulu-17) 产物
- 并发：`SkillGeneratorSkill.userStates`、`ScheduledTaskManager.tasks` 是 HashMap 被多线程读写；`ThreadUtils` 核心 200/队列 1/最大 10000 + CallerRunsPolicy
- 反射 hack：VectorStoreService 反射调 `similaritySearch(String,int)`、反射清私有 `store` 字段
- 三套 Redis 客户端并存（Lettuce/Jedis/Redisson），Redisson 建了不用；mysql-connector 完全未用
- fastjson 1.2.83 直接反序列化 WebSocket 不可信数据，未开 safeMode
- 死代码：UnicodeDecoder、ValidationService、GlobalExceptionHandler、RedisUtils.getRedissonClient 等

### 核实到的关键事实（2026-10）
- `org.springaicommunity:spring-ai-agent-utils` 0.4.2 真实存在，要求 Spring AI **2.0.0-M2+**；`SkillsTool.builder().addSkillsDirectory(...)` 为真；另有 `addSkillsResource()` 支持 classpath 打包分发
- `SkillsTool` **只发现+激活，不执行**；执行靠同包 `ShellTools`
- **Spring 官方博客明确安全提示**：脚本在本机**无沙箱**执行，建议整体跑容器里 → 换框架不解决沙箱问题
- 概念澄清：**Skill ≠ Tool**。Skill 是"何时用/什么流程"（SKILL.md），Tool 是"能做什么"的动作；一个 Skill 编排多个 Tool
