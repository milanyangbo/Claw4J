### IDEA 里点 Claw4jApplication 起不来的根因与修法
- 现象：IDEA 直接跑启动类，`ModelConfiguration.requireConfigured` 抛"没有配置任何 API key"。
- 根因：`spring.config.import` 原先只写在 `application-local.yml`。IDEA 点绿三角时既不激活 local，
  工作目录又是模块目录 `claw4j-app`（`$MODULE_WORKING_DIR$`），所以 `.env` 从头到尾没人读；
  但错误信息说"没有配置任何 API key"，看着像配置写错，其实只是没喂给它。
- 修法：import 上移到 base `application.yml`，两个相对位置都试：
  `optional:file:./.env[.properties],optional:file:../.env[.properties]`
  （仓库根目录 = 命令行启动；模块目录 = IDEA 默认）。`application-local.yml(.example)` 里那份删掉，
  别让同一份文件有两个读它的地方。
- 验证：`cd claw4j-app && env -u DEEPSEEK_API_KEY -u QWEN_API_KEY java -jar target/*.jar` → 2.5s 起在 Tomcat，
  走的是 `../.env`；带 key 不带 profile 时不连库也能起（Hikari 懒连接、flyway 默认关）。
- 顺手修的两处过期文案：`.env.example` 还写着"没 key 自动降级 mock / CLAW4J_MODEL_MOCK 可强制 mock"
  （ADR-0011 已废），改为"必须配 key"；`requireConfigured` 的异常信息补上两条具体做法（.env 或 IDEA
  的 Environment variables）。
- 回归：`./scripts/verify.sh` 全绿 155 条、跳过 0、覆盖率 domain 100/channel 80.5/capability 84.7/agent 87.1。

### 415 Unsupported Media Type：README 演示段漏了 Content-Type
- 现象：照 README 演示段那条 curl 跑，返回 `status:415, Unsupported Media Type`。
- 原因：curl 带 `-d` 时默认 `Content-Type: application/x-www-form-urlencoded`，而
  `/api/chat` 用 `@RequestBody` 走 JSON 转换器 → 不认这个类型。补 `-H 'Content-Type: application/json'` 即好。
- README 里 快速开始 / 用法 两段本来就有这行，只有"演示"段的三条漏了（已修，commit ce9ac87）。
  docs/design/capability-layers.md 的 6 条 curl 都带着，没有同样问题。
- 另：本地库不是干净种子（问出来 ￥99,999.00 / 1 笔订单，README 示例是 ￥128,400.00）。
  128400 对应的是空库种子，ApplicationAssemblyTest 在 testcontainers 上断言的就是它，所以示例数字没错。

### 记忆与 Redis 的边界（用户问"长短记忆是不是要用 Redis"）
- **spring-ai-session 早集成了，而且不用 Redis**：`org.springaicommunity:spring-ai-starter-session-jdbc` 0.10.0
  （根 pom 的 `spring-ai-session-bom` 管版本）。装配在 `agent/session/SessionMemoryConfiguration`：
  自建会话连接池（URL 带 `currentSchema=claw4j_session`，不注册成 bean）+ `FaultTolerantSessionService`
  + `SessionMemoryAdvisor(order=HIGHEST_PRECEDENCE)`；`AgentAutoConfiguration` 的 `defaultAdvisors`
  收走它；`ChatClientAgentPort.promptOf` 每轮塞 SESSION_ID/USER_ID。建表在
  `capability/db/migration/V3__session_schema.sql`。测试 `SessionMemoryTest` 11 条（刚复核：0 失败）。
- **社区 session-bom 只有 jdbc 实现**（session / session-jdbc / autoconfigure / starter 四件），
  没有 redis 实现；ADR-0005 也明确否决"Redis 兼做会话存储"（缺事务与查询能力）。Redis 定位只剩 M3 语义缓存。
- 现状：`claw4j-app` 引了 `spring-boot-starter-data-redis`、`application.yml` 配了 `spring.data.redis`、
  compose 起了 Redis，**代码零引用**（无 RedisTemplate / 连接工厂注入点）。启动不连（Lettuce 懒连接）。
- 顺手修：`claw4j-app/pom.xml` 里那条 redis 依赖头上顶着一整段**Flyway 的注释**（还提到已不存在的
  "tools 模块"）——copy 错位。换成"它不是会话存储、只服务 M3 语义缓存、当前零引用，别删这段说明"。
- 真正的记忆缺口不是 Redis，是**轮次压缩没开**：`FaultTolerantSessionService.compact` 只是穿透方法，
  配置里没有 compactionTrigger（ADR-0008 ④ 要求 Trigger 与 Strategy 成对），长对话会全量进提示词。
  已写进 spec 的 Out of Scope，跟 M3 的 token 计量一起做（压缩按 token 触发，分开做要返工）。
