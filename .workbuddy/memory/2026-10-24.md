  app 里藏的 `TwoRoundModel`；连带 `claw4j.model.mock` 三态与 `-Preal-model` profile。

### 真模型当场抓到的两个缺陷（本趟最值钱的输出）

1. **用户消息里的手机号以明文进了会话表**。出站脱敏在 `after`，会话记忆在 `before` 最早那步
   就把用户消息写库了，改不到它。修法：`ChatClientAgentPort` 入站先过 `PiiRedactor`。
   代价：模型看不到用户写的原始号码（当前没有"按手机号查"的工具）。
2. **三条 HTTP 用例互相污染**：共用一个 `X-Claw4j-User` 就共用一个会话，真模型把上一轮的
   "没权限"带进下一轮。改成每条用例换用户。

### 真模型的断言习惯（踩过的坑）

- 金额必须按 `128,400.00 / 128400.00 / 128,400 / 128400` 四种写法匹配——真模型会自己加千分位
- 不能断言"回答里回着问题原话"、不能断言 `[mock]`、不能断言拒绝原话（会被模型转述）
- Advisor 留痕从 before 挪到 after（真模型不复述用户消息）

## 收尾核对（票 01 关闭，179 测试）

用户问"票面勾选框怎么没打勾"，逐条核对后发现**第 5 条漏做**，另两条变异检验没做。已补齐：

1. **`RealModelIT` → `RealModelTest`**，去掉 IT 后缀与 `claw4j-app/pom.xml` 的 `real-model`
   profile，4 条进常规回归、全绿。ADR-0011 本来就否决了"真模型只跑 IT + profile 隔离"，
   README 里我却写着"仍留在 -Preal-model"——自相矛盾，属于漏做而非有意决定。
   它多覆盖的是**完整装配**层（app yml、真 Flyway、fat-jar 接线），与 agent 模块级那批断的东西不同。
   库来源没变：本机由 `spring-boot-docker-compose` 按 `compose.yaml` 起。
2. **我自己写的永真断言掩盖了一个真问题**（值得记因果顺序）：`HttpChannelEndToEndTest` 三条
   断言被我写成"回答非空"，补做变异检验（改回"有没有库里那个数"）时立刻红 3 条——
   这个测试一直用**没权限的默认角色**（只发 user 头 → `defaultRole = read-only`）问成交额，
   且用固定用户名（app 侧是常驻库、会话落库，上一轮的"没权限"被真模型读进去了）。
   改成每用例换用户 + 显式 `X-Claw4j-Role: admin` 后绿。
   教训：换真模型不会自动改善判据，断言放宽得比模型更狠，真实性就被原样吃掉。
3. **变异"脱敏 ORDER 挪进工具循环内"不再红**：会话那 7 条仍绿，只有
   `PiiRedactionAdvisorTest.order排在工具循环外面` 红。原因是入站脱敏上线后防线前移——
   order 从唯一防线降级为第二道防线。两道都在：去入站脱敏红（主），挪 order 红（副，单测盯着）。
