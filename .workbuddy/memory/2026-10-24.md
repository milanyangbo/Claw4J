## M2-02：MCP 跨进程闭环（提交 306b49b）

能力三层里的第二层第一次落成代码。`claw4j-tools` 新增 `io.github.claw4j.tools.mcp`：
`McpServerEndpoint`（接缝）/ `McpConnection`（生命周期）/ `McpToolCallback`（适配成
Spring AI 的 ToolCallback）/ `McpToolProvider`（fail-fast + 权限登记）/ `McpToolAutoConfiguration`；
`stdio/` 下 `InProcessStdioMcpServer` + `PipedStdioClientTransport`。

### 关键决策与坑

- **坐标从 BOM 逐条核过**（starter-mcp-client / spring-ai-mcp / spring-ai-mcp-annotations），
  确认 `mcp-spring-webflux|webmvc` 是 optional 才敢引（不会把 web 栈带进 tools）。
  没引 server starter：server 侧用到的类都在传递引里。
- **SDK 的 `StdioClientTransport` 只接受 `ServerParameters`，一定会起子进程**；
  进程内那半没有现成的客户端传输，所以自己照抄它的线程分工写了一个管道版。
- **"跨进程"跨的是协议边界不是 OS 进程**（偏差已记账）。子进程路线在 surefire 下要拿
  manifest-only booter jar 的 classpath，CI 上脆；spec 明令避免"必测只在有 Docker 的机器上测过"。
  接缝是 `McpServerEndpoint.openTransport()`，真实 server（gh/himalaya）留给 07。
- **fail-fast 判据只有一条"清单是空的"**：SDK 对"没声明 tools 能力"另有
  `Server does not provide tools capability` 一说，在 `listTools()` 里归一成空清单，
  免得同一种故障两条报错路径。
- **只认 `McpTransportSessionNotFoundException`**（沿 cause 链找一层，可能已被 Reactor 包过），
  重连后重放**一次**；把超时/协议错误也当"重开一次"会把真故障变成一串无意义重连。
- **顺手修掉一个同类静默坑**：`salesToolPermissionRegistry` 上的
  `@ConditionalOnMissingBean(ToolPermissionRegistry.class)` 会让第二个来源的登记表让位，
  它的工具从此一律按"未登记"被拒——与 01 修掉的"工具静默消失"同一个形状。
  两个来源都改成按"本层能不能成立"判。
- **引 starter 会带进框架自己的空 `ToolCallbackProvider`（`mcpToolCallbacks`）**，
  让按类型注入"那个 provider"的地方装配失败。`spring.ai.mcp.client.enabled: false` 关掉，
  并补一条断言盯着那行配置（"配置文件少一行"最容易在合并里丢）。

### 测试要点

- 端到端断言盯的是**随机 marker 而不是常识值**：原先让模型报"处理器有几个"，
  那是它猜得出来的数，猜对就假绿，而"模型到底调没调工具"正是要验的事。
- 会话丢失那条断言两处：调用仍成功 **且** `initializations()==2`（少后者则"成功"可能是根本没丢过）。
- 变异四条全红：去 fail-fast / 去重连 / 给 MCP 登记业务表 / 给"未登记"用例登记上权限。

## M2-03 Script Package 受限执行（票 03，closed，提交 8b8eb6d）

### 物理形态是"应用容器内的受限子进程"，不是另一台容器

判据只有一条：**能不能在 CI 里跑起来**。CI 的 runner 上没有 Docker 守护进程
（数据库那一类靠 `CLAW4J_POSTGRES_IMAGE` 指定镜像），依赖容器的沙箱在 CI 上就是一串红灯。
`LocalExecBackend`（社区包）自带 `workingDirectory` 与 `cleanEnvironment`，不需要 Docker/Python。
接缝是 `ExecBackendFactory`（默认 `SandboxedExecBackend::forPackage`），
`ScriptPackageRunner` 只认 `ExecBackend`；换形态改注入的那个实现，调用方一行不动。

挡得住的五样各一条测试：工作目录（`pwd` 验）、参数（`..`/绝对路径/符号链接）、
环境（从零开始只给 PATH）、超时（上限 30s，不给或超上限就**拒绝**不夹取）、非 root。
**挡不住的写进 README 与 GLOSSARY**：脚本体内自己读绝对路径或自己连网——
进程沙箱锁得住入口与参数，锁不住脚本自己的行为，那要靠 ADR-0003 第 ② 类沙箱（06）。

### 三个可复用的判断

- **ArchUnit 的 `callMethod(Runtime.class, "exec")` 会写出一条永远不生效的规则**：
  第三个参数是可变形参类型，写成 `"exec"` 等于"无参的 exec"（而 exec 无无参重载）——
  不报错、永远匹配不上、显示成绿。改用 `callMethodWhere` + 显式谓词。
  同类风险值得以后每次加 ArchUnit 规则都做一次"注入违规看它红不红"。
- **只扫 API 挡不住"把命令行当字符串传下去"**：那种写法起进程的不是本项目，
  ArchUnit 看不见。补一条源码字面量扫描（`claw4j-*/src/main/java`），
  代价是本项目的 Javadoc 不能出现那些字面量（写这条规则时它自己先红了一次）。
- **参数校验不做"像不像路径"的预判**：只校验含 `/` 或以 `.` 开头的参数时，
  包里一个叫 `leak.txt`、指向外面的符号链接靠**裸文件名**就能读出来。
  改成一律过 `resolveInside`——普通字符串本来就落在包目录内，代价是零。

### 权限与动作

登记的动作是 **`run_script` 而不是 `read`**：只读角色能查数是本意，能执行脚本就不是了
（脚本能写文件、能往外连）。表一张都没有，而"表是空的"不等于"不需要权限"——
没登记过的工具一律按拒绝。后台执行（`ExecBackend.start`）直接拒绝：`ExecHandle` 没有超时。
脚本层默认不启用，开关是"有没有配 `claw4j.scripts.directory`"，配了不存在即启动失败。

### 测试要点

- "脚本本体不进上下文"靠脚本里一个**从不打印的记号**断言：它出现在返回值里的唯一途径
  就是有人把脚本文件也读了进来。换成"返回值长度/包含预期内容"都盯不到。
- 环境那条断言排除 shell 自己生成的 `PWD / SHLVL / _ / OLDPWD`，
  否则"洗过了"和"没洗"两种情况都红；先断言 `PATH=` 在，防 env 没跑起来导致假绿。
- 变异七条全红：去 workingDirectory（3 条）、去超时校验、cleanEnvironment(false)、
  权限登记成 read、参数不过 resolveInside、注入 ProcessBuilder/Runtime.exec。

229 测试全绿、skipped 0（192→229）；README 新增"Script Package"一节与门禁两行，
GLOSSARY 新增"沙箱"与"run_script"两条。

## M2-04 Agent Skills 渐进式披露（票 04，closed，提交 da525d0）

### 渐进式披露的形状是社区包自带的，本项目要做的是别把它改坏

`SkillsTool.Builder.build()` 返回的 `ToolCallback`，描述里只有 `Skill.toXml()` 渲染的
front matter（name + description），正文只在模型用名字调用后作为那次调用的结果回来。
**没有自己再包一层工具类型**——理由不是少写代码：这条边界的判据落在"工具描述里有什么"上，
自己包一层就多出一个要同步维护的描述字符串，也就多一个正文可以溜进上下文的地方。
工具名由社区包定死为 `"Skill"`，所以 `AgentSkills.TOOL_NAME` 只留一份引用。

### 三个可复用的判断

- **只钉一个方向的断言等于没钉**：只断言"正文没进上下文"，那么"谁的正文都没进来"
  （这一层压根没生效）也全绿。端到端那条把每一轮请求摊平成一个字符串后，
  先断言两个 Skill 的元数据都在（转储要是空的这条先红），再断言未命中那份的正文不在里面。
  摊得全是系统提示 + 每条消息 + 工具调用 + 工具结果 + 清单里每个工具的名字/描述/Schema——
  漏洞可能出现在任意一处，只查一处，漏的那处就是假绿。
- **`RealModelSupport.eventually` 之外的断言不受重试保护**：`executor.calls()` 最初写在
  重试 lambda 外面，于是重试只兜住了回答、兜不住"这一轮到底调没调工具"，全量运行时红了一次。
  改法：两条断言一起进 lambda，并且用**本轮前后的计数差**而不是累计值
  （否则前一次尝试调过、这一次没调也会算过）。以后写端到端，凡是要靠重试压 flaky 的断言，
  都必须整个进 `eventually`。
- **"零张业务表"是一条声明不是没有约束**：Skill 不碰库，它让模型去读，
  那一步照样过鉴权。所以表级受限的 guest 也能按 Skill 办事——
  这条顺手成了变异的红线（给权限登记一张 sales_order，guest 就被挡住）。

### 权限与配置

登记 `use_skill` 而不是 `read`：读一张表与"把一份流程指令放进上下文"是两件事。
应用侧给 `read-only` 与 `guest` 都加了 `use_skill`（admin 的 `"*"` 含它）——
加载做法既不读表也不写东西；`guest` 的受限因此仍纯粹是表级的。
"技能目录必须落在沙箱根目录内"没做：要等 06 把 Skill 与脚本包放进同一棵目录树，
现在做是凭空加耦合。`Workspace#display` 是"技能目录在模型眼里长什么样"的接缝，留着。

### 变异

三条全红：把正文拼进工具描述（tools 的"描述里没有正文" + 端到端的"未命中正文不进上下文"）、
去掉权限登记那个 `@Bean`（同步与流式两条端到端红）、给权限登记一张业务表。

## M2-05 Subagent 编排（票 05，closed，提交 b54d191）

### 社区包的 TaskTool 不能直接用：它拿不到 Principal

`org.springaicommunity` 的 `TaskTool` + `ClaudeSubagentExecutor` 形状是对的
（front matter 的 tools/disallowedTools、`call().content()` 只回结论），
但 `TaskFunction` 是 `Function<TaskCall, String>`：`FunctionToolCallback` **丢弃 `ToolContext`**，
于是委派时拿不到 Principal → 子链上那道 `AuthorizationAdvisor` 挂不上去，
"父越不过的界派个专职 Agent 就过去了"。它的 `ChatClient.Builder` 还得外部传，
用 Spring 注入那份等于把预算退回 40/150（ADR-0008 记过的坑）。
只借它的 `MarkdownParser` 与字段名，执行器（`SubagentRunner`）自己写。

### 三个可复用的判断

- **工具内部要身份，就把身份放进 prompt 的 `toolContext`**：委派发生在工具回调里，
  那里只有 `ToolContext`（advisor 上下文进不去，`DefaultToolCallingManager.buildToolContext`
  只读 `ToolCallingChatOptions#getToolContext`）。做法在 `ChatClientAgentPort`：
  `.toolContext(Map.of(PRINCIPAL_CONTEXT_KEY, principal))`，与 advisor param 是同一把 key。
  取不到就拒绝这次委派——"委派脱离身份"会让子链鉴权变成摆设。
- **装配期展开 `ObjectProvider<ToolCallback>` 会把自己卷成循环依赖**：`Task` 自己就是一个
  `ToolCallback` bean，而它的 Runner 又要收全部 `ToolCallback`。改成 `Supplier` 惰性取，
  展开推迟到委派那一刻。代价：白名单点名了没装上的工具，失败发生在**首次委派**而不是启动时，
  姿势仍是拒绝并点名缺哪个工具。
- **给子那一侧凑工具集时又踩了"两种形态"的坑**：第一版只收单回调形态，
  `querySales`（来自 `ToolCallbackProvider`）在子那边就成了"没有这个工具"——
  01 号票那个坑的第三次出现。修法是复用 `AgentAutoConfiguration.collectToolCallbacks`
  （改成 public static）：**收工具只该有一处实现**，复制一份就多一个漏收的地方。

### 测试侧

- **预算那条用例里工具不能抛异常**：抛异常会被框架直接冒泡，测的是"第一次失败就炸"，
  不是"一直失败时在上限处停下"。改成返回失败文本（与 `SalesTools` 同一个口径）。
- **隔离要两条正向对照**：只断言"回传里没有 X"不够（子那一趟没跑也绿）。
  组件级（`SubagentRunnerTest`，桩模型驱动）断言工具被调用过 + X 在子窗口出现过；

  端到端的 X 放在工具返回值里（子系统提示词那条另有一条，更稳）。
- **变异六条全红**：中间轨迹一起回传（组件级与端到端各红一条，票面点名这条）、
  去掉白名单过滤、子链不吃预算、不传身份、无身份照常委派、描述里塞进正文、空目录不失败。

## M2-06 Skill Generator 五步链路（票 06，closed，提交 9a1b45b）

### 第 ② 类沙箱给不了"网络受限"，就别把它写成承诺

票面写的是"网络受限、有资源上限"，而纯 Java 起的子进程**没有可移植的网络/资源限制手段**
（`unshare` / `sandbox-exec` 都是要再起一条命令，那正是 ADR-0002 禁止的事）。
处理姿势与 03 处理"非 root"时一致：规格里单独立一个 `Network` 枚举，
本地形态如实写成 `NOT_ISOLATED` 并附原因，**有一条断言盯着它不许撒谎**
（防的是"改成一个叫 networkIsolated 的布尔量让规格看起来更漂亮"）。
补偿手段是把联网挡在**静态检查**那一关（`NETWORK_CLIENT` / `PY_NETWORK`）——
反正沙箱没网，会连的脚本自测必然失败。ADR-0002 修订记录 + ADR-0013 都写明了。

### 与第 ① 类分清的那一条是一条具体断言

两套代码长得越像，"为什么要有两个"越需要一个说得出来的理由。
理由落在**复制**：自测把候选目录复制成临时目录再跑、跑完即删。
这不是形式主义——候选目录里放着"等着被人审的"脚本，让自测跑在那儿
等于允许未审核代码改自己将要被审的内容，甚至给自己写一个审批标记
（沙箱锁得住入口、参数、工作目录，锁不住脚本体内写一个绝对路径，03 就写明挡不住这个）。
所以审批目录默认在暂存区**旁边**，不在里面，也不在沙箱里。

### 三个可复用的判断

- **静态检查放在落盘之前，且必须是纯函数**：危险代码不该先被写下来再被删掉
  （"磁盘上出现过它"没人会记录）。纯函数（不读文件/时间/随机）让"挡住了什么"
  能被一张表钉死；用例两个方向都要有，只测"危险被挡下"的话一条全拒的实现也会绿。
- **人审比对的是"审的哪一版"，不是"有没有签"**：签字文件里带脚本摘要，
  摘要对不上就作废。否则"审过一次"会变成长期通行证——人看到"我审过"、系统跑的是另一份。
  四项缺一不算通过，`status` 严格相等（"approve"/"Approved" 不算，"看着像通过"不算通过）。
- **"未人审不在清单"要落在清单的取法上**：`ScriptPackageToolProvider` 从
  "构造时快照"改成从 registry **现取**，权限表同样现取（否则新包在清单里却在鉴权那步被拒）。
  registry 还要把"建执行后端"这条挂上去（`onRegister`）——只在 provider 构造里挂一次，
  挂两次会在注册时撞上"重名即失败"，报的是"已经有一个叫 X 的包"，离"listener 挂重了"隔了一层。

### 跨层接线的两个顺序坑

- **执行留痕不能按类型注入 listener**：脚本层先装配、生成器后装配，
  注入那一刻还没有审计，"没接上"是静默的。改成容器 `ExecutionListeners` 先落地、
  后来者 `add()`。审计是留痕手段不是安全边界，所以空容器不该让脚本层挂掉。
- **身份那把 key 搬到了 domain**（`ContextKeys.PRINCIPAL`）：工具回调里要读身份
  （委派、执行都在工具内部），而 tools 不认识 agent（ADR-0010），
  各写一份会漂移，漂移的表现是"一律按没身份拒绝"。

### 测试侧

真模型 E2E 只花 8 秒就绿了：让模型提交一个 `echo GENERATED-SCRIPT-RAN` 的脚本，
断言盯的是**审计与清单**（自测那条 detail 含那个 marker、registry 为空），
不是模型的措辞——模型怎么说每轮都可能变。

变异八条全红，票面点名的两条（去掉静态检查、跳过人审直接注册）各命中：
前者红 1 条，后者红 5 条（含装配那条"人审之后进清单"）。

## M2-07 场景迁移、文档收尾与真实模型联调（票 07，closed，提交 999bd09）

### 结构化 argv 不是"拼命令行"，但注释里写那两个字也会红

接真实外部 CLI 用的是 SDK 的 `ServerParameters`（command 与 List<String> args 分开给，
SDK 内部走 `ProcessBuilder`），不经任何命令解释器——这与 ADR-0002 禁的那种写法是两回事，
界线写进了 ADR-0002 的修订记录与 ADR-0014。但 **`NoHandBuiltShellCommandTest` 扫的是整份源码文件、
注释里的字面量一样命中**：我在 Javadoc 里写 "1.x 的 `sh -c`" 直接把全量构建搞红了一次。
那条规则是故意不做语法解析的（注释与代码分开解析会让规则变成要维护的东西），
代价就是本项目注释得换个说法——改成"交给解释器去解释"。

### 脚本层拿不到凭据，这是一条硬事实而不是偏好

`SandboxPolicy` 给子进程的环境只有 PATH，所以**依赖 API key 的能力走不了脚本层**。
`summarize` 那个保留场景因此从"调火山引擎生成摘要"改成**抽取式**摘要（零依赖）。
`weather-forecast` 用的是公开无 key 的接口，所以能留下。`xurl` 包 CLI，没装就给一句怎么装。
需要凭据的能力该走 MCP——那边可以在起进程时显式给 env，而"给出去了什么"看得见。

### tag 排除不能用 assume 顶替，也不能靠命令行顶

- 用 `assumeTrue` 隔离真实 CLI → 产出 **skipped**，而本仓库有闸把 skipped 判成失败，等于给闸开口子。
  排除（surefire `excludedGroups`）是"这次没选它"，报表里不出现。
- `-DexcludedGroups=` 顶不掉 pom 里那条：surefire 把**空值当成没设置**，照样继承排除；
  `-Dgroups=real-cli` 同理（groups 与 excludedGroups 给同一组 = 被排除）。
  最后用 **profile**（`-Preal-cli`）同时换掉两个参数才确定。
- 顺带一个坑：本项目不继承 spring-boot parent，pluginManagement 里给 surefire 加配置
  必须显式写 `<version>`，否则插件版本解析不出来、构建直接失败。

### 数量断言在多来源的世界里会变成"顺手 +1"的断言

`ToolsWiringTest` 那条"容器里只有一个 ToolCallbackProvider"原本盯的是"框架那份 mcpToolCallbacks 没关"，
M2 每加一层它就红一次，而红的原因与它要防的事毫无关系——那种断言会被顺手改成 2、3、4，从此守不住任何东西。
改成**按 bean 名断言**（`doesNotContainKey("mcpToolCallbacks")`）：盯的是事实本身，加多少来源都不影响它。

### 复核那两条怎么写才不是在重复实现

- 预算：`BudgetAcrossLayersTest` 把一层（provider 形态 + 单回调形态）、二层（真协议连接）、
  三层（脚本包）放进**同一份清单**，第 7 次仍被总数上限拦住。放进来的形态越多，
  "某一种来源静默不进清单"就越早红（少一种就撞不到上限）。变异：去掉 `maxTotalToolCalls` → 红。
- 鉴权：`PermissionsAcrossLayersTest` 在**装配出来的容器**上验，判据用 `AuthorizationAdvisor` 的
  **行为**（"模型要调它，会不会被拦"）而不是"表里有这个名字"——后者只是把实现重复了一遍。
  变异用 01 号票那个坑的形状（给某层权限表加 `@ConditionalOnMissingBean`）→ 红两条。
- 另加一条方向相反的：只读角色**调得见但调不动**脚本（报"不允许执行 run_script"而不是"未登记"）——
  两种拒绝的话术不同，运维一眼能看出该改哪行配置。

### 其他两个小决定

- `McpConnection` 的请求超时改成可注入（默认 30 秒）：测试里给 2 秒，
  于是"命令不存在"那条断言从 20 秒降到 2 秒。
- 演示接线 `McpDemoConfiguration` 只在 `mcp-demo` profile 下生效、三个 server 各一个开关。
  MCP 层是"启动就去连对方"的，把"必须装了 gh"写进默认配置等于让没装 gh 的机器启动不了应用。

### 真实联调实录（README 里那五条就是这趟跑出来的）

起应用带上 `examples/{scripts,skills,subagents}` 三个目录 + `mcp-demo` profile：
一层 systemStatus（堆上限 8192MB / 线程 42）、二层 demo_echo（真 Python 子进程回话）、

连"环比这一版没做"都照着正文那条边界说）、Subagent sql-reviewer（自己跑去查库验证，
算出取消订单让 sum 虚高 13.7%），以及 guest 问天气被拒（"不允许执行 run_script"）。

### M2-08：脚本层改成结构化 argv（已提交 7cb7e00，391 测试 / skipped 0）

把 code-review 抓到的"脚本层仍把命令行交给命令解释器"消掉。做法与代价：

- **接缝整条换掉**：社区包的 `ExecBackend`/`ExecSpec`/`ExecResult` 退出本项目，
  新建 `claw4j-tools/.../tools/process/`：`ProcessRequest(argv, timeout)`、
  `ProcessOutcome(status, exitCode, stdout, stderr)`、`ProcessRunner`（接缝）、
  `LocalProcessRunner`（**全仓唯一碰 ProcessBuilder 的类**）、`ProcessStartException`。
  `SandboxedProcessBackend` 只过策略，`GeneratorSandbox` 复用同一个执行器。
- **红线收窄**：`AppArchitectureTest` 从"全仓不得依赖 ProcessBuilder"改成
  "除 `LocalProcessRunner` 这一个类外"。收窄不删除——删了"Java 侧不起进程"就没有机器证据。
- **两处直接后果**：① 入口必须有可执行位与 shebang（静态检查加 `NO_SHEBANG`，
  执行侧对漏过去的报"第一行"）；② `SandboxPolicy#requireNoInjectedEnvironment` 撤销——
  `ProcessRequest` 没有 env 字段，注入在类型上无入口（盯它的换成反射断言"请求里没有环境变量这一项"）。
- **坑**：`NoHandBuiltShellCommandTest` 的禁用字面量含 `sh -c`/`/bin/sh`，
  **注释里写 shebang 例子也会红**，所以文档里一律写"#! 开头"。
  起进程读输出必须**两路各一条线程**（管道会堵死），且要 `setDaemon(true)` + 有界 join。
- **环境**：本机跑长驻应用要用 Bash 工具的 `run_in_background`（nohup 起的进程会随 shell 退出被杀）；
  curl 本机端口可能被 Electron/代理抢，用 `--noproxy '*'` + 显式 `--server.port`。
